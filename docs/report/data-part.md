# 데이터 파트 본문·근거 인계 · 심민준

기준 main `c6e2195`, 2026-11-10. 전체 보고서20쪽 편집을 맡은 대겸에게 전달하는 데이터 파트 원고다. 최종 보고서나 별도 발표자료가 아니다. 아래 확인된 범위와 미완료 표시를 유지해 [본문 초안](report-draft.md)의3·6·7절에 반영한다.

## 본문에 사용할 설명

배차 조정에는 차량·작업·기존 배정, 반입 시작과 마감, 화물 준비시각, 방향별 이동시간, 처리·여유시간과 고정 조건이 필요하다. 현재 실제 운송사의 배차표와 차량GPS는 확보하지 못했으므로 이 입력은 모의 자료로 구성했다. 부족한 값을0이나 즉시 가용으로 채우지 않고, 준비·복귀·이동 경로 등 계산에 필요한 정보가 없으면 입력검사 단계에서 계산을 보류한다. 일부 값을 가정으로 보완할 때도 실제 관측과 분리해 기록한다.

실제 확보한 자료는 출처별로 사용 범위를 나눴다. HJNC 표본에서는 항차 ID, 반입 시작·마감과 접안 예정시각을 확인했다. JSON 안의 `stringContent`가 다시 JSON 배열 문자열인 형식이다. 대겸의 후속 검증으로10행/표시24건 표본의 정확한 수신기록을 확인했지만, 전체 조회 범위·원문 시간대·동일 항차의 확정 변경 쌍·반복 수집/공개 조건은 미확인이다. 접안 예정시각을 반입마감으로 대신 쓰지 않는다.

기상청은 본인 일반회원 가입·키 발급과 서비스별 활용신청 뒤 지점·해양 관측·특보의 실제 응답을 받았다. 응답은 CP949 계열 텍스트이며 관측CSV에는14개 값, 특보에는10개 값이 있다. 관측 KST 시각과 UTC 수신시각을 구분하고 풍속m/s·유의파고m의 단위를 확인했다. 거제도 관측은 HJNC 내부 실측이 아닌 인근 참고 정보다. 부산앞바다 예비특보의 시간대 코드를 정확한 분 단위 발효시각으로 해석하지 않는다. 기상이 일치했다는 사실만으로 항만 지연의 원인이나 지연시간을 계산하지 않는다.

도로공사에서는 인증·정역방향 응답·빈 결과와 오류를 검증했지만, 현행 시간 단위·집계 코드·부산 구간/차종과 값의 품질에 공백이 있어 계산용 이동시간으로 채택하지 않았다. 서울↔동수원 시험 표본은 부산항 경로 자료가 아니다. 원문의 시간 단위를 추측하거나 역방향을 복제해 이동행렬을 완성하지 않는다. ORS 거리/시간 표본은 길웅 담당의 별도 검증 후보이며, 실제 확보/채택 여부를 데이터 담당이 대신 완료 처리하지 않는다.

서버와 화면의 실패 처리를 시험하기 위해 실제 원문과 별도로 공급자 형식을 따르는 합성 예제21종을 생성했다. HJNC7종과KMA14종은 정상·0행·부분·오래됨·오류와 결측·미래 관측·지점 불일치·예비특보를 포함한다. 각 파일에는 실제가 아닌 모의 자료라는 선언, 모의 수신/현재시각, 인코딩과 해시, 예상 판정을 연결했다. 기존 감사 도구로 결과를 대조하며 이21종을 실제 관측 건수나 효과 실험의 표본 수로 세지 않는다.

자료가 실제로 보인다는 사실과 그 값이 배차 계산에 쓰였다는 사실은 다르다. 현재의 안전한 사용 범위는 실제 항차·기상 등의 참고 조회와 명시적인 모의 배차 계산이다. 혼합 계산을 채택하려면 해당 필드의 의미·단위·시간대·권한·신선도와 저장/독립검사/승인 경계까지 대조해야 한다. 현장 자료·사용 조건이 부족하면 한계를 표시하고 기존 모의 평가 원본을 유지한다.

데이터 모듈·합성 예제와 검사는 AI 보조로 작성·실행했다. 팀이 채택한 업무 의미와 입력 보류 기준을 명세·예제·실행 결과에 연결했으며, AI가 작성했다는 사실을 외부 자료의 진위나 현장 효과의 근거로 쓰지 않는다. 데이터 담당은 원본과 합성의 차이, 필드 변환, 누락 시 보류하는 이유와 검사 결과를 직접 설명할 수 있어야 한다.

## 검사 근거와 실제 연결의 미완료

- [합성 wire 예제와 재현 명령](../data/provider-fixtures-2026-11-10/README.md):21종의 파일 해시·생성 재현·기존 파서 기대 결과. 추가 회귀8개는 바이트 변조·폴더 밖 참조·자료 종류 위장·중복·출력 덮어쓰기 등을 검사한다.
- 기존 [개발9종 감사](../data/input-audit.json), [평가10쌍 감사](../data/evaluation-data.md), [공백9사례](../experiments/data-demo-2026-11-10/README.md)는 각각 범위가 다르다. 합성wire21종과 합쳐 실험·현장 건수로 표시하지 않는다.
- PR42의 실제 표본 읽기 대조는 [고정head 인계](../data/reference-handoff.md), HJNC 후속 수신기록 대조는 [별도 검증](../data/hjnc-reference-verification.md)을 따른다. 서로 다른 원문/수신기록을 합쳐 만들지 않는다.
- **미완료:** 키 소유자의 허용 환경에서 새 실제 조회→서버→화면 확인, 최종 공개본의 자료 구분/실패/누락 테스트. 아직 실행되지 않은 검수를 통과로 쓰지 않는다. 최종 URL·버전이 제공되면 입력 순서/기대/실제 결과와 화면 증거를 전체 검수 양식으로 전달한다.

## 출처·권한과 인계

2026-11-11 추가 범위 R1~R8에 맞춰 [담당자 대응 검수 자료](../data/response-acceptance-2026-11-11/README.md)를 인계했다. 계산/설명 9사례와 보완 전후 4쌍, 전달/응답 기대 자료 15종은 모두 합성이다. 준비시각만 앞당겨도 미해결이 남는 경우와 추가 차량 때문에 처리 작업 집합이 바뀌는 경우를 구별했다. 입력 누락을 0건 기준으로 비교하지 않고, SEARCH_LIMIT는 모의 시계로 강제한 오류 검수이며 현장 불가능이나 성능 측정으로 쓰지 않는다. 차량별 변경은 재배정 이전/신규 차량을 포함하되 실제 운송 취소가 아니다.

PR61의 고정 head에서 주입 전송기로 전달 예제 9종을 API 상태와 대조했다. 접수·열람·명시 확인·수행 가능/곤란과 불명을 구분했고 실휴대폰에는 보내지 않았다. 실제 제공 자료는 기존 출처별 검증 범위만 해당한다. 이번 추가 자료의 배차·수신자는 모의이며 현장 업무·실차량 운행은 미검증이다. 실제 도입에는 허용된 배차/가용 조건, 동의한 수신자 연결과 HTTPS 실기기 왕복 증거가 더 필요하다. 최종본 화면/휴대폰 검수와 보고서 최종 편집은 아직 완료가 아니다.

공식 출처와 확인일·범위는 각 검증 문서에 있다. 원문·개인키·전화번호·비밀번호는 Git/보고서/제출ZIP에 넣지 않는다. 합성wire 예제는 새로 생성한 팀 자료이며 원본 공개 허가를 대신하지 않는다. KMA 개인키는 소유자가 허용 환경에서 사용하고, 공용 서버/재표시 조건을 확인한다. HJNC 공개 조회를 무제한 수집 허가로 보지 않는다. 화면의 모의시계·가정 변경을 실제 시각·실제 사건으로 표시하지 않는다.

대겸에게는 이 본문과 자료표·예제manifest·검사 명령을 인계한다. 본문3·6절의 기존 사실과 중복을 줄이고7절에는 실제 연결/배포에서 새로 검증한 사실만 추가한다. 최종 편집·PDF/코드 패키지·실제 배포는 대겸 담당이며 발표자료는 이번 작업에 포함하지 않는다.

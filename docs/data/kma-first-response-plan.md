# 기상청 첫 응답 검증 준비 · 심민준

기준 main `12b0a64`, 2026-11-09. [민준 #35](https://github.com/unknownamed/banipmatch/issues/35)의 신청·표본 검증 준비다. 사용자에게 기존 계정이 없음을 확인했고 [가입 화면](https://apihub.kma.go.kr/join.do)을 열었다. 가입 여부 확인용 이메일 입력부터 본인 처리가 필요하며 **가입·휴대전화 인증·키 발급·실제 응답은 아직 미완료**다. 기관회원·사업자 정보·유료 경로를 사용하지 않는다.

## 확인한 공식 명세

| 자료 | 첫 요청 조건 | 확인할 출력과 한계 |
|---|---|---|
| [해양 종합 관측](https://apihub.kma.go.kr/apiList.do?seqApi=3&seqApiSub=249)의 `sea_obs.php` | `stn`은 확인한 부산 인근 지점1개, `help=1`, 필요시 `tm=YYYYMMDDHHmm`(KST). 인증키는 로컬에서만 설정 | `TP`, `STN_ID`, `STN_KO`, `TM`(KST), `WH`(유의파고 m), `WD`(도), `WS/WS_GST`(m/s), `TW/TA`(℃), `PA`(hPa), `HM`(%). 지점 위치와 운영기간을 먼저 확인하며 인근 관측을 터미널 내부 관측으로 표현하지 않음 |
| [기상특보 현황](https://apihub.kma.go.kr/apiList.do?seqApi=10&seqApiSub=288)의 `wrn_now_data.php` | `fe=f`는 발표기준, `fe=e`는 발효기준. `tm`은KST 기준시각, `help=1`. 최초에는 기준 하나만 소량 확인 | `REG_UP/REG_UP_KO`, `REG_ID/REG_KO`, `TM_FC`(발표 KST), `TM_EF`(발효 KST), `WRN/LVL/CMD`. 발표·발효·수신시각을 분리하고 부산/진해의 육상·해상 구역을 구분 |

위 자료는 공개 설명 확인이며 실제 응답의 구분자·결측·권한/활용 신청 결과를 확인한 것은 아니다. 부산 인근 지점/구역의 실제 코드를 추측하지 않는다. 키 발급 후 공식 지점·구역 정보로 대상과 의미를 확인한 뒤 요청한다.

명세상 주의할 점:

- `sea_obs.php`는 요청 시각에서 **가장 가까운 생산시각** 자료를 반환한다. 조회 인수의 시각을 실제 관측시각으로 복사하지 않는다. 과거 사례 검증에서는 응답 `TM`이 판단 시점 이후인 자료를 당시 알려진 근거로 쓰지 않는다.
- `stn=0` 또는 생략은 전체 지점이다. 단일 지점 번호를 확인하기 전 편의상 기본값0으로 수집을 켜지 않는다.
- `wrn_now_data.php`의 공개 요청표에는 지역 필터 `reg`가 없다. 다른 특보 API의 인수를 복사하지 않는다. 필요한 현황 응답의 범위·크기와 허용 조건을 확인하고, 공식 구역 코드에 따른 후처리를 별도로 기록한다. 현황을 장기간 전국 이력 수집으로 확대하지 않는다.
- 확인한 두 공개 상세 설명에는 결측 수치 코드가 명시돼 있지 않았다. 다른 기상 API의 `-9`/`-99` 등을 일괄 이식하거나0으로 치환하지 않는다. 첫 응답의 도움말과 공식 항목 설명으로 확인하고 미확인 값은 보류한다.
- 특보 응답에 행이 없거나 조회가 실패한 것을 ‘해당 구역 특보 없음’으로 단정하지 않는다. 취소/해제 등 `CMD` 의미, 지역 범위, 기준 시각과 성공 상태를 함께 확인한다.

## 가입 후 시험과 수신 기록

일반회원 가입 안내는 자동 승인·가입 시 키 발급을 설명한다. 발급된 키는 로그인 후 마이페이지에서 확인한다. 사용자가 저장할 Git 제외 파일은 `local/secrets/kma-api-key.txt`다. 기존 파일은 덮어쓰지 않았고 키 없이 API를 호출하지 않았다. 비밀번호·휴대전화·OTP·키·키 포함 URL은 이슈/로그/공유 Git에 넣지 않는다.

1. 본인 가입·휴대전화 인증·키 발급 상태와 서비스별 활용신청 필요 여부를 확인한다. 화면·이슈에는 상태만 기록한다.
2. 지점/구역의 공식 ID·위치·적용 범위를 확인한다. 실제 필요한 지점1개와 특보 현황 한 기준에서 시작하고 무한 재시도/예약 수집을 하지 않는다.
3. HTTP 상태·본문 오류/정상·행수·실제 지점/구역·관측/발표/발효시각·UTC 수신시각·원본 해시를 기록한다. 응답에 민감한 값이나 키가 들어있는지 공유 전에 확인한다.
4. 단위·결측·자료 신선도·요청시각과 반환시각 차이·빈 자료를 검사한다. 수신시각이 신선해도 과거 자료이면 과거로 표시한다. 실패를 모의 성공으로 대체하지 않는다.
5. 실제 응답 형식이 확인된 뒤 그 형식의 검사·정상/오류/결측 예시를 추가한다. 선효에게는 키 없이 허용 표본·매핑·제약을 인계한다. 현재 생산 API의 `simulated` 전용 저장과 승인 경계를 유지한다.

## 한도·권한과 완료 판정

[공식 이용안내](https://apihub.kma.go.kr/apiInfo.do)는 일반회원 무료 일20,000건·5GB(시스템에 따라 변경 가능), 본인만 키 사용·양도/대여 금지, 공공누리 유형별 이용조건 적용을 설명한다. [약관](https://apihub.kma.go.kr/policy.do)과 자료별 조건을 확인하며 공용 서버 운영·재배포 허용을 가입만으로 확정하지 않는다. [출처표시 안내](https://apihub.kma.go.kr/notice.do?seqNotice=57)에 따라 자료와 활용 결과의 출처도 남긴다.

신청 준비와 실제 발급·실응답·제품 채택은 별개다. 현재 완료한 것은 공식 요청/출력 의미 확인과 가입·로컬 보관 준비이며 #35를 닫지 않는다. 관측 기상과 반입 지연의 동시 발생을 확정 원인으로 바꾸거나 선박 ETA/확정 반입마감을 기상으로 덮어쓰지 않는다.

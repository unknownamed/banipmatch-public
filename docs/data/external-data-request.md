# 외부 요청 전 준비와 자료 수신 기준

기준 main `55a7d4e`, 심민준 데이터 담당. [실제 수집 조사](source-collection-2026-11-09.md)의 후속이다. 이 문서는 연락 담당자가 검토할 요청 초안과 수신 체크리스트이며 발송 기록이나 새 API 계약이 아니다.

## 우리 쪽에서 끝낸 부분

- 모의 입력 검증·출처 구분, 개발9종·평가10쌍 감사와 대표 사례 설명을 준비했다.
- HJNC 공개 응답10행과 광양항 공개 CSV를 로컬에 확보했다. [집계 보고서](collected-samples-audit.json)에는 원본 해시·분모·누락·시간 차이 분포만 남겼다. 개별 차량/항차 식별자는 포함하지 않는다.
- [로컬 재집계 도구](../../tools/audit_collected_samples.py)로 원본을 수정하지 않고 집계를 재현한다. 외부 호출·수집 예약·엔진 입력 변환을 하지 않으며, 원본과 같은 출력 경로나 기존 출력 파일 덮어쓰기를 거절한다.
- 광양항58,171건 중 원본 작업시간과 다른28,548건은 모두 `출입시각 차이−작업시간=1분`이었다. 원인은 미확인이며 시간값을 임의 교정하지 않았다. 원자료의 의미와 지역이 달라 HJNC 처리/대기시간으로 보정하지 않았다.
- 현재 기능 검증은 모의 입력으로 계속 가능하다. 아래 자료는 대표 실제 사례의 확인에 필요한 추가 증거이지 앱 개발을 시작하기 위한 조건이 아니다.

재집계 예시(원본은 공유 Git에 없으므로 보관자 또는 공식 출처에서 확보):

```sh
python tools/audit_collected_samples.py --hjnc local/data-research-2026-11-09/hjnc-one-request.json --gate-csv local/data-research-2026-11-09/gwangyang-west-2026-h1.csv --output local/collected-samples-new.json
```

저장 경로의 상위 폴더를 먼저 준비한다. 종료코드0은 집계/저장 성공,2는 읽기·형식·입출력 경로 오류,1은 보고서 저장 실패다. 오류 메시지에는 원문 셀 값을 출력하지 않는다. 광양 CSV의 누락·시각 역전·날짜/작업시간 오류는 집계하고 통계 제외 분모를 남긴다. CSV 구조 또는 HJNC 예상 날짜/응답 형식이 다르면 보고서 생성을 거절한다. 이 도구는 이번 두 자료 형식 전용이며 새로운 공급자 자료에 자동 적용하지 않는다. 보고서 일치는 자료 진위·사용 권한·현장 대표성의 증명이 아니다.

## 외부에서만 받을 수 있는 것

| 요청 | 최소 목적과 범위 | 대신 요청할 수 있는 것 |
|---|---|---|
| 동일 항차 변경 전후1사례 | 터미널·항차키, 이전/이후 반입 시작/마감, 그 사실을 확인할 수 있는 공지/기록·시점·시간대 | 전산 이력이 어렵다면 날짜가 있는 두 화면/문서나 담당자가 확인한 비식별 요약. 단일 현재 화면·ETB 변화는 대체 증거가 아님 |
| 관련 배차 원안 소량 | 같은 사건에 연결된 작업/차량의 원안과 당시 조건. 3~10작업은 전달 부담을 줄이기 위한 제안이며 통계적 충분 표본 기준이 아님 | 일부 항목은 공란과 의미 설명으로 제공. 빈 양식/가상 예시는 업무 적합성 참고로만 구분하고 실제 효과 검증으로 쓰지 않음 |
| 사용 허용과 필드 의미 | 시간대·필드 의미, 보관기간, 팀 공유·보고서·발표·공개 시연·재배포 각각의 허용 여부 | 공개 금지 항목은 제외하거나 집계만 사용. 허용되지 않은 용도로 사용 범위를 넓히지 않음 |

키·실시간 API·GPS·운송사 전체 데이터·장기간 수집 권한은 이 최소 요청의 필수 조건으로 요구하지 않는다. 도로 API는 영업소 구간 참고 후보이며, 현장 사례를 구성하는 데 꼭 필요한 경로가 확인된 뒤 별도로 진행한다. API 계정 없이 허용된 일회 표본으로 시작할 수 있다.

## 기존 문의에 이어 붙일 요청 초안

아래 문안은 기존 BPA/HJNC 문의 및 운송사 접촉 범위를 대겸이 확인한 뒤 수신처에 맞게 사용한다. BPA에는 보유하지 않은 배차표 제공을 단정적으로 요구하지 않고, 해당 자료 보유 기관/운송사 연결 가능 여부를 묻는다. 기존 질문과 이미 받은 답은 제외한다.

> 공개 자료 확인과 모의 배차 검증은 저희 쪽에서 진행했습니다. 다음 단계로 실제 반입시간 변경 사례 하나를 확인하고 싶습니다.
>
> 가능하시다면 같은 항차의 변경 전·후 반입 시작/마감 시간과 확인 시점, 시간대, 근거 자료를 받을 수 있을까요? 관련 배차 원안도 제공 가능하다면 작업·차량 ID를 가상값으로 바꾼 소량 표본을 부탁드립니다. 준비 완료 시각, 원래 배정·순서·시간, 출발하거나 변경할 수 없는 작업, 이동·처리시간 조건을 알 수 있으면 됩니다. 보유하지 않은 항목은 비워 두셔도 됩니다.
>
> 업체·기사·고객의 이름이나 연락처, 상세 주소는 필요하지 않습니다. 실제 배차 자료 제공이 어렵다면 빈 양식이나 가상 예시, 또는 자료를 보유한 담당 창구 안내도 도움이 됩니다. 이 경우 실제 자료와 구분해 사용하겠습니다.
>
> 자료별로 교육·연구 목적의 로컬 보관, 팀 공유, 보고서·발표, 공개 시연, 재배포 중 허용되는 범위와 보관기간도 알려주시면 그 범위에 맞추겠습니다. 실시간 API 연결은 이번 표본 요청의 필수 조건이 아닙니다.

## 받았을 때 작성할 수신 기록

아래 빈 양식을 Git 제외 `local/`에 복사한다. 공유 문서에는 허용된 요약·가상 ID·비밀값을 제거한 참조만 옮긴다. 자료 제공자의 동의가 없는 외부 AI/서비스 업로드도 별도 허용으로 간주하지 않는다.

| 항목 | 기록할 내용 |
|---|---|
| 자료 구분·출처 참조 | 실제 관측 / 제공자 가상 예시 / 팀 가정. 민감한 원문 링크·개인 연락처는 공유하지 않음 |
| 원본 파일·SHA-256·수신시각 | 원본 보존 위치와 해시. 실제 수신시각과 조회/변경 발생시각을 따로 기록 |
| 사용 범위·보관기간 | 로컬/팀/보고서/발표/공개 시연/재배포 각각 허용·불가·미확인과 근거 |
| 시각·단위 | 원문 시간대·정밀도·단위 및 제공자 설명. UTC 오프셋을 추정하지 않음 |
| 사건 연결 | 같은 항차의 전후 기록, 변경 발생/발표/수신시각 중 확인된 것, 당시 알고 있던 입력 |
| 작업·차량·항차 연결 | 가상 ID 연결표. 준비·원안·출발/고정·장비/중량·용량·위치·방향별 이동·서비스/여유 값과 각각의 출처 |
| 품질 | 전체 건수, 빈 행, 필드별 누락/분모, 중복·시각 역전·단위 불일치, 제외/보완 사유 |
| 판정·남은 질문 | ①수신만 완료 ②설명·허용 범위 확인 ③변환 가능 ④입력 검사 통과 ⑤별도 일정 검사. 각 상태를 구분 |

수신 파일을 자동으로 앱에 올리지 않는다. 현 계약은 UTC `Z`와 분 경계이므로 초가 있는 원본·미확인 시간대는 그대로 보존하고, 의미를 보존하는 정규화 기준을 합의하기 전 입력 변환을 보류한다. 누락값은0·즉시 준비로 채우지 않는다. 실제와 모의 보완이 섞이면 항목별로 분리 기록한다.

민준은 출처·품질·입력 의미와 변환을, 대겸은 사건/원안에 대한 실험 설계를, 선효는 결과의 독립 일정 검사와 승인 연결을 확인한다. 제공받은 단일 사례로 변경 빈도·평균 손실·일반적인 개선율을 주장하지 않는다. 회신이 없으면 기존 모의 시연과 현장 미검증 한계를 유지한다.

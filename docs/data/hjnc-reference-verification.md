# HJNC 수신기록 대조와 계산 입력 채택 판단

황대겸 · 2026-11-10. 기준 main `fb1072d`, 검토 대상 [Draft PR42](https://github.com/unknownamed/banipmatch/pull/42)의 `122db8fae706316526092767dabad05913733e47`이다. [민준의 데이터 인계](reference-handoff.md)에 이어 대겸이 보관한 별도 표본을 대조했다. PR42의 초안 해제·관련자 검토·병합 또는 앱 연결 완료를 뜻하지 않는다.

## 실제로 확인한 것

[식별자 없는 대조 결과](hjnc-reference-reader-check.json)에 검사 시각·코드 커밋·원본 해시·상태를 보존했다. 기존 로컬 표본만 읽었고 새로운 API 요청·키 접근은 없었다.

| 항목 | 결과 |
|---|---|
| 표본 출처 | HJNC 공식 선석 조회, 2026-11-09T12:51:14Z 수신 기록이 있는 대겸의 별도 캡처 |
| 원본 대조 | 5,739바이트, SHA-256 `a2f90a10eeeaa5d70798996280851ae10c64228518c3e207f425672067138743`가 수신기록과 일치 |
| 읽기 결과 | `partial`, 수신10행 / 표시 총24행, 투영10행 / 제외0행 |
| 필드 | 10행 모두 `VOY_NO`, `YARD_OPEN`, `YARD_CLOSE`, `ETB` 원문 값과 일치. 시간대 변환·ETB의 마감 대체 없음 |
| 시각 | 원래 수신시각 유지, 검사 시점에는 `stale`. 공급자 관측시각은 `observed_at=null` 유지 |
| 보존·계산 | 캐시 비활성·`cached=null`, `engine_conversion=blocked`, `approval_eligible=false`, 자동 모의 전환 없음 |

민준의 초기 표본은 수신10행/표시22행인 **다른 캡처**다. 이번 수신시각을 민준 표본에 채우지 않았다. 로컬 원본과 수신기록의 일치는 제공자의 전자서명이나 이용 허가 검증이 아니다. Git에는 실제 행·항차 식별자·개인 경로·키를 올리지 않았다.

원문 시각의 시간대, 전체 조회 범위, 동일 항차의 변경 전후 사건, 반복 수집·공용 서버·공개 시연 조건은 여전히 미확인이다. 단일 관측10행을 변경10건으로 세거나 `partial`을 성공적인 전체 수집으로 표시하지 않는다.

## 대겸 파트의 채택 판단

| 자료 | 지금 가능한 활용 | 계산에 넣기 전에 필요한 것 |
|---|---|---|
| HJNC 반입 시작·마감 | 로컬 참고 읽기·관측 비교. 이번 표본의 정밀 수신기록 공백은 해소 | 선택 항차의 시간대·필드 의미·업무 적용 범위와 이용 조건 확인. 실제 변경 쌍이 없으면 가정 변경이라고 명시 |
| [도로공사 정·역방향](road-api-verification.md) | 인증/통신·실패·부분 자료 처리 검증 | 현행 시간 단위·집계 의미·부산경남 필요 구간과 차종·품질 확인. 현재 표본은 유효 투영0행이므로 이동분으로 변환하지 않음 |
| [기상청 관측·특보](kma-response-verification.md) | 시각·출처가 있는 과거 참고 근거. 특보 예비 시간대를 정확한 발효시각과 구분 | 항만 적용 구역·대표성·결측 및 이용 조건 확인. 별도 참고 읽기/표시 연결 필요. 날씨로 지연 분·반입 제한을 자동 생성하지 않음 |
| [AIS PR43](https://github.com/unknownamed/banipmatch/pull/43) | 합성 선박 시연 및 수신 검사. 마이애미 수신과 부산 무수신 기록을 분리 | 부산 실표본·선박과 항차 연결·권한 확인. 선박 위치를 화물차 위치나 반입마감으로 변환하지 않음 |
| [ORS #37](https://github.com/unknownamed/banipmatch/issues/37) | 담당자 개인 신청·수치 표본 확인 대기 | 발급/실응답·시간/거리 단위·부산 경로·이용 조건 확인. 실시간 교통이나 화물차 통행 적법성 보장으로 쓰지 않음 |

‘참고로 쓸 수 있음’과 ‘계산 입력으로 채택 가능’은 다르다. 일부 항차만 검증돼도 그 항차의 제한된 사례를 검토할 수 있으며 전체 항만 수집을 강제하지 않는다. 반대로 아직 검증되지 않은 필드를 채워 넣어 혼합 사례를 서둘러 만들지 않는다. 지금은 기존 모의 입력·평가를 유지하고 실제 자료를 읽는 경계부터 검증한다.

## 새 혼합 사례의 진행 순서

1. 민준의 필드/단위/권한 인계 중 확인된 자료만 선택한다. 원본 해시·수신시각·변환 규칙과 실제/참고/모의 범위를 기록한다. 미확인 값은 추정해 실제 값으로 만들지 않는다.
2. 기존 동결80회와 별도 경로에 새 입력·변경 전 원안·시나리오를 저장한다. 운송사 배차·차량·준비시각·대기/복귀시간은 확보된 실자료가 없으므로 명시적 모의/가정으로 둔다. 실제 변경이 없으면 제목부터 ‘실제 항차에 가정한 마감 변경’으로 쓴다.
3. 실행 전 입력·시드·방법별 계산 예산·여유시간 시나리오를 고정한다. B0~B3가 같은 조건을 쓰며 출발/고정 작업을 보존한다. 결과를 보고 입력을 바꾸면 별도 개발 사례로 남긴다.
4. 원안·후보의 미처리/위반/고정 위험을 먼저 비교한다. 처리 화물 집합이 같은지 확인한 뒤 변경 작업 수와 이동 부담을 비교하고 목적 단계별 증명 상태를 함께 적는다. 새 결과를 기존80회나 현장 실측 효과에 합산하지 않는다.
5. 현재 저장 API의 `422 DEMO_DATA_ONLY`는 유지한다. 읽기 검증만으로 혼합 자료 저장·독립 검사·승인을 허용하지 않으며 [선효 #31](https://github.com/unknownamed/banipmatch/issues/31)의 관련자 검토와 계약 결정을 따른다.

따라서 [대겸 #33](https://github.com/unknownamed/banipmatch/issues/33)은 **HJNC 실제 읽기 대조 추가 완료, 새 혼합 계산은 미완료**로 유지한다. 이번 작업은 새 평가를 실행하거나 기존 솔버·API·DB 계약을 변경하지 않았다.

## 재현 범위

허용된 동일 표본과 실제 수신기록을 가진 작업자는 PR42의 위 커밋에서 `backend.references` CLI에 `--source hjnc --kind reference --received-at 2026-11-09T12:51:14Z`와 본인 표본 경로·로컬 읽기 근거를 지정해 상태를 대조할 수 있다. 이 시각은 해당 해시의 표본 전용이며 다른 파일에는 사용하지 않는다. 최신 head에서는 변경 차이를 먼저 확인한다. 민준의 표본이나 Git의 집계 JSON은 이 원문 입력을 대신하지 않는다.

관측 비교 도구와 기존 수집 근거는 [공통 실제 자료 계획](../team/real-data-integration.md)을 따른다. 외부 발송·재수집·키 공유·공개 배포는 하지 않았다.

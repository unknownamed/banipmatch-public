# AIS 합성 데이터 · 오프라인 시연

2026-11-10 안선효, #36 후속. 실제 부산 자료 확보와 별개로 **명시적으로 선택한 모의 모드**를 구현함. 최신 main에서 별도 시연 브랜치를 만들고 기존 AIS 수신 시험 작업을 보존해 이어감. #31 초안 PR과 섞지 않음.

## 부산0건의 해석

실제 시험에서는 부산 기본45초/확대90초 모두 선택3종0건, 같은 키·코드의 마이애미 대조는 약4초에4건이었음. 인증·구독·압축·기본 파싱은 대조 해역에서 동작했음. 지역 자료 공급/커버리지를 우선 의심할 수 있으나 선박 부재·현재 제공사 장애를 확정한 결과는 아님. [기존 실행 기록](aisstream-first-response-plan.md) 참조.

[공식 안내](https://aisstream.io/documentation)는 사건 기반 수신이며 필터·현재 선박 활동·상위 자료원 중단·네트워크/처리 속도 등이 공백에 영향을 준다고 설명함. [한국 무수신 보고](https://github.com/aisstream/issues/issues/255)는 8월2일 사용자의 과거 보고이며 현재 장애 확인 답변이 아님. 이번 작업에서 실제 AIS를 추가 조회하거나 재수신을 기다리는 자동 작업은 실행하지 않음.

## 재현

저장소 루트, 기존 개발 Python 사용. AIS 키·websockets 추가 설치 없이 생성 가능함.

```powershell
python -m tools.demo_aisstream --mode simulated --output local/aisstream/demo-new
```

생성한 `index.html`을 브라우저에서 열면 됨. 서버·인터넷 없이 재생/일시정지·15초 진행·시간 이동·사례 선택·JSON 확인 가능. 기존 디렉터리를 지정하면 보존하고 실패함. 생성 실패 후에도 새 디렉터리명을 사용해야 함.

출력은 `index.html`, `manifest.json`, 사례별 `*.jsonl`과 `*.receipts.json`임. **manifest의 kind=simulated 및 수신시각 파일과 함께 전달해야 함.** JSONL은 공급자 wire 모양을 유지하므로 임의의 모의/수신 필드를 AIS 객체 안에 추가하지 않음. 이 파일들은 실응답 캡처가 아님.

| 사례 | 시연 내용 |
|---|---|
| 정상 수신 | 합성2척의 위치와 정적 이름을 같은 MMSI로 연결, 좌표 점 갱신 |
| 위치 중단 | 두 번째 선박이35초 이후 위치 미수신. 90초 경과 시 stale, 이전 점/수신시각 유지. 160초 정적 메시지로 위치 나이를 초기화하지 않음 |
| 정적 정보 누락 | 위치는 유지하고 이름/정적 연결은 누락으로 표시 |
| 잘못된 위치·식별자 | 위도91, MMSI/UserID 불일치2건 거부. 마지막 유효 위치 유지 |
| 위치 수신 없음 | 구독 확인만 있고 위치 없음. 선박 없음으로 표현하지 않음 |

재생은 합성3분을 실제18초로 압축함. 기본 화면은20초 지점이며 처음으로 버튼으로0초부터 볼 수 있음. 90초 신선도는 **시연을 위한 설계 선택**이며 AIS 규격의 수신 주기/안전 기준이 아님.

## 형식과 생성 근거

[공식 메시지 안내](https://aisstream.io/documentation)와 [공급자 모델](https://github.com/aisstream/ais-message-models/blob/master/type-definition.yaml)을 확인함. 마이애미 실수신은 집계만 보존했으므로 실응답 전체를 재사용하거나 부산 값으로 바꾼 것은 아님.

- 공통 envelope: `MessageType`, `MetaData`, `Message`. MessageType으로 Message 아래의 typed 객체를 선택함.
- PositionReport: MMSI/UserID 연결, 유효성, 위경도, Sog(knots), Cog(degrees), 초 필드 등 사용. MetaData 좌표명은 현재 공식 예제의 Latitude/Longitude를 따름. 재생의 위치 검증은 PositionReport 본문으로 수행함.
- ShipStaticData: 이름·선박 종류·제원·Eta 등의 공식 필드 구조. Eta는 전체 연도/UTC 도착시각으로 복원하지 않으며 반입시간으로 사용하지 않음.
- StaticDataReport: A/B 부분을 나눔. A의 유효 이름만 연결하고 B나 빈 이름으로 기존 이름을 지우지 않음. 정적 메시지의 마지막 알려진 좌표를 이동 위치로 사용하지 않음.
- 선박명은 SIM 접두어, 식별자는 설명용9자리 생성값임. 실제 선박 조회/할당 확인을 거친 ID나 예약된 모의 MMSI 대역이라고 주장하지 않음. 위치는 부산 신항 주변 시험 사각형 안의 직선 생성점이며 실제 항로/해안선·항만 운항 가능성의 근거가 아님.
- 입력 시각은 고정 합성 UTC, 화면은 KST. 마지막 유효 위치의 수신시각으로 나이를 계산하고 provider time_utc나 AIS Timestamp에서 실제 관측시각을 추정하지 않음.

Replay는 합성 시연용 단일 소유 메모리 객체임. 생산 수집기·완전한 AIS 프로토콜 검증기·제품 API가 아님. 화면에는 모의 표식을 항상 표시하고 기존 API/DB/계산/승인·카카오 지도 화면은 변경하지 않음. 항차 연결·확정 반입 변경·승인 적격성은 모두 false.

## 실행한 확인

- 수신 도구+합성 재생 pytest **31개 통과**. stale 경계·정적 메시지의 나이 초기화 금지·A/B 순서·잘못된 위치/식별자·알 수 없는/이전 메시지·공급자 시각 분리·원본/기존 출력 보존·명시 모드 검사 포함.
- 공식 공개 모델을 읽어 생성한 typed payload **100개**의 필수 필드/자료형을 검사해 통과. 의도한 의미 오류2건도 타입은 맞으며 Replay에서 별도로 거부함. 이 검사는 공급자 실응답 전체 호환성이나 AIS 업무 의미 완전 검증이 아님.
- 브라우저에서5사례 전환, 위치 중단 후 fresh1/stale1·145초 경과, 정적 누락1, 오류2, 무수신0 위치, JSON 형식 펼침, 재생/일시정지 및 시각 진행 확인. 도형/합성 표식 표시 확인.
- 샌드박스에서 로컬 접속/자식 프로세스 실행이 지연되어 해당 실행은 중단하고 일반 로컬 환경에서 위 검사를 완료함. 키를 입력하거나 실제 외부 AIS를 호출하지 않음.

실제 부산 표본·커버리지·time_utc 의미·항차 연결·보관/공개 조건은 계속 미확인임. 합성 시연 성공으로 #36의 부산 실수신 완료나 현장 효과를 주장하지 않음. 외부 운영 연결/모의 자동 대체는 추가하지 않음. 독립 시연 도구의 관련자 검토는 민준1회가 필요하며 제품 화면 연결은 길웅과 별도 조정 대상임.

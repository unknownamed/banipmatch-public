## 광양항 CSV 품질 확인

원본은 CP949, 5,401,590바이트다. SHA-256은 `890bebf3f82d61a4efa2fa0161bf58907b31a89db4e5208646eb7bb9d04a251e`이다. 열은 차량번호·진입게이트·진입일시·진출게이트·진출일시·작업시간이다. 차량번호는 공개 원본에서도 마스킹되어 있지만 개별 행은 공유 Git에 복제하지 않았다.

원본을 수정하지 않고 전 열 공백 행만 기술통계에서 제외했다. 진입·진출은 `%Y-%m-%d %H:%M`으로 읽고 두 시각 차이를 분으로 계산했다. 원본 `작업시간`은 `시×60+분`으로 별도 계산해 비교했으며 불일치 원인은 미확인이다. 58,171건의 **출입시각 차이**는 중앙값23분·90백분위59분·95백분위73분, 범위0~360분이다. 백분위는 오름차순 `ceil(n×p)`번째 값으로 계산했다. 원본 작업시간과 같은 지표로 합치거나 불일치를 임의 교정하지 않는다.

이 값은 해당 터미널 입장 후 퇴장까지의 경과시간이다. 외부 게이트 대기·순수 하역 서비스시간·출발지에서 터미널까지 이동시간과 동일하지 않다. HJNC의 `service_minutes`나 `buffer_minutes`를 23분으로 변경할 근거가 아니며, 현재 합성 평가 결과에도 적용하지 않았다.

로컬 원본: `local/data-research-2026-11-09/gwangyang-west-2026-h1.csv`. 집계: 같은 폴더의 `gwangyang-quality-summary.json`. 팀원이 재검증하려면 위 공식 링크에서 원본을 받아 해시·인코딩·빈 행 수부터 대조한다.

후속: [공유 재현 집계](collected-samples-audit.json)와 [로컬 실행·외부 요청 준비](external-data-request.md)를 추가했다. 시간 불일치28,548건 모두 출입시각 차이가 원본 작업시간보다1분 컸다. 그 원인은 확인되지 않았으며 기존 해석과 합성 입력은 유지한다.

HJNC 페이지의 공개 JavaScript도 후속 확인했다. 표는 실제로 `stringContent`를 파싱하고 페이지 수는 `result.total / amount`에서 직접 계산한다. 따라서 `hasNext=false`만으로 수집 완료를 판단하면 안 된다. 앞선 날짜의 ETB를 가진 첫3행은 ATD가 요청 기간에 들어 있었으나, 이것만으로 서버 날짜 필터의 정확한 조건을 단정하지 않는다. 공개 화면 소스 확인이며 새 항차 응답 수집·허가 확보는 아니다.

# AISstream · 선효의 1회 수신 시험

담당 이슈 [#36](https://github.com/unknownamed/banipmatch/issues/36). 2026-11-10 공식 [시작 안내](https://aisstream.io/)와 [명세](https://aisstream.io/documentation)를 확인함. 계정 관리 화면 확인과 실제 키 인증·수신 성공은 별개로 기록함.

부산 실수신을 기다리는 동안 실행할 [합성 데이터·오프라인 시연](aisstream-synthetic-demo.md)을 별도로 준비함. 실응답 재생이나 자동 모의 전환이 아니며 합성 선박2척·5사례로 화면 동작을 확인함.

## 시험 범위

- 서버 WSS 한 연결·구독 한 번, 기본 수신 대기 최대 45초·50프레임. 별도 연결 대기 10초·구독 전송 2초·종료 대기 3초 상한. 자동 재접속·구독 갱신·대량 저장 없음. 연결 후 구독 전송 제한 2초로 공식 3초 조건에 맞춤.
- 기본 사각형은 위도 35.00~35.13, 경도 128.72~128.90의 부산 신항 주변 시험 범위임. 공식 항계나 AIS 커버리지 경계로 주장하지 않음. `--bbox south,west,north,east`로 좁게 조정 가능.
- 필요한 `PositionReport`, `ShipStaticData`, `StaticDataReport`만 요청하고 압축을 사용. 계정/IP별 3연결 제한을 늘리려 하지 않으며 다른 팀 프로세스는 종료하지 않음.
- 원본 프레임·키·선박명·MMSI 값·개별 좌표는 파일·표준 출력에 남기지 않음. 메시지 종류별 건수, MMSI 형식/중복 및 위치/정적 정보의 같은 MMSI 연결 건수, 위치 유효성·범위, 공급자 시각 차이만 집계함.
- `PositionReport.Timestamp`는 분 안의 초 값이므로 전체 날짜를 복원하지 않음. `MetaData.time_utc`의 정확한 의미는 미확인으로 남기며 수신시각과의 차이를 관측 신선도로 확정하지 않음. 정적 메시지의 마지막 위치를 현재 위치로 승격하지 않음.
- 수신 0건은 선박 없음의 증거가 아님. 항차 연결·확정 ETA·트럭/컨테이너 위치를 검증한 것이 아니며 앱 입력·지도·배차 계산에는 자동 연결하지 않음.
- 11월10일 통합 검토에서 집계 기준을 보완함. `MetaData.MMSI` 형식 검사와 본문의 정수 `UserID` 일치 검사를 분리하며, 본문 `Valid=true`와 좌표 유효성까지 통과한 위치만 선박 수·정적 정보 연결에 포함함. 누락/불일치 식별자와 무효 정적 메시지는 별도 집계함. 근거는 [공급자 모델](https://github.com/aisstream/ais-message-models/blob/master/type-definition.yaml)의 `UserID`·`Valid`이며 전체 AIS 의미 검증을 완료했다는 뜻은 아님. 아래 과거 실수신 집계는 당시 코드로 얻은 기록으로 보존하며, 원문을 보관하지 않아 새 기준으로 재검산했다고 주장하지 않음.

## 실행

선택 의존성만 별도 설치. 기존 API 서버는 이 패키지를 자동으로 읽지 않음.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-aisstream.txt
.\.venv\Scripts\python.exe -m tools.probe_aisstream --prompt-key --output local/aisstream/probe.json
```

`--prompt-key`는 터미널에서 키를 숨겨 입력하며 명령행에 키를 넣지 않음. 또는 소유자가 `AISSTREAM_API_KEY` 환경변수를 설정하거나 Git 제외된 `local/aisstream.key`에 한 줄로 저장한 뒤 `--key-file local/aisstream.key` 사용. 채팅·GitHub·프론트 환경변수로 전달하지 않음. 기존 출력 파일은 보존하며 새 파일명을 사용함.

키가 없으면 네트워크 없이 `key_missing`, 종료코드 2. 연결·키·자료 오류는 원문을 반사하지 않고 종류만 반환. 수신시간/건수 상한에서 연결을 닫고 `connection_closed` 확인. 구독 확인도 메시지도 없으면 성공으로 종료하지 않음.

## 확인·공유 기준

- 발급 상태 / 실제 연결·구독 상태 / 수신 상태 / 자료 의미·보관 조건 / 제품 채택을 분리.
- 개인 키의 서버 환경 사용·자료 보관·공개 시연·재배포 권한은 미확인. 선택 패키지의 라이선스를 AIS 수신 자료의 이용 허가로 해석하지 않음.
- 집계도 실제 시험 결과임을 확인한 뒤 공유하며, 원본 대량 저장과 공개 선박 지도는 별도 권한 확인 전 실행하지 않음.
- 시험 집계와 종료 여부, 막힌 단계만 #36 및 AP-06에 기록. 이 문서의 계획과 합성 테스트 성공을 실수신 완료로 쓰지 않음.

## 11월 10일 실제 실행 결과

- 09:11:59~09:12:48 KST(연결·종료 시간 포함), 기본 시험 범위에서 수신 대기 45초·한 연결·한 구독 실행.
- `SubscriptionConfirmation` 수신, `CompressionEnabled=true` 확인. 서버 키 인증·구독 연결은 확인됐으나 위치/정적 자료는 0건.
- `connection_closed=true`와 실행 프로세스 종료 확인. 키는 숨김 입력으로 전달했고 별도 키 파일·환경 파일을 생성하지 않음. 원본 프레임·키·선박 식별자·개별 좌표는 보관하지 않음.
- 집계는 제외된 `local/aisstream/`에 보관. 현재 MMSI/IMO/항차 연결·실위치/신선도·커버리지·보관/공개 조건 검증은 미완료. 0건을 선박 없음으로 해석하지 않음.
- 후속 시험은 담당자가 시각·범위를 정해 소량으로 수행. 이번 도구는 재접속이나 범위 확대를 자동으로 하지 않음.

### 같은 날 확대 해역 후속 시험

- 09:17:50~09:19:22 KST, 위도 35.00~35.15·경도 128.70~129.00으로 범위를 넓혀 수신 대기 90초·최대50프레임·한 연결·한 구독으로 추가 실행.
- 구독·압축 확인은 정상, 선택한 위치/정적 메시지 3종은 다시 0건. 연결과 프로세스 종료 확인. 이는 AIS 전체 메시지 종류나 해당 구역의 모든 선박이 없다는 증거가 아님.
- 첫45초/확대90초 두 시험 모두 인증·구독은 확인했으나 실제 선박 표본은 확보하지 못함. MMSI·항차 연결과 위치 신선도는 계속 미검증이며 제품 채택을 보류함. 무제한 반복·전체 해역 수집으로 확대하지 않음.
- 공식 [명세](https://aisstream.io/documentation)와 [개인정보 처리방침](https://aisstream.io/privacypolicy)을 재확인. 확인한 본문에서 AIS 원본의 팀 서버 운용·보관·공개 시연·재배포 조건을 확정할 근거는 확보하지 못함. 개인정보 처리방침을 AIS 데이터 이용 허가로 대체하지 않음.
- 다음 판단에는 다른 시간대의 소량 표본 또는 제공사의 해당 해역/필터 수신 조건 근거가 필요함. 이번에는 신규 외부 문의를 발송하지 않음.

## 실제 호출과 구분

활용신청 전3개 API는 모두 HTTP403·활용신청 필요 메시지였다. 본인이 신청을 마쳤다고 알려준 뒤 **API별1회, 총3회만 재조회**했다. 무한 재시도·예약 수집·전국 관측/장기간 이력 수집은 하지 않았다. 키와 개인정보는 공유 Git·로그·이슈에 포함하지 않는다.

|---|---|---|

지점22104는 공식 기상청 공개 관측망 자료의 거제도 코드에서 시작해 현재 `stn_inf.php` 응답으로 재확인했다. 특보 구역S1311100은 상세 페이지에서 연결한 [공식 구역 CSV](https://apihub.kma.go.kr/getAttachFile.do?fileName=%ED%8A%B9%EB%B3%B4%EA%B5%AC%EC%97%AD+%EC%BD%94%EB%93%9C.csv)의 부산앞바다와 대조했다. 상위 구역·다른 하위 구역의 행을 같은 경보로 무작정 합치지 않는다.

원본·수신시각·HTTP 상태·키를 제외한 요청 조건·SHA는 `local/kma-verification-2026-11-09/`에 보존한다. 이번 재조회 수신시각은23:06:42 KST이며 각 요청의 정확한 UTC 시각·원본 해시는 [공유 감사 JSON](kma-response-audit.json)에 있다. 이전403과 이후200을 모두 보존해 가입/발급과 서비스 권한을 구분한다. 이 로컬 경로는 팀원에게 자동 공유되지 않는다.

## 응답 형식과 시간 해석

- 본문은 EUC-KR 응답이며 로컬 파서는 CP949로 읽는다. 해양 관측은 CSV 구분자로14개 값과 빈 필드/`=` 종료 표지가 온다. 공개 출력표의12항목과 달리 실제 CSV에는 경도·위도가 있고 순서도 달라 출력표만 보고 열을 고정하면 풍속·파고가 어긋난다. 실제 형식으로 검사한다.
- 지점정보는9개 공백 구분 값인 이번 단일 지점 형식만 지원한다. 새 형식·공백이 있는 이름 등으로 구조가 달라지면 추정 복구하지 않고 거절한다. 일반적인 모든 지점 형식 지원을 뜻하지 않는다.
- 지점/해양 응답에는 시작·종료 표지가 있지만 이번 특보 응답에는 `#7777END`가 없었다. 특보 헤더와 각 행의10개 값/`=`를 검사하고 별도로 전체 범위 미확인을 유지한다. 종료 표지 없는 모든 텍스트를 정상 빈 결과로 받아들이지 않는다.
- 해양 API 공개 설명의 ‘가장 가까운 생산시각’과 응답 도움말의 ‘요청시간 -59분~00분 자료 모두 표출’ 표현이 다르다. 이번 요청은 `tm`을 생략했고23:00 관측1행이었다. 정확한 조회 범위 의미를 단정하지 않으며 각 응답 시각을 보존한다. 원문 시각을 오늘로 이동하거나 수신시각으로 덮어쓰지 않는다.
- 관측23:00 KST는14:00Z이고 수신까지402초(초 미만 절삭)였다. 수신 시점 이후의 관측은0/1행이다. 이것으로 항상 같은 갱신 주기·402초 지연을 보장하지 않는다.
- 부산앞바다 행은 풍랑 **예비**, 명령 **발표**, 발표시각11월8일16:00 KST였다. `TM_EF=202611092358`은 도움말상 **밤18시~24시의 예비 시간대 코드**이므로23:58의 정확한 발효시각으로 변환하지 않았다. 감사 결과의 `effective_at_utc`는null이고 원문 코드·예비 구분을 보존한다. 주의/경보 행의 시각 변환과 분리한다.
- 단위는 응답 도움말과 공식 명세에서 확인했다. 이번 관측의 파고·풍속·돌풍에 빈 문자열/음수·비유한 값은0/1행이다. 실제 결측 표본·결측 코드 전체를 확보한 것은 아니다. 타 API의 음수 센티널을 일괄0으로 바꾸지 않는다. 특보 행이 없거나 실패하면 ‘해당 구역 특보 없음’으로 단정하지 않는다.

## 검사와 재현

[오프라인 감사 도구](../../tools/audit_kma_response.py)는 저장된 원문과 HTTP 상태·실제 UTC 수신시각·대상 ID를 받는다. 네트워크·키·엔진 변환은 사용하지 않는다. 이전403은 `application_required`, 정상 유효 형식의 빈 응답은 `empty_framed_response`, 원문 구조 오류는 실패로 분리한다. 일부 특보의 종료 표지 부재를 전체 수신 완료로 표현하지 않는다.

```sh
python tools/audit_kma_response.py --input local/kma-verification-2026-11-09/sea-approved.txt --kind sea --http-status 200 --received-at 2026-11-09T14:06:42.294790+00:00 --station 22104 --output local/kma-sea-audit-new.json
python -m pytest tests/data/test_kma_response.py -q
```

기존 입력/출력을 덮어쓰지 않는다. 종료코드0은 감사 보고서 저장,2는 읽기/형식 오류,1은 저장 실패다. 보고서 생성은 자료의 진위·권한·엔진 적합성·현장 효과 승인이 아니다. 검사에는 KST 자정 변환·미래 관측·지점 불일치·실제 열 위치·결측/0구분·예비 시간코드·구역 선택·오류/잘린 형식·덮어쓰기/인수 비노출을 포함했다.

## 인계와 남은 범위

민준의 가입·발급·활용신청·첫 실응답 확인은 완료했다. **실제 결측 규칙·추가 지역 대표성/구역 계층·조회 범위 상충 설명과 공용 서버 사용/자료별 공유 조건은 추가 확인이 필요**하므로 #35는 열어 둔다.

- 선효: 개인키를 넘기지 않고 허용 표본·매핑·감사만 인계한다. 마지막 성공/실패/오래된 자료와 공급자 권한 오류를 구분하고 `simulated` 전용 저장 제한을 임의 해제하지 않는다.
- 길웅: 거제도 관측은 인근 참고, 부산앞바다 행은 예비특보로 표시해야 한다. 예비 시간코드를 확정 발효시각이나 터미널 운영 제한으로 표시하지 않는다.
- 대겸: 기상과 지연의 동시 발생은 원인 확정이 아니다. 검증된 입력의 보조 근거로만 검토하고 기존 반입시간·출발/고정 작업·80회 평가를 바꾸지 않는다.

생산 API·DB·엔진·화면·공통 계약 변경은 없다. 새로운 가입·결제·메일·기사 연락·공개 배포도 하지 않았다. API 활용신청은 사용자가 직접 수행했으며 AI가 대신 가입/인증했다고 기록하지 않는다.

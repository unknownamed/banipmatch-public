기준 main `4c1eb29`, 확인일2026-11-09. [민준 #30](https://github.com/unknownamed/banipmatch/issues/30)의 발급·첫 실응답 검증 후속이다. 사용자가 본인 명의로 발급한 키를 Git 제외 로컬 파일에 저장한 뒤 소량 호출을 요청했다. **키 유효성과 실응답은 확인했지만, 엔진용 이동시간 매핑은 보류한다.**

공식 근거: [현행 서비스](https://data.ex.co.kr/openapi/basicinfo/openApiInfoM?apiId=0147), [발급 화면](https://data.ex.co.kr/openapi/apikey/requestKey), [이용약관](https://data.ex.co.kr/portal/guide/useSite), [공공데이터 이용정책](https://data.ex.co.kr/portal/guide/publicDataPolicy). 이번에는 공식 상세 HTML·샘플 코드와 실제 응답을 확인했다. 이전 준비 문서의 약관 검토를 연결하며, 공용 서버 운영·숫자 한도·원본 재배포 허가를 새로 확정한 것은 아니다.

## 실제 수행

- 현행 `https://data.ex.co.kr/openapi/trtm/realUnitTrtm`에 총5회만 호출했다. 자동 재시도·주기 수집·전체 페이지 수집은 하지 않았다.
- 키는 메모리에서 요청에만 포함했다. 키 포함 URL·예외 문자열은 출력하거나 저장하지 않았다. 응답 저장 전 키 포함 여부를 검사했고5개 응답 모두 키 문자열이 없었다.
- 원본과 요청 조건·HTTP 상태·UTC 수신시각·원본 SHA는 개인 `local/road-api-2026-11-09/`에만 보관했다. [공유 감사 JSON](road-api-audit.json)은 키·개인정보 없이 집계와 필드/조건을 기록한다. 호출 시점의 표본이며 최신 교통정보 캐시가 아니다.

## 필드 대응과 채택 차단

| 원본 | 관측한 형식·의미 | 현재 처리 |
|---|---|---|
| `code`, `message` | HTTP200에서도SUCCESS/ERROR가 다름 | HTTP 상태와 본문 상태를 따로 검사. 오류를 빈 구간으로 바꾸지 않음 |

품질 검사: 구조 확인3행 중1행, 역방향5행 중3행에서 `timeMin ≤ timeAvg ≤ timeMax`가 성립하지 않았다. 정방향5행에서는 이 불일치가 없었다. 세 응답을 서로 독립 표본처럼 합산하거나 원인을 확정하지 않는다. 이 검사 결과를 숨기려고 평균을 최댓값으로 잘라내거나 행을 정상값으로 교정하지 않았다.

공식 화면이 호출하는 `openApiInfoDetail`은 POST404, GET405였고 세션을 유지한 재확인도 POST404였다. 상세 필드 안내를 얻지 못했으며 접근 제한을 우회하지 않았다. 코드·단위 설명이 확보되기 전에는 매핑 완료로 표시하지 않는다.

## 재현과 인계

[오프라인 감사 도구](../../tools/audit_road_response.py)는 네트워크·키를 사용하지 않고 저장된 응답을 검사한다. 원본/기존 출력은 덮어쓰지 않는다. 성공/빈 결과/공급자 오류/HTTP 오류를 구분하고 누락·비유한/음수 시간·방향·날짜·최소/평균/최대 순서를 집계한다. 종료코드0은 감사 보고서 생성,2는 읽기·형식 오류,1은 저장 실패이며 보고서 생성이 자료 채택을 뜻하지 않는다.

```sh
python tools/audit_road_response.py --input local/road-api-2026-11-09/forward.json --start 101 --end 102 --http-status 200 --output local/road-forward-audit-new.json
python -m pytest tests/data/test_road_response.py -q
```

- **민준:** 키 발급·인증·정역방향 연결 시험은 확인. 남은 것은 현행 단위/집계 코드/시간대의 공식 의미, 실제 필요한 영업소 쌍과 해당 차종 표본, 숫자 한도·캐시 및 공유 환경 조건이다. #30은 이 작업만으로 닫지 않는다.
- **선효:** 본문ERROR와 정상0행을 구분하는 예시를 활용한다. 실패를 모의 성공으로 대체하지 않으며 단위·시각 미확인 표본은 계산/승인 입력으로 승격하지 않는다. 키 전달 없이 허용 표본·집계만 인계한다. 현재 `DEMO_DATA_ONLY` 제한을 삭제하지 않았다.
- **길웅:** 이 표본을 현재 HJNC까지의 실시간 이동시간으로 표시하지 않는다. 참고 표본·수신시각·범위/품질 미확인을 구분한다.
- **대겸:** 기존 합성 이동행렬·80회 동결 평가를 보존한다. 구간·차종·단위 확인 후 새 사례에서 참고 구간과 가정한 접근/복귀/대기 시간을 분리한다.

이번 변경은 로컬 데이터 감사와 인계이며 생산 엔진·API·DB·화면·공통 v0.1 계약은 변경하지 않는다. 현장 효과·운영 외부 연결·공개 배포 완료가 아니다.

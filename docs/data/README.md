## 필드별 설명과 누락 대응

| 입력/원본 후보 | 의미·단위·근거 | 누락·혼동 방지 |
|---|---|---|
| `VOY_NO` → `voyage_id` | 원본 항차키와 출처·터미널을 함께 보존 후 내부 ID 연결 | 선명만으로 합치지 않음. 현 모의 V1/V2는 실제 항차 아님 |
| `YARD_OPEN/CLOSE` → `opens_at/closes_at` | 확인된 항차 반입 허용시간 후보 | ETB/방문예약/정산 마감과 구분. 시간대·확인자·시점·이력 필요 |
| `VSL_NM`, `ETB` | 선명·접안 예정. 원본 요약에만 존재 | 현재 Snapshot 필드가 아니며 반입마감으로 대체하지 않음 |
| `ready_at` | 상차 완료 후 출발 가능한 시각. 현 입력은 모의 | null이면 입력 부족. 서류 상태만으로 준비 완료를 추정하지 않음 |
| `travel_times.minutes` | 방향별 정수 분. 현 입력의 가정/모의 이동행렬 | 미확인 경로를0으로 채우지 않음. 실제 화물차 경로·법적 제한 검증 아님 |
| `gross_weight_kg`, 차량 용량 | 정수 kg. 현 입력의 모의 중량/허용값 | 누락을0으로 보완하지 않음. 실제 도로 적법성 판정 근거 아님 |
| 장비·작업 상태·고정 | DRY20/40, planned/departed, frozen과 이유 | 빈차/공컨을 혼동하지 않음. 출발 고정은 현 시제품 범위 |
| `service_minutes`, `buffer_minutes` | 처리시간과 계획 여유를 구분한 정수 분 | 관측 게이트 대기시간으로 설명하지 않음.0분도 일부 실험의 단순화 가정 |
| `evidence` | 유형·출처 참조·관측·수신 시각 | 선언된 유형은 진위/권한 인증이 아님. 미래 수신·역전/정밀도 오류는 차단 |

실제 자료를 확보하면 원본 참조·허용 범위·원본 시간대·수신 시각·변환표와 누락 건수/분모를 함께 남겨야 한다.
11월9일 공개 표본의 필드별 누락/분모는 별도 조사와 재현 보고서에 있다. 전체 모집단의 누락률·수집 주기·호출한도는 확인하지 못했다. 모의 입력이나 단일 공개 응답의 값이 채워졌다고 실제 자료 품질100%라고 쓰지 않는다.

## 설명·재현에 사용할 산출물

- [모의 입력 생성 근거](fixture-design.md):9종 목적·범위·단순화와 개발/평가 분리의 한계.
- [대표4작업 사례](representative-case.md): 값의 의미, 수작업 대조, 입력 오류·전체 흐름 설명 순서.
- [자동 집계 원본](input-audit.json): 입력별 정규화 해시, 선언된 출처, 사실 묶음 수·범위·null 집계.
- [고정 평가 데이터 근거](evaluation-data.md) · [변경 전후 감사 원본](evaluation-input-audit.json): 새10사례/전후20파일의 원본 해시·변경 범위·생성 재현 확인. 기존9종 감사는 그대로 보존.

```sh
python -m pip install -r backend/data/requirements.txt
python tools/audit_data_evidence.py --output local/input-audit-new.json
```

기본 범위는 위 실험 입력7개와 혼합 입력2개다. 입력/출력 경로를 바꿔 새 보고서를 만들 수 있다.
출력은 기존 파일을 덮어쓰지 않는다. 입력 거절은 보고서에 오류를 남기며 종료코드2, 경로/저장 오류는1이다.
정상 집계는0이다. 이 도구는 솔버·API·외부 웹을 호출하지 않고 입력과 과거 결과를 바꾸지 않는다.

보고서의 `declared_*`는 입력에 적힌 선언이다. `fact_bundle_count`는 재사용한 메타데이터 묶음 수이며 독립적인 현장 관측 건수나 실험 횟수가 아니다.
`observed_at_null_count`는 관측시각이 없는 묶음의 수다. 모의 자료에서 null은 설계된 상태이며 실제 결측률로 환산하지 않는다.
검사 통과·해시 일치는 일정의 실행 가능성·실제성·자료 이용권한·현장 효과를 증명하지 않는다.

입력 또는 데이터 검사/집계 코드를 바꾸면 새 결과를 생성해 `input-audit.json` 갱신 필요 여부를 검토한다.
CI는 현재 입력·검사 소스와 보관 보고서가 일치하는지, 기존 혼합 생성 코드가 저장 입력을 재현하는지 검사한다.

반입맞춤 - 팀 공유 개발 초안 v0.1
작성일: 2026-11-07

공유 방법
1. 네 명 모두 00_반입맞춤_공통개발규격_v0.1.pdf(6쪽)를 먼저 읽습니다.
2. 담당별 문서 폴더에서 본인 역할의 PDF(각 3쪽)를 읽습니다.
   01 프론트 / 02 데이터 / 03 최적화 엔진 / 04 API·통합
3. 개발할 때는 공통 규격과 예제 데이터 폴더를 같은 버전으로 사용합니다.
   실명 담당자와 프론트 도구는 아직 정하지 않았습니다.

들어 있는 것
- 공유용 PDF 5개: 공통 6쪽, 담당별 각 3쪽(합계 18쪽).
- openapi.yaml / openapi.json: 같은 내용의 내부 HTTP API 명세.
- contracts.schema.json: 입력·결과·승인 요청·오류 객체의 JSON Schema.
- schema.sql / DB_필드사전.tsv: SQLite 기준 스키마와 필드 목록.
- 의미검증_규칙.txt: JSON 형식 검사만으로 확인할 수 없는 업무 규칙.
- 예제 JSON 8개, 기대결과, 작업 CSV: 전부 모의 자료.
- 검수 기록과 재실행 스크립트.

현재 상태
명세와 예제를 검증한 개발 초안입니다. 실행되는 웹앱·최적화 엔진·인증 서버는
아직 만들지 않았습니다. 04_results_설명용.json은 수작업 예시이며 실제 계산
속도·최적성·현장 효과의 근거로 쓸 수 없습니다. 이 결과의 승인은 차단합니다.
참고 근거 폴더에는 HJNC 조회 요약을 함께 넣었습니다. 일부 필드의 근거이며
데이터 이용 승인 증빙은 아닙니다.
외부 API·지도·GPS·문자 연결과 자료 제공 권한은 별도 확인 후 구현합니다.

첫 통합 목표
같은 예제를 입력하고 J0 고정, J1/J2 조정, J3 미처리 근거를 한 화면에서 확인.
그다음 모의 결과를 실제 엔진 결과로 교체하고, 독립 검증을 통과한 결과만
내부 계획으로 승인합니다. 외부 예약 변경·기사 발송은 자동 실행하지 않습니다.

개발자가 검수를 다시 실행할 때
Python 3.12 환경 기준입니다. 별도 가상환경에서 아래 패키지를 설치합니다.
  python -m pip install -r 검수/requirements-validation.txt
  python 검수/validate_contracts.py
  python 검수/validate_db.py
SQLite 연결마다 foreign_keys와 recursive_triggers를 모두 켭니다.
검수 스크립트는 계약/예제 또는 메모리 DB를 확인합니다. 실제 서버나 외부 API를
실행하지 않습니다. DB 검수용 가짜 computed 상태는 DB 제약 시험에만 쓰며
최적화 엔진의 계산 결과로 사용하지 않습니다.

변경 관리
필드명·단위·필수값·상태 의미가 달라지면 네 담당이 함께 확인하고 규격 버전,
OpenAPI, JSON Schema, DB, 예제, 문서를 같이 갱신합니다. 기존 버전은 보존합니다.
공통 규격의 *_pages.json은 PDF 편집용 본문 사본입니다.

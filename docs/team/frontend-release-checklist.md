# 배포본 화면 검수 절차 · 길웅

작성 2026-11-11, 기준 main `9902b5d`(PR #64·#65 병합 후). 대겸 배포본에서 화면 담당이 직접 따라 할 순서다. 판정 칸은 [검수 기록 양식](release-acceptance-template.md)에 적는다. 이 문서는 **아직 실행하지 않은 절차**이며 체크한 항목이 없다. 로컬 검사 결과는 각 PR과 [#55 인계](handoffs/2026-11-11-choigilung-dispatch-response.md)에 있다.

## 배포 전에 대겸과 맞출 설정

- 프론트를 **`VITE_API_MODE=v2`로 빌드**한다(`npm run build`). 이 값이 없으면 공통 예제(설명용) 화면이 뜬다. `VITE_API_TOKEN`·관리자 비밀·ORS 키는 프론트 빌드 환경에 넣지 않는다.
- 같은 출처에서 `/v2/*`는 백엔드로 넘기고, `/recipient`·`/?…` 직접 방문과 새로고침은 `index.html`로 돌려준다. API 오류를 HTML 200으로 바꾸지 않는다.
- `sw.js`·`manifest.webmanifest`·아이콘은 사이트 루트에서 제공한다(`dist/` 그대로).
- 서버의 허용 출처(`BANIPMATCH_CORS_ORIGINS`/`PUBLIC_HOSTS`)를 실제 HTTPS 주소로 맞춘다. 맞지 않으면 쓰기 요청이 `ORIGIN_NOT_ALLOWED`로 막힌다.
- 서버를 켠 직후 첫 계산에서 B2가 제한시간을 넘긴 적이 로컬에서 1회 있었다(원인 미확정). 시연 전에 한 번 계산해 두고 결과를 기록한다.
- 웹 푸시는 VAPID 설정·`PUSH_ENABLED=1`과 시연 세션의 시험 발송 허가가 있어야 한다. 허가는 운영자(대겸)만 한다.

## 기록할 기준 정보

배포 URL, main SHA, 빌드 시각, 검사 기기(PC 브라우저 / Android Chrome / iPhone iOS 버전), 시나리오·실행·계획 ID와 버전(토큰·초대 비밀은 적지 않음).

# 최종 통합·배포·보고서 검수 기록 양식

**실행 전 양식이며 빈 칸은 통과가 아니다.** [전체 완료 계획](completion-plan.md)에 따라 팀원이 자기 파트/통합본을 검사해 대겸에게 보고하고, 대겸이 통합·수정·보완한다. 서버/주소·실제 배포는 대겸이 직접 수행한다. 발표자료는 이번 검사 범위가 아니다.

## 실행 기준

- 검사자 / 일시(KST): 미기록
- main SHA / PR / 실제 배포 빌드 버전: 미기록
- 환경 / Python·Node·OS / PC·서버 자원: 미기록
- URL 또는 로컬 / 실제 키 소유자 허용 환경: 미기록
- 시연 세션 A·B / 시나리오·입력 해시·실행·계획 버전(비밀 토큰 제외): 미기록
- 실제 제공자·관측/수신시각·이용범위 / 동결 실험과 새 실행 차이: 미기록

## 팀원 보고 → 대겸 수정 → 재확인

- 재현 순서 / 기대·실제 / 안전한 증거 / 영향: 미기록
- 대겸 수정 커밋·배포 버전 / 담당자 재시험 결과: 미기록
- 중요 오류 / 조건부 보류 근거·대안·보고서 표현: 미기록
- 파트준비 / 통합최종본 / 배포 / 보고서파일 완료: 모두 미판정
- 사용자에게 필요한 서버환경·설정·주소 정보(비밀값 제외): 미기록

상세 버그 보고는 GitHub의 ‘통합·배포본 테스트 결과’ 템플릿을 사용한다. 필수 검사를 임의로 해당 없음 처리하지 않는다. API별 실패를 다른 API 성공과 합쳐 통과로 바꾸지 않는다. 정적/로컬검사·과거 동결결과는 새 공개계산 검수의 대체가 아니다.

# 대회 완성본까지의 전체 작업과 완료 기준

2026-11-10 작성. 사용자가 요청한 **완성본까지의 전체 작업 목록**이다. 다음 할 일만 나열한 [자료 연결 실행 계획](data-demo-sprint-2026-11-10.md)을 포함하며, 설계 v6·심사 보완서·현재 계약을 기준으로 한다. 아래 일정은 팀의 작업 목표이고 담당자의 완료 약속이나 이미 끝난 사실이 아니다. 새 API/DB 필드를 이 문서만으로 확정하지 않는다.

전체 추적: [#50](https://github.com/unknownamed/banipmatch/issues/50). 새 결과물은 [릴리스/패키지 #47](https://github.com/unknownamed/banipmatch/issues/47), [보고서/제출 #48](https://github.com/unknownamed/banipmatch/issues/48), [발표/시연 #49](https://github.com/unknownamed/banipmatch/issues/49). 기존 개발 이슈7개는 그대로 사용한다.

## 1. 지금 어디까지 왔는가

확인 기준은 main `51b3545`다. 핵심 엔진 B0~B3, 모의 입력→계산→독립 검사→비교→로컬 내부 승인, 기존 지도, 동결 평가와 자료 공백9사례가 있다. **실제 API→웹 화면, 새 연결의 전체 검수, 최종 보고서·발표자료·제출 패키지·공개 URL은 아직 완료되지 않았다.** 통과한 테스트 수로 완성률을 계산하지 않는다.

- PR42는 읽기 모듈 초안이며 실제 HTTP 수집·화면 연결 완료가 아니다.
- PR43은 AIS 수신 시험/합성 재생이며 관련자 검토가 남았다. 부산 실수신이나 제품 지도 연결 완료가 아니다.
- HJNC·KMA·도로의 실응답 검증과 AIS 제한 시험은 존재한다. ORS 발급·부산 실응답은 아직 증거가 없다.
- 대겸의 엔진·비교 도구 기반은 준비됐다. 자료 채택 판정, 새 통합 검수, 최종 설명·보고서·발표 검증은 남아 있다. 팀원 작업을 기다리지 않고 할 수 있는 보고서 본문·주장/근거 정리도 남아 있다.

## 2. 완성본의 범위

**주사용자:** 운송사 배차 담당자. **대상:** 부산항 신항(진해) HJNC 일반 수출 컨테이너의 확인된 반입시간 변경. 기존 배차의 위험을 점검하고, 출발/고정 작업을 보존하며 남은 작업의 조정안과 해결되지 않은 이유를 비교한다.

완성본은 다음 세 결과물로 구분한다. 한 결과물이 끝났다고 나머지까지 완료 표시하지 않는다.

1. **로컬 시연 앱:** 실제 자료의 조회·출처·시각·공백 표시 + 명시적인 모의 배차 계산·비교·내부 승인 + 선박 참고/차량 모의 지도. 실제 연결과 모의 계산의 경계가 화면에서도 보인다.
2. **대회 제출본:** 재현 가능한 코드/데이터, 20쪽 이내 보고서, 15쪽 이내 발표 PDF, 시연 순서·오프라인 대안·질문 답변 근거. 최종 메일 도착 확인까지 제출 기록을 남긴다.
3. **첫 공개 시연:** 기존 읽기 전용 모의 결과 탐색 화면을 HTTPS 주소로 게시하고 실제 URL을 검수한다. 로컬 실계산·승인 서버를 공개하는 것은 이 범위가 아니다. 호스팅 계정·게시 대상을 구체화한 뒤 사용자의 게시 승인을 받는다. 비공개 저장소를 자동 공개하지 않는다.

### 실제 자료의 필수 작업과 중단 기준

| 자료 | 이번에 끝낼 작업 | 완료로 인정하지 않는 것 / 조건부 처리 |
|---|---|---|
| HJNC | 기존 표본 매핑과 제한된 실제 조회 경로, 항차/반입시간 참고 표시, 부분 응답·시간대·권한 상태 명시 | 단일 조회를 변경 이력으로 표현하지 않음. 반복 수집·보관·공개 허용 미확정이면 해당 동작은 끄고 이유/확인 범위를 남김 |
| KMA | 본인 키 소유자 환경에서 해양·특보 실응답→서버→화면 검수, 지점/구역·관측시각·단위 표시 | 거제도 부이를 HJNC 실측 또는 지연 원인/분의 증거로 쓰지 않음. 키가 없다는 이유로 합성 응답을 실연결 완료로 표시하지 않음 |
| ORS | 길웅이 개인 신청/계정 한도 확인, 부산 방향별 matrix 표본 검증, 시간·거리 참고 표시와 null 처리 | 발급/응답 성공 전 완료 아님. 실제 제약·권한 문제로 채택하지 못하면 증거와 대안을 남겨 범위 판정. 단순히 작업 시간이 부족한 것을 불가능으로 쓰지 않음 |
| AIS | 기존 제한 수신 코드와 합성 wire 예제를 제품 참고 화면에 연결. 무수신·stale·오류·모의 재생 구분 | 부산에서 반드시 선박을 수신하는 것은 통제할 수 없는 조건. 0건이면 그대로 보이고 합성 재생은 별도 선택. 무한 재시도/선박·컨테이너·트럭 자동 동일시는 하지 않음 |
| 도로공사 | 검증 결과·단위/집계 공백·보류 이유를 자료표와 보고서에 반영 | 미확인 단위를 추측해서 엔진에 넣지 않음. 새 대체 공급자를 끝없이 늘리지 않음 |
| 실배차·GPS·입출차 | 일관된 모의 자료와 미확보/접근 조건을 설명. 공차·공컨·적컨·미확인 상태는 구별 | 실제 위치 추적·입출차 데이터 확보·현장 효과라고 주장하지 않음. 500건 생성은 필수 아님 |

**실제 외부 응답이 서버를 거쳐 화면에 표시되는 검증은 필수다.** KMA를 키 소유자 환경에서 검증하는 경로가 현재 현실적이다. HJNC/ORS/AIS도 각각 위 작업을 수행하고 채택/제약 결과를 기록한다. 한 API 성공으로 나머지가 전부 연결됐다고 닫지 않는다. 실패를 모의 성공으로 자동 치환하지 않는다.

**혼합 계산은 조건부다.** 실제 필드의 의미·시간대·단위·권한·신선도와 변경 확인, 공통 계약·저장·독립 검사·승인 경계가 검증되면 별도 사례로 구현한다. 그렇지 않으면 실제 참고 조회와 모의 계산을 분리한 완성본으로 명시하고 한계에 남긴다. 현행 `DEMO_DATA_ONLY`만 제거하거나 실자료에 simulated 표시를 붙여 통과시키지 않는다. 이 결정과 근거는 대겸·선효가 #33/#31에 남기며, 검증 없는 혼합 입력은 제출 전에도 도입하지 않는다.

이번 완료 조건에서 제외: 유료 화물 추적/회사 계약, 실제 기사 통보·예약 변경, 항만 전체 관제·선석 배정, 실GPS 수집 장치, 기상 기반 지연시간 예측 모델, 다중 고객 운영 인증/과금, 50건 B3의 전체 최적성 증명. 기존 기능의 오류를 고치는 일은 제외 대상이 아니다. 신규 요구는 범위·담당·검증·일정 영향을 적고 합의한 뒤 추가한다.

## 4. 네 명이 지금부터 끝까지 맡는 결과물

- **민준:** 데이터 준비·필드/출처/이용조건·합성 예제와 KMA 실제 검증, 보고서의 데이터/한계 부분, 제출 데이터의 재배포/재현 점검. 도로/기상 재가입은 하지 않는다.
- **선효:** 실제 읽기 API·AIS·계약/DB 보호·실패 처리, 실행 환경과 제출 코드 패키지, 정적 공개 배포 준비, 보고서의 구조/검증/운영 부분. UI·엔진의 미완성까지 혼자 맡지 않는다.
- **길웅:** 통합 화면·지도·ORS 신청/표본, 브라우저 사용성, 발표 PDF 디자인·시연 화면/오프라인 영상, 공개 화면 검수. 데이터의 의미/엔진 수치를 임의 수정하지 않는다.
- **대겸:** 자료 채택/혼합 경계 판정, 엔진 결과·모의 평가 주장, 최종 통합 검수와 보고서 편집·발표 흐름·제출 확인. 각 파트 본문과 결함 수정은 원 담당자에게 인계하며, 본인이 수정한 통합 오류도 기록한다.

### 대겸 파트의 남은 일

**지금 할 수 있음:** (1) 80회 평가/9사례의 보고서용 주장·근거표와 그림 선정, (2) 문제/경쟁서비스/차별성·한계 본문, (3) 최종 검수표·시연 대본·질문 답변 초안, (4) 코드/자료 패키지 포함·제외 목록, (5) 공개 모의 화면과 보고서 수치 대조. 현재 도구를 더 만드는 것만 반복하지 않는다.

**인계 후 진행:** (6) KMA/HJNC/ORS/AIS 실제 표시와 시각·단위·누락 대조, (7) 혼합 채택 여부 기록과 채택 시 새 사례 검사, (8) 동일 입력→실행→비교→승인 버전 최종 검사, (9) 통합 결함 수정/회귀, (10) 최종 보고서/발표 수치·파일·제출 기록 확정. **대겸 파트도 아직 완료가 아니다.**

## 5. 최종 수용검사

상세 실행 기록은 [검수 기록 양식](release-acceptance-template.md)을 복사해 남긴다. 새 연결을 합친 최종 main에서 수행하고 실패가 남으면 해당 범위를 완료로 표시하지 않는다.

1. **정상 경로:** 같은 입력으로 B0~B3 실행→원안/추천·미처리/고정 위험 비교→독립 일정 검사→내부 승인→저장 계획 일치.
2. **안전한 차단:** 준비시각/필요 경로/복귀 누락, 미확정 반입시간, 미래 근거, 오래된 실행/계획 버전, 중복 승인. 원래 차단 규칙을 유지하고 화면에도 이유가 보임.
3. **외부 자료:** 키 없음·인증 실패·timeout·429·0건·부분·stale·잘못된 ID/좌표를 구별. 실제 성공1건 이상은 출처/수신시각과 화면 대조. 각 공급자별 성공/실패를 따로 기록.
4. **지도와 화면:** 모의 움직임/실제 최종 관측 구별, stale 점 정지, 일반/위성 전환에서 선택 유지. 빠른 사례 전환·새로고침·실패 후 재시도·좁은 화면·키보드 조작 검사. 조작 중 중복 외부 수집이나 오래된 응답 덮어쓰기 없음.
5. **결과 정직성:** 같은 처리 작업을 비교했는지, 이동 증가·고정 위험·최적성 미증명을 숨기지 않는지, 비용·현장효과를 가정으로 확대하지 않는지 확인.
6. **재현/공개 경계:** 깨끗한 폴더에서 모의 실행, 키 미설정 안내, 허용 데이터만 포장. 공개 정적 결과는 새 계산/승인이라고 표시하지 않고 로컬 토큰/쓰기 API에 접근하지 않음.

관련 자동 검사는 기존 CI 명령을 사용한다: `python tools/check_development.py`, `python -m pytest`, 프론트 `npm test`·`npm run build`·`npm run build:showcase`, 루트 `python tools/build_showcase_evidence.py --check`·`python tools/check_showcase_dist.py`. 새 기능은 관련 회귀를 추가하며 CI와 브라우저/실API 수동 검사를 구별한다. 성능은 PC·입력 규모·계산 예산·실제 경과시간을 기록하고 계약된 timeout/예산과 비교한다. 근거 없는 응답속도 보장은 하지 않는다.

## 7. 제출 패키지와 최종 종료

권장 파일명: `반입맞춤_문제해결_보고서.pdf`, `반입맞춤_코드_데이터.zip`, `반입맞춤_발표자료.pdf`. 수정본은 로컬 보존 폴더/manifest에서 구별하고 제출 파일명에 임시 문구·중복 확장자를 넣지 않는다. 회신으로 다른 규칙이 오면 우선 적용한다.

ZIP에는 선택한 릴리스 커밋의 소스, 의존성/버전, 실행 README, 키 없는 환경 예시, 허용된 모의 데이터·스키마·출처/라이선스·평가 입력/결과·재현 명령, 실제 자료의 공개 가능한 검증 요약과 자료 미포함 이유, 파일 해시 manifest를 넣는다. `.git`, `.env`, 개인 연락처/서명/채팅, 실제 운송자료, 미허용 원문, 로컬 DB, 가상환경/node_modules는 제외한다. 원본 실험 기록을 현 버전 실행이라고 바꾸지 않는다.

- **개발 완료:** F01~F07의 필수 항목 검증, 조건부 항목의 판정/한계 기록, 중요 오류0, 최종 SHA/회귀·통합 증거 확보.
- **대회 제출 완료:** F08~F10/F12 결과물과 각 마감의 제출 기록 확보. 초안 생성/발송 버튼 클릭만으로 수령 확인을 대신하지 않음.
- **공개 완료:** F11의 실제 주소 검수·되돌리기 경로 확보. 파일 빌드/CI artifact만으로 공개 완료라고 하지 않음.

사용자에게 필요한 행동은 키 소유자의 인증/로컬 설정, 최종 게시 계정·공개 승인, 최종 제출 확인처럼 실제 막히는 시점에 구체적으로 요청한다. 키를 카톡으로 취합하지 않는다. 대겸이 모든 키를 새로 발급받아야 하는 계획은 아니다.

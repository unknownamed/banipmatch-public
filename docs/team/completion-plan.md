# 완성본 작업 계획 — 직접 계산 웹앱·보고서·코드

2026-11-10 최신 사용자 확정. **팀원은 자기 파트를 구현·시험해 인계하고, 황대겸이 최종 통합·수정·보완·최종본 제작을 맡는다. 서버 준비·실행·주소 설정·실제 배포는 대겸이 직접 한다. 팀원들은 통합/배포본을 시험하고 문제를 대겸에게 알려주며, 대겸이 수정·보완한다.** 현재 제출물 범위는 보고서와 데이터·코드다. 발표자료·리허설은 이번 작업에서 제외한다.

전체 추적 [#50](https://github.com/unknownamed/banipmatch/issues/50) · 통합/배포 준비/최종본 [#47](https://github.com/unknownamed/banipmatch/issues/47) · 보고서 [#48](https://github.com/unknownamed/banipmatch/issues/48). 발표 #49는 후속 보류다. 이전 정적 결과 화면만 게시하는 계획과 F08~F12 분담은 아래 최신 기준으로 대체한다.

## 2026-11-10 최신 추가 완료 조건

[담당자 대응 범위 R1~R8](dispatcher-response-scope.md)은 선택 기능이 아니다. 기존 F01~F12에 **F13 조건 재계산·변경 명세·웹 푸시·수신자 응답 왕복**을 추가한다. 선효 #54, 길웅 #55, 민준 #56, 대겸 #57. 먼저 로직/계약→화면/서버→대겸 HTTPS 배포→실기기 왕복을 수행하며 코드만 있거나 가짜 발송 상태로 동작하면 완료가 아니다. 전화/채팅·실차량 확보·터미널 예약/마감 자동 변경은 제외한다.

## 1. 완료 목표와 현재 상태

목표는 **방문자가 모의 배차를 직접 계산하고 원안·조정안·미해결 이유를 비교할 수 있는 배포 웹앱 + 그 구현/검증을 설명하는 최종 보고서 + 재현 가능한 코드·데이터 제출 파일**이다. 공개 앱의 계획 적용은 시연 세션 안에서만 이뤄지며 실제 운송사 계획·터미널 예약에 영향을 주지 않는다. 지정 팀원을 기사 역할로 연결한 웹 푸시·확인/수행 곤란 응답은 실제 기기로 검증하며, 일반 공개 방문자가 임의 실제 기사에게 보내는 기능은 허용하지 않는다.

설계 v6·후속 심사 보완과 개발 계약을 바탕으로 부산항 신항(진해) 수출 컨테이너의 확인된 반입시간 변경에 대응한다. 주사용자는 운송사 배차 담당자다. 출발/고정 작업을 유지하고 남은 작업만 조정한다. [자료별 상세 실행 계획](data-demo-sprint-2026-11-10.md)은 F01~F06 개발에 계속 적용한다.

main 51b3545에서 핵심 B0~B3, 모의 입력→계산→독립검사→비교→로컬 내부 승인, 지도, 동결 평가와 공백9사례가 있다. 그러나 **실제 API→제품 화면, 공개 계산 서버의 방문자 분리/자원 보호, 새 연결 통합검수, 최종 패키지·보고서·배포 URL은 미완료**다. PR42는 읽기 모듈 초안, PR43은 AIS 시험/합성 재생이며 관련자 검토·병합과 제품 연결을 구분한다. 통과한 테스트 개수로 완성률을 계산하지 않는다.

기존 dist-showcase는 저장 결과를 탐색하는 읽기 전용 화면이다. 보조·장애 대안으로 보존하지만 **직접 계산 배포 목표의 완료 증거가 아니다.**

각 담당은 자기 파트를 테스트한 후 인계한다. 팀원의 보고를 받으면 대겸이 직접 수정·보완할 수 있다. 원 파트의 설명이나 추가 확인이 필요하면 요청하되 모든 결함을 다시 작성자에게 돌려야 하는 규칙은 아니다. 큰 계약/파트 연결의 관련자1회 검토와 실제 GitHub 병합 제한은 기존 [리뷰 규칙](review-policy.md)을 유지한다. 테스트 피드백은 모든 PR의 반복 승인 요청과 다르다.

AI는 대겸 파트의 통합·검사·수정·패키지·절차·보고서를 돕는다. **이번 범위에서 AI가 임의로 서버를 띄우거나 주소/계정을 설정하거나 공개 게시하지 않는다.** 사용자가 배포 환경/주소를 알려주면 허용된 범위의 검수와 오류 보완을 돕는다. 계정/키는 채팅·Git에 쓰지 않는다.

## 4. 공개 계산 웹앱에서 반드시 할 일

대겸이 [현재 코드의 배포 전 공백](deployment-gap-audit-2026-11-10.md)을 점검했다. 방법별 자식 프로세스 timeout·단일 worker·중단 복구·독립 결과 검사는 이미 있으므로 재사용한다. 남은 것은 공개 방문자 격리·요청/큐/전체 자원 제한과 실제 배포 환경 경계다.

로컬 공통 demo token이나 loopback 제한을 단순 삭제해서 공개하지 않는다. 기존 v0.1은 보존하고 변경 응답/환경/저장 규칙은 제안·예제·회귀와 함께 정리한다. 공개 운영형 회사 서비스까지 확장하지 않고 **개인정보 없는 모의 시연**에 맞춰 아래 경계를 구현한다.

- **방문자 분리:** 서버가 발급한 추측 불가능한 시연 세션으로 입력/실행/계획을 분리한다. 다른 세션 ID를 바꿔 조회·수정·승인할 수 없어야 한다. 만료/정리·새 시연 시작을 지원한다. 공용DB의 하나뿐인 계획을 모든 방문자가 덮어쓰지 않는다.
- **계산량 제한:** 허용된 모의 예제/입력값·규모·method만 받고, 입력 크기·차량/작업 수·solver budget·전체 wall timeout·동시 작업·대기열·요청 속도를 서버에서 제한한다. 초기 상한은 실제 성능 시험으로 정해 설정/README/화면에 일치시킨다. 20/50건 기존 기록을 SLA로 바꾸지 않는다.
- **실패와 자원 회수:** timeout/실행 취소·재시작 때 내 계산 자식을 정리하고 상태를 남긴다. 중복 계산/적용과 오래된 결과를 막는다. 두 방문자 동시 계산·한도 초과·서비스 재시작 후에도 오염/무한 대기가 없어야 한다.
- **공개 경계:** HTTPS·허용 Origin/Host·프록시 신뢰 범위·세션 쿠키/쓰기 요청 보호를 배포환경에 맞춘다. 개발 토큰·제공자 키·원문 URL·개인자료는 브라우저/로그/ZIP에 노출하지 않는다. 임의 공급자 URL/파일 업로드·외부 예약·실제 기사 연락은 제공하지 않는다.
- **실자료 호출:** 서버의 허용 소유자 키만 설정하고 서비스별 한도/동시조회 묶기/재시도·429·캐시 조건을 지킨다. 모의 재생·지도 움직임이 외부 호출을 만들지 않는다. public 재표시/서버 사용 권한이 미확정인 공급자는 공개 기능을 끄고 상태/한계를 표시하며 합성 성공으로 위장하지 않는다.
- **운영 인계:** 대겸이 선택할 서버환경에 맞춰 패키지·환경변수 예시·프록시/HTTPS·저장수명·프로세스 시작/종료·재시작/health·로그·이전 버전 복구 절차를 제공한다. 호스팅/주소/유료결제는 팀원이나 AI가 임의 결정·실행하지 않는다.

일반 사용자 계정/결제/기업별 권한·실운송자료 운영은 별도 후속 범위다. 세션 격리만으로 상용 보안/다중 고객 운영 완성을 주장하지 않는다.

## 5. 실제 자료의 사용 기준과 종료선

실제 외부 응답이 서버를 거쳐 화면에 나타나는 검증은 필수다. KMA는 키 소유자 허용 환경에서 검증하는 현실적인 경로다. 다른 공급자도 각각 검증·채택/제약을 기록하며 한 건 성공으로 모두 연결됐다고 표시하지 않는다. 공개 배포에서 사용할 권한과 로컬 확인은 구분한다.

| 자료 | 끝낼 작업 | 제한·보류 기준 |
|---|---|---|
| HJNC | 실제 표본 매핑·제한 조회, 항차/반입시간 참고 표시, 부분/시각/권한 상태 | 단일 조회는 변경 이력이 아님. 반복/보관/공개 권한 미확정 동작은 끔 |
| KMA | 해양/특보 실응답→서버→화면, 지점/구역·시각·단위. 개인키 전달 금지 | 거제도 관측을 HJNC 실측·지연 원인/분으로 확정하지 않음 |
| ORS | 길웅 개인 신청/한도·부산 방향별 matrix 표본, 시간/거리·null 검증 | 발급·응답 증거 전 완료 아님. 추정 경로를 실시간 교통·화물차 통행 인증으로 쓰지 않음 |
| AIS | 제한 수신과 제품 참고/합성 재생·무수신/stale 처리 | 부산 수신 성공을 보장하지 않음. 실제 점을 모의로 계속 움직이거나 선박을 트럭 위치로 연결하지 않음 |
| 도로공사 | 단위/집계·품질 검증 결과와 보류 이유를 본문/자료표에 보존 | 미확인 단위를 추정해 계산하지 않음 |
| 실배차/GPS/입출차 | 모의 차량/작업·준비/복귀/고정·공차/공컨/적컨/미확인을 일관되게 시연 | 실자료/현장 효과로 부르지 않음. 수량500건은 필수 아님 |

혼합 계산은 필드 의미·시간대·단위·신선도·이용권한·변경 확인과 계약/저장/독립검사/승인 경계가 검증될 때 채택한다. 아니면 **실제 참고 조회 + 명시적 모의 계산**으로 한계를 남긴다. 현행 DEMO_DATA_ONLY만 제거하거나 실자료를 simulated로 위장하지 않는다. 대겸이 민준·선효 근거로 #33/#31에 채택 판정을 남긴다.

필수에서 제외: 회사/기관 자격·유료 계약, 실기사 통보/예약 변경, 항만 전체 관제/선석 배정, GPS 장치, 기상 지연시간 예측 모델, 50건B3 전체 최적성 증명, 이번 발표자료/리허설. 기존 기능 오류 보완은 계속 한다. 새 공급자·기능은 효용/권한/일정 영향을 확인하고 추가한다.

## 6. 대겸 파트: 지금부터 최종본까지

**지금 할 수 있는 것:** 기존 평가·공백9사례의 보고서용 주장/원시근거·그림 선정, 문제·차별성·방법·한계 본문, 최종 통합/두 방문자·배포검수표, 실행/제출 패키지 구성과 담당 연결 합의. 새 도구만 늘리며 본문 작성을 미루지 않는다.

현재 [본문 초안](../report/report-draft.md)·[E01~E09 근거표](../report/evidence-index.md)·[배포 전 코드 점검](deployment-gap-audit-2026-11-10.md)·팀원 테스트 이슈 양식을 작성했다. 실제 연결/공개 계산/배포 결과가 없는 부분은 미완료로 남겼으며 최종 PDF/최종 배포본이 아니다.

**파트 인계 후:** 최신 PR 검토·필요 보완/검사·병합, 최종 main 전체 연결, 실제 표시와 시간대/단위/출처 대조, 혼합 채택 판정, 새 공개 계산 경계의 검수, 최종 패키지·실행 절차 확정.

**본인 서버 준비 후:** 대겸이 직접 주소·서버를 설정해 실행/배포 → 팀원 테스트 → 대겸이 이슈별 수정·회귀/배포본 재확인 → 해당 버전을 보고서/코드 패키지에 고정. 대겸 파트도 아직 끝난 상태가 아니다.

## 7. 테스트 인계 방식

각 파트는 인계 시 최신 main/관련PR 기준 SHA, 변경 내용, 실행 명령·통과/실패, 입력/기대/실제, 미완료·설정 조건을 남긴다. 통합/배포본에서는 다음 양식으로 **대겸에게 GitHub 이슈 또는 기존 이슈 댓글**로 알리고 카톡에는 링크/요약만 전달한다.

- 검사한 URL 또는 로컬 환경, 배포 SHA/빌드 버전·시각
- 브라우저/화면 크기, 시나리오·입력값, 재현 순서
- 기대 결과 / 실제 결과 / 개인정보 없는 화면·로그 근거
- 영향: 계산/데이터 오염·타 세션 접근·실패 은폐 등 중요 오류인지, 기능/표시 문제인지
- 대겸 수정 커밋과 같은 절차 재시험 결과

팀원이 발견 사실만 알리고 끝내지 않고 재현 근거를 준다. 대겸이 수정·보완하고, 해당 테스트를 한 팀원이 수정 버전을 확인한다. 같은 변경에 반복 사람 Approve를 요구하는 절차를 새로 만들지 않는다.

최종 확인은 정상 계산/독립검사/시연 계획 적용, 누락·미확정·미래근거·오래된 버전 차단, 각 공급자 성공/실패, 지도/모의 구별, 두 방문자 격리/한도·timeout/복구, 새 폴더 재현, 실제 HTTPS URL PC/모바일·재시작, 보고서/코드 버전 일치다. 자동 CI와 브라우저·실API·배포 검수는 구분한다.

## 9. 최종본 파일과 종료 기준

권장 제출명은 **반입맞춤_문제해결_보고서.pdf**, **반입맞춤_코드_데이터.zip**이다. 수정 전 파일은 별도 보존하고 임시 문구·중복 확장자를 제출명에 넣지 않는다. 회신으로 별도 규칙이 확인되면 적용한다.

ZIP에는 선택한 릴리스 소스·버전, 의존성, 설치/실행 README, 키 없는 환경 예시, 배포환경 설정/시작·종료·복구 절차, 허용된 모의 데이터·스키마·출처/라이선스·평가 입력/결과·재현 명령, 공개 가능한 실제 검증 요약·미포함 이유, 파일 해시 manifest를 넣는다. .git/.env/개인 채팅·연락처·서명/미허용 실제 원문·운송자료/로컬DB/가상환경/node_modules는 제외한다.

- **파트 준비 완료:** 자기 파트 검사·설정/한계 인계가 끝남. 전체 완료가 아님.
- **통합 최종본 완료:** 대겸 통합 후 중요 오류 해소·같은 버전 회귀/전체 검수·재현 패키지 확보.
- **배포 완료:** 대겸이 서버/주소를 실제로 올리고 직접 계산 가능한 URL에서 팀원 테스트·대겸 보완·재확인. 정적 결과/로컬 실행만으로 대체 불가.
- **보고서/제출 파일 작성 완료:** 전 페이지/수치/출처/한계/코드·자료·배포 상태 대조,20쪽 이내 PDF와 재현 ZIP 확정. 실제 메일 발송은 별도 사용자 제출 단계로 구분하며 이번 계획/문서 작업으로 발송했다고 기록하지 않는다.

따라서 현재 목표의 종료는 **통합 최종본 + 직접 계산 배포 검수 + 보고서/코드·데이터 작성 완료**다. 사용자 직접 배포 전에는 준비 완료까지만 표시한다.

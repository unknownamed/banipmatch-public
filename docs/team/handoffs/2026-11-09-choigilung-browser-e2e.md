## 요청과 결정

## 변경과 검증

- 환경: Windows 11, Node 24.16.0, Python 3.12.14, OR-Tools 9.15. 백엔드 `BANIPMATCH_RUN_MODE=engine`, 임시 DB, 모의 토큰(값은 기록하지 않음). 프론트 `npm run dev` + HTTP 모드.
- 확인한 정상·실패 사례 (실제 서버 응답):

  | 사례 | 결과 |
  |---|---|
  | 01 예제를 화면에서 등록·계산(B0·B3) | 201→202→200. B3 `OPTIMAL`, 독립 검사 `passed`. J0 원안 유지, J1/J2 조정, J3 미처리(준비 지연) |
  | 같은 실행의 승인 | `503 INPUT_EXPIRED`. 예제 기준시각(11-07)이 지나 서버가 정상 거절 |
  | 시각만 현재로 옮긴 01 모의 입력, B0~B3 | B1 `HEURISTIC`, B2·B3 `OPTIMAL`, 세 방법 모두 `passed` |
  | B3 승인 | **실제 승인 성공**: 내부 계획 v2, 외부 반영 없음 |
  | 승인 뒤 B1 탭 | "B3 조정안이 승인되었습니다" 안내와 함께 전송 차단 |
  | 새로고침 뒤 B2 승인 | `409 PLAN_VERSION_CONFLICT` 안내 (수정 뒤에는 보내기 전에 차단) |
  | 07 / 08 예제 | `422 INPUT_INCOMPLETE` (/jobs/1/ready_at), `503 WINDOW_UNCONFIRMED` (/change/verification). 거절 화면·재시도 숨김 |

  콘솔 오류는 위 의도한 4xx/5xx 응답의 리소스 로드 기록뿐이다.

- 검수 중 고친 화면 문제:
  1. 코드가 있는 503(`INPUT_EXPIRED` 등) 확정 거절이 "승인 결과 확인 필요"와 비활성 "다시 시도" 버튼으로 보였다. 이제 "승인 거절"로 표시하고, 재시도 가능한 오류에만 "다시 시도"를 쓴다(`ApprovalPanel.tsx`).
  2. 다른 방법 탭의 안내 문구 "승인됨입니다"를 "승인되었습니다"로 고쳤다.
  3. 새로고침하면 이미 승인돼 계획 버전이 바뀐 사실을 409를 받은 뒤에야 알 수 있었다. 이제 `GET /v1/plans/{plan_id}`의 현재 버전이 실행 기준과 다르면 보내기 전에 차단 이유를 보여준다(`App.tsx`). 최종 판단은 서버가 한다.
  4. 계산 요청 화면의 "현재 서버는 설명용 결과만" 문구를 실계산 모드에 맞게 고치고, 공통 예제는 승인 시 유효기간 만료로 거절될 수 있음을 적었다(`StartRunPanel.tsx`).
- 실행한 검사: `npx vitest run` 64개 통과(회귀 2개 추가: 503 확정 거절 표시, 계획 버전 이동 차단), `npm run build` 성공. 수정 뒤 같은 서버로 1·3·4번을 브라우저에서 다시 확인.
- 실행하지 못한 검사: Python 전체 검사(백엔드 미변경), 모바일 폭·접근성 점검.

## 다음 작업

- 남은 일과 담당:
  - (최길웅) 계산 요청 화면은 여전히 B0·B3만 요청한다. 설명용 모드는 B1/B2에 422를 주므로 서버 모드를 알 수 없는 지금은 유지했다. 실계산 시연에서 B1~B3 비교를 보이려면 방법 선택이나 서버 모드 표시가 필요하다.
  - (팀 결정) 공통 예제로 승인까지 시연하려면 예제 시각을 현재로 옮기는 시연용 입력이 필요하다. 이번 검수는 임시 스크립트로 모든 시각을 같은 폭만큼 옮겨 확인했으며, 저장소에는 넣지 않았다. 업무 값이 바뀌는 것이므로 데이터·API 담당과 합의 후 정한다.
  - 승인 확인 체크박스의 접근성 이름이 "on"으로 잡힌다. 디자인 교체 때 함께 정리한다.
- 연결된 파트에 전달할 것: 안선효 — `503 INPUT_EXPIRED`·`409 PLAN_VERSION_CONFLICT` 응답 본문과 코드가 화면 안내와 맞게 동작함을 확인했다.

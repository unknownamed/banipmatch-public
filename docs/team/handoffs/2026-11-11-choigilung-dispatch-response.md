# 길웅 #55 담당자 대응 화면·수신자 화면 인계

시작 main `740a2fb`(PR #61 v0.2 API 병합 포함), 작업 브랜치 `codex/choigilung-dispatch-response`. 제출 전 재확인 때도 main 변경이 없었다. 열린 PR #42는 프론트 파일을 바꾸지 않는다. API·DB·엔진·공통 계약은 바꾸지 않았다.

## 구현한 화면

- **v0.2 연결**: `VITE_API_MODE=v2`이면 `/v2` 세션 쿠키·CSRF로 연결한다. 관리자 토큰을 화면에 두지 않는다. 기존 비교·승인 화면은 그대로 쓰고, 예제 01은 서버가 현재 시각으로 옮긴 모의 입력을 쓴다.
- **R4 조건 보완·재계산**: 상차 준비·차량 가용·근무 종료 시각만 수정한다. 고정·출발 작업, 마감, 이동시간은 입력 칸이 없다. 확인된 조건(모의)과 가정 시험을 고르고 수정 이유를 반드시 받는다. 새 입력을 저장한 뒤 이전 실행과 같은 방법·예산·seed로 재계산하고, 서버의 전후 비교와 해석 한계를 그대로 보여준다. 가정 시험 입력은 화면에서도 승인을 막는다. 확인 시각이 입력 기준시각보다 늦으면 기준시각을 그 시각으로 옮긴다. 서버가 이 경우를 비교 한계로 표시한다.
- **R5~R7 전달·응답(담당자)**: 내부 승인 뒤에만 차량별 변경 명세와 확인할 사항을 보여준다. 재배정은 양쪽 차량에, 미처리 전환은 "운송 취소 아님"으로 표시한다. 시험 발송이 허가된 세션만 동의 확인 후 초대 링크를 만든다. 비밀은 `#` 뒤에만 둔다. 확인 체크 후 전달하며 승인당 멱등키는 1개다. 대상별 전달 상태와 사람 응답은 따로 표시한다(접수≠읽음≠확인≠수행 가능). 확실한 실패만 다시 보낼 수 있다.
- **수신자 화면 `/recipient`**:
  - 초대는 시작할 때 한 번 읽고 주소에서 지운다. 초대 해시로 만든 수락 키를 쓴다.
  - iPhone Safari에서는 수락하지 않고 홈 화면 추가와 붙여넣기만 안내한다.
  - 알림 허용·끄기는 버튼으로만 한다. 미지원·거절·서버 설정 없음은 따로 안내한다.
  - 내 차량 변경만 보여주고 상대 차량은 가린다. 열람만 기록한다. 응답은 확인함·수행 가능·수행 곤란을 명시적으로 고른다. 이전 계획 알림은 상세와 응답을 막는다.
- **푸시 표시 `public/sw.js`**: 잠금 화면에는 일반 문구만 쓰고, 알림을 누르면 `/recipient#notification=ID`를 연다. manifest와 아이콘은 수신자 화면에서만 연결한다. 오프라인 캐시는 넣지 않았다.
- **모의 링크 `/recipient?demo=1`**: 서버·푸시 없이 탭 메모리의 가짜 자료로 동작하고, 배너로 모의임을 밝힌다. 화면 확인·캡처용이며 수신 증거가 아니다.

## 실제로 실행한 검사

- `npm test` 15파일 130개 통과(새로 추가한 #55 테스트 포함), `npm run typecheck`, `npm run build`, `npm run build:showcase` 통과. 빌드 결과물에서 서버 토큰·개인키 문자열은 발견되지 않았다.
- 로컬 실제 서버(`BANIPMATCH_WORKFLOW=1`, `RUN_MODE=engine`) + 브라우저:
  - 세션 생성 → 예제 등록 → B0~B3 계산 → 위험 확인 → 내부 승인 v2.
  - J3 준비시각 보완 → 새 입력 → 재계산 → 전후 비교.
  - 가정 시험의 승인 차단.
  - 승인 계획의 차량별 명세, 허가 없는 세션의 초대·전달 차단.
  - `/recipient`에서 초대 제거, 잘못된 초대 거절 표시, `sw.js`·manifest 제공.
  - `/recipient?demo=1`의 수락 → 응답.
- **서버 쪽에서 본 현상**: 백엔드를 켠 직후 첫 계산에서 B2가 `실행 제한시간 초과`로 실패했다. 같은 입력으로 B2만 따로 돌리면 2.4초에 최적해가 나왔고, 다시 요청하니 B0~B3 모두 통과했다. 처음 라이브러리를 불러오는 지연으로 추정하며 확정하지 않았다. 배포본을 켠 직후 첫 시연에서도 날 수 있다.

## 확인하지 못한 것

- **초대 수락→구독→전달→응답의 실제 서버 왕복**: 시험 발송 허가 명령(`tools.workflow_admin authorize-test-session`)이 이번 작업 환경의 권한 검사에서 막혔다. 우회하지 않았다. 이 흐름은 가짜 서버를 둔 화면 테스트로만 확인했다.
- **실제 웹 푸시 수신**: HTTPS와 서버 VAPID 설정이 있어야 한다. Android Chrome과 iPhone 홈 화면 앱(iOS 16.4 이상) 실기기 검수가 남았다. iPhone의 Safari와 홈 화면 앱 쿠키 분리는 알려진 동작을 근거로 설계했고 실기기로 재현하지 않았다.
- **차량 추가(R4)**: 위치·방향별 이동시간까지 입력해야 해서 이번 화면에서 제외했다.
- **입력 부족 예제(07)의 보완 경로**: 서버가 예제 01만 현재 시각으로 옮겨서 07은 만료로 막힌다. 이 경로는 아직 연결하지 않았다.

## 배포 담당(대겸)에게

- `/v2/*`는 백엔드로 넘긴다. `/recipient` 직접 방문·새로고침·알림 클릭은 `index.html`로 넘긴다. API 오류를 HTML 200으로 바꾸지 않는다.
- `sw.js`와 `manifest.webmanifest`는 사이트 루트에서 제공한다. 서버의 허용 출처(`CORS_ORIGINS`/`PUBLIC_HOSTS`)를 실제 HTTPS 주소로 맞춘다.
- VAPID를 설정하고 `PUSH_ENABLED=1`로 켠다. 동의한 팀원 세션 ID만 허가한 뒤, 담당자 화면에서 초대 → 수신자 화면에서 수락·알림 허용 → 전달 → 응답 → 담당자 상태 순서로 왕복을 기록한다. 미지원·거절 기기는 미검증으로 남긴다.

리뷰 필요 — 선효 1회: v0.2 요청·응답과 쿠키·CSRF·수신자 경계를 화면이 맞게 쓰는지 확인. 실제 왕복 검수는 배포 후 함께 한다.

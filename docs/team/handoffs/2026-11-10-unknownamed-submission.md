# 대겸 인계 — 보고서·제출 패키지 준비

기준 main `96ce157`, 브랜치 `codex/unknownamed-submission-draft`. 대겸 #33/#47/#48에서 팀원 구현을 기다리지 않고 진행할 수 있는 보고서 편집과 패키지 재현 작업이다. 생산 API·DB·엔진·프론트 계약·동결 실험은 바꾸지 않았다.

## 구현

- `tools/build_submission_report.py`: 표지·참고문헌 포함10쪽 한글 PDF 검토본. 문제/경쟁·사용자 대응·실자료/공백·B0~B3·전체80회/대표6사례·변경/이동 도표·현재 구현과 미완료·도입/재현을 구성했다. 기존 원시 결과에서 표·그림을 만들고 솔버를 재실행하지 않는다. 짙은 초록·회색, 한글 폰트 내장, 클릭 가능한 출처를 사용한다.
- `tools/build_submission.py`: 지정 커밋의 Git blob 바이트를 내보내 로컬 변경/키/DB/캐시를 섞지 않는다. PDF 커밋·해시·입력과 생성기/의존성 해시를 대조한다. 과거 평가 소스21개를 별도로 보존하고 원래 해시와 비교한다. 모든 파일·바이트·SHA-256 manifest와 검토본 상태를 남기며 기존 출력은 덮어쓰지 않는다.
- `tools/check_submission.py`: Git 없는 새 추출 폴더에서 파일·보고서·과거 소스·동결 입력/80회 기록/일정을 검사한다. 추가 파일을 허용 목록처럼 조용히 받아들이지 않는다. 설치 전 또는 외부 가상환경으로 검사한다.
- [상세 재현 명령](../../submission/README.md). 기존 Git 이력 전용 테스트2모듈은 원본 저장소에서 실행하며 패키지 검수에서는 명시적으로 제외한다. 해당 검사를 삭제하거나 통과로 위장하지 않았다.

## 검사와 기록

신규 패키지 회귀22개: 경로 탈출·민감/로컬 경로 제외·바이트 변조·추가/중복·보고서 커밋/생성기 불일치·출력 덮어쓰기·작업트리 대신 커밋 바이트 사용. 생성기 코드 미커밋 변경을 보고서와 같은 커밋으로 표시할 수 있던 공백을 좁은 보조 검토에서 찾아 수정하고 회귀를 추가했다. 핵심 구현·수정·검증 판정은 대겸 작업에서 수행했다.

PDF 전10쪽 렌더 검수에서 표 머리글 줄바꿈과 0값 막대 표시를 보완했다. 최종 PDF/ZIP은 병합된 같은 커밋으로 다시 생성하며, 새 폴더 재현·CI 결과와 파일 해시는 PR/로컬 산출물 기록에 남긴다. 보고서 생성은 `requirements-report.txt`가 선택 의존성이고 운영 백엔드의 의존성을 늘리지 않는다.

실제 새 폴더 검사(소스 `89872bd`): 저장소 밖 Windows 임시 폴더에 ZIP을 풀고 Git 디렉터리 없이442개 파일·과거21개 소스·동결80회/20쌍(동일 작업14쌍)을 검사했다. 계약/예제29개·DB32개, 패키지 회귀384개·하위255개, Node24에서 프론트101개·타입·빌드가 통과했다. 패키지 회귀는 안내에 적힌 Git 이력 전용2모듈 제외 명령이며 전체 저장소 CI와 구분한다. 테스트는 로컬과 인메모리 클라이언트로 수행했고 실제 서버·외부 API·공개 배포를 실행하지 않았다.

이 작업은 검토본·재현 도구의 완료다. 조건 편집/전달·응답 화면/API, 공개 시연 보호, 실제 자료→웹 연결, 휴대폰 왕복, 실배포의 완료를 뜻하지 않는다. #47/#48/#57은 남은 통합/최종본 검수를 위해 열어 둔다. API/화면 인계가 들어오면 최종 소스와 실제 결과를 보고서에 반영하고 동일 절차로 새 파일을 만든다.

# 황대겸 · 엔진 시간 초과 진단 보완

최신 main0f5fc6a의 엔진을 점검해, B2/B3 모형 구성 시간 초과가 이미 확인한 입력 누락을 숨기는 오류를 재현하고 수정했습니다. 엔진0.2.3이며 API·DB·공통 계약·최적화 목적은 유지합니다.

## 전후 동작과 검사

공통 예제의 T1 `available_at`을 null로 두면 정상 계산은 `INPUT_INCOMPLETE`를 반환하지만, 모형 구성 중 시간이 초과되면 기존 구현은 `UNKNOWN`만 반환하고 해당 누락 사유를 잃었습니다. 접근 경로 D→O가 미확정인 경우도 같았습니다.

이제 초기안에서 발견한 누락, 차량 상태의 누락, 중단된 모형에서 발견한 진단을 보존합니다. 입력이 부족하면 `INPUT_INCOMPLETE`와 구체적인 `INPUT_MISSING`을 반환합니다. 고정 J0 기록, `NOT_RUN` 목적 단계, 최적성 미증명, `approval_eligible=false`는 그대로입니다. 입력이 충분한 시간 초과의 유효안을 버리지 않습니다.

새 회귀3개에서 수정 전 실패를 재현하고 수정 후 통과했습니다. 전체 Python174개·하위160개(엔진89개), 계약29개·DB32개가 통과했습니다. 실제 시계를 경주시키지 않고 생성 전/생성 도중 시간 초과를 제어해 검사합니다. 성능 모형 변경이 아니므로 이전72회 실험이나 PDF를 불필요하게 다시 생성하지 않았습니다.

## 연결 담당에게

- 선효: `solution_status`와 `issues`를 함께 유지합니다. 시간 제한 표시가 true여도 입력 확인이 필요한 결과일 수 있습니다. 단순 실행 재시도로 입력 누락이 해결된다고 설명하지 않습니다. 실제 엔진 연결·독립 일정 검사·승인 저장은 계속 선효 담당입니다.
- 길웅: `UNKNOWN`/시간 제한과 `INPUT_INCOMPLETE`를 구분합니다. 입력 누락 사유가 있으면 입력 확인 안내를 보여주고, 고정 원안과 남은 작업을 숨기지 않습니다.
- 대겸: 다음 우선순위는 실제 API 연결 후 같은 입력에 대한 엔진 직접 결과와 API 결과를 대조하는 것입니다. 50건 B3의 최적성 미증명은 여전히 남으며, 새 성능 변화나 통합 병목이 확인될 때 추가 실험을 진행합니다.

이 수정은 엔진 내부 진단의 보존이며, 별도 독립 일정 검증기를 구현한 것이 아닙니다. 외부 API 신청·배포·실제 데이터 확보가 이 수정의 전제는 아닙니다.

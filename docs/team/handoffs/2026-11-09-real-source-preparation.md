# 실제 자료 검증·신청 담당 인계

기준 main: `bdae3fa`(PR29 포함). 작업 브랜치: `codex/real-source-integration-prep`. 작업 시작/제출 전 원격 main과 열린 PR을 확인했다. 작업 시작 때 열린 PR은 없었으며 민준의 PR29 표본 감사 도구를 재사용했다.

## 이번 변경

- [실제 자료 실행 계획](../real-data-integration.md), API 신청·진행표, 역할·README·AI 지침을 갱신했다. HJNC/도로를 우선 검증하고 기존 지도는 활용한다. 기상·추적은 권한/표본/효용이 있을 때 추가한다.
- [민준 #30](https://github.com/unknownamed/banipmatch/issues/30)에 도로공사 키 보유 확인→없으면 본인 명의 즉시 신청→현재 응답/구간/단위/한도 검증을 배정했다. 발급·실응답은 아직 확인되지 않았다. 본인 키는 전달하지 않고 허용된 표본·검증을 인계한다.
- [선효 #31](https://github.com/unknownamed/banipmatch/issues/31)은 수집/캐시/실패와 혼합 입력 제한 검토, [길웅 #32](https://github.com/unknownamed/banipmatch/issues/32)는 항목별 출처·실제/참고/모의·실패 표시, [대겸 #33](https://github.com/unknownamed/banipmatch/issues/33)은 관측 비교·검증된 혼합 사례 평가다.
- 현재 API는 `simulated` 이외를 `422 DEMO_DATA_ONLY`로 거부한다. 이번에는 저장/승인 보호를 바꾸지 않았고 혼합 자료를 모의로 위장하지 않는다. 후속 파트 연결/공통 동작 변경은 관련자 1회 검토한다.
- `tools/compare_hjnc_observations.py`는 저장한 표본만 비교한다. 단일 관측/공통 항차 없음은 비교 불가, YARD_OPEN/CLOSE 차이와 ETB 차이는 별도, 조회에서 사라진 항차는 취소로 해석하지 않는다. 공급자 변경시각·시간대·전체 페이지·진위·권한은 확인된 것으로 만들지 않는다. 원본/기존 출력 덮어쓰기와 인수/오류의 원문 노출을 막는다.

## 검증

- 합성 표본을 사용하는 새 비교 검사30개와 기존 표본 감사6개, 합계 **36개 통과**. 수신시각 역전·필수 항목 누락·중복·ETB만 변경·부분 페이지·공통 항차 없음·출력 보존·비밀값 출력 방지를 확인했다.
- 실제 공개 HJNC 응답1회: UTC `2026-11-09T12:51:14Z`, HTTP200, 5,739바이트, 10행/표시 전체24. 이 표본에 단일 관측 도구를 실행해 `not_comparable_single_observation`을 확인했다. 원본·수신기록·결과는 로컬만 보존했다. 주기 수집·변경 이력 확보·운영 앱 연결 완료가 아니다.
- 도로공사·HJNC·체인포털 공식 자료를 검토했다. 도로 구판 단위의 현행 적용, HJNC 시간대·수집 조건 등 미확인 사항은 실행 계획에 남겼다.
- 생산 엔진·API·DB·공통 계약·프론트·기존 동결 평가 원본은 변경하지 않았다. 화면이 바뀌지 않아 이전 브라우저 검수를 반복하지 않는다. PR의 정확한 head에서 실행된 CI 결과도 함께 확인한다.

## 다음 순서

민준의 신청 상태/응답·매핑 검증과 선효/길웅의 합성 응답 기반 준비를 병행한다. 의미·권한이 확인되면 혼합 입력의 저장/검사/승인 범위를 검토하고 새 사례를 연결한다. 자료 실패를 모의 성공으로 숨기지 않는다. 대겸 이슈는 도구 준비만으로 닫지 않으며 실제 채택/평가는 검증된 입력을 받은 뒤 이어간다. 기존 문의 외 새 메일·유료 계약·기사 연락·공개 배포는 하지 않았다.

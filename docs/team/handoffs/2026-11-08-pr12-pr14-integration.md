# PR12·14 통합과 심사 대응 문서 인계

기준일 2026-11-08. 사용자가 당시 열린 두 PR만 대겸 계정에서 선효 대신 검토하고 가능한 것을 병합하도록 지정했습니다. AI 보조 검토와 실제 검사에 근거하며 선효·길웅의 수동 검토로 기록하지 않습니다. 이후 새 PR까지 자동으로 대체 검토하는 상시 규칙은 아닙니다.

## 병합한 범위

- [PR12](https://github.com/unknownamed/banipmatch/pull/12), head `6f813e5`: 실제 B0~B3 계산, 독립 일정 검사, 로컬 내부 승인 저장. 기존 지적의 가용시각 역행과 프론트 목표 필드 불일치를 작성자가 수정한 것을 확인했습니다. 신규 고정 시간 회귀6개와 정확한 head의 CI3개가 통과했습니다.
- [PR14](https://github.com/unknownamed/banipmatch/pull/14), head `2e5cb51`: 로컬 입력 준비 CLI와 출처 시각 검사. 데이터60개/하위107개, PR12 실행 전 점검 연결5사례와 정확한 head의 CI3개가 통과했습니다. 새 중요 오류를 발견하지 못했습니다.
- PR12 병합 `a5a99d8`, PR14 병합 뒤 코드 기준 `54326f6`. 알려진 중요한 오류를 남긴 채 병합하거나 실제 GitHub 제한을 우회하지 않았습니다.

## 모두 합친 뒤 한 번 수행한 검수

- Python **216개**, 하위 사례 **221개**, 공통 계약·예제 **29개**, 메모리 DB **32개** 통과.
- 프론트 **62개**, 타입 검사·빌드 통과. 로컬 체크아웃의 오래된 의존성 때문에 처음에는 jsdom 누락이 발생했으며 잠금파일 기준 `npm ci --ignore-scripts` 후 통과했습니다. 코드나 검사를 약화하지 않았고 설치 후 npm audit 취약점0건입니다.
- CLI로 모의 입력을 검사·저장하고 생성한 해시를 실제 API 등록 및 결과 해시와 대조했습니다.
- 실제 자식 프로세스 B0/B1/B2/B3 계산과 독립 검사, 고정 J0 보존, B0 승인 차단 표시를 확인했습니다.
- 현재 시각으로 일괄 이동한 모의 입력을 사용해 **서버 시계 변경 없이** B3 내부 승인201·현재 계획 version2·같은 키 재시도·다른 키의 이전 버전409를 확인했습니다. 외부 동작은 false입니다.
- 새 출처 오류2종은 입력 등록201을 유지하면서 실행422 `INPUT_INVALID`와 원래 필드/오류를 전달했습니다. 거절한 실행은 DB에 생성되지 않았습니다.
- 임시 SQLite·파일과 테스트 실행 스레드를 정리했고 자식 계산 프로세스도 종료했습니다. 실자료나 인증키는 사용하지 않았습니다.

이는 ASGI HTTP·DB·CLI·실엔진 연결 검수와 프론트 컴포넌트 검사입니다. 브라우저 전체 조작 시연, 외부 항만 API, 실제 운송 효과, 다중 사용자 운영 인증·공개 배포가 완료됐다는 뜻은 아닙니다.

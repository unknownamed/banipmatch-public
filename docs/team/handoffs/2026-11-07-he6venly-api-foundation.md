## 구현과 결정

- `backend/api/`: 공통 JSON Schema 검사, 로컬 모의 접속, 공통 오류, 입력·실행·결과·계획 조회, 승인 차단
- `backend/db/`: 기존 SQL 초기화, 원본·검색 행·계획 저장, 멱등 응답, 활성 입력 변경, 불변 이력 보존
- 동일 DB의 서버 중복 실행 방지, 이전 queued/running 복구, 작업 중 조회 가능
- FastAPI·SQLite 선택 이유와 실행·설정·파트 연결 경계는 [백엔드 안내](../../../backend/README.md)에 기록
- seed·시간 예산은 저장하지만 설명용 재생에서는 계산하지 않음. 실제 엔진·일정 검사처럼 표시하지 않음
- 공통 예제에서 저장 ID 외 업무 값이 달라지면 설명용 응답 적용 차단. 07 누락·08 미확인 변경도 구분
- 설명용 결과는 항상 `illustrative_fixture`, `validation_status=not_run`, `approval_eligible=false`
- 이전 입력 결과 승인 409, 현재 설명용 결과 승인 422. 승인 저장·외부 행동 없음

## 실행한 검증

- Windows / Python 3.12.10·3.13.3: `python -m pytest -q` 각각 27건 통과
- 두 환경의 `python tools/check_development.py`: 각각 계약·예제 29건 + DB 32건 통과
- Python 3.12 검증 환경은 `local/venv312`, 기본 `.venv`는 Python 3.13.3임
- 실제 `python -m backend` 로컬 서버와 `python tools/demo_api.py`로 등록→입력 조회→B0/B3 결과→승인 차단 확인
- 검사 후 생성한 자식 서버 종료. 원본 v0.1 파일 변경 없음
- 최초 샌드박스 검사에서 임시 폴더·스레드 실행 문제가 있어 허용된 로컬 실행 환경에서 재검증
- 3.12 의존성 준비 중 uv 캐시 접근 오류로 중단 후 pip로 설치 완료
- CI 정의에 API 검사를 추가했으나 원격 Actions 실행 결과는 확인하지 않음

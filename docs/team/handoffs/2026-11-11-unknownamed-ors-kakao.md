# ORS·카카오 지도 실제 연결

사용자가 키 미확보로 막힌 기능을 확인한 뒤 ORS·카카오 신청 및 실제 연결을 요청했다. 기상청·AIS 이미 확보한 키를 다시 신청하는 작업으로 확대하지 않았다.

- ORS: 대겸 GitHub 간편가입, 이메일 읽기·약관·자동입력 방지 확인에 직접 동의를 받은 후 무료 기본키 발급. 뉴스레터 미신청. 계정 화면 Matrix500/일·40/분, Directions2000/일·40/분. 실제 키는 로컬 `local/secrets/ors-api-key.txt`에만 보관한다.
- 카카오: 대겸 계정에 기존 BIMC 앱(1470416)의 Editor 권한이 이미 있었다. 신규 앱·유료전환 없이 기존 JS 키와 지도 ON·무료쿼터를 확인했다. 기존 localhost:5173을 보존하고 현재 시연 HTTPS주소와127.0.0.1:8877만 도메인에 추가했다. 키값은 Git에 없다.
- 실제 수신: ORS `driving-hgv` 3×3 HTTP200. [길웅 표본과 동일한 근사 좌표](../../data/ors-matrix-verification.md)로 독립 호출했다. 신항 부근→사상 부근1732.86초, 반대1826.56초; 첫 지점 도로 보정207.23m. 실제 게이트 좌표가 아니다.
- 구현: `backend/references/ors.py` 고정 주소·좌표·1회·15초·1MB 제한, 인증 헤더/오류 본문 비노출·redirect 차단. 읽기 `/v2/references/current`에 선택적 `road` 추가, OpenAPI와 화면 동기화. null/양방향/단위/429/인증·형식 오류를 구분한다.
- 화면: 참고 자료의 ‘마지막 실제 수신’에 ORS 시간·거리·근사좌표/도로 보정거리·수신시각·출처·라이선스 표시. 카카오 일반/위성/위성+지명은 배경 지도이며 모의 선박 지도와 별도다.
- 검증: Python 관련68개, 프론트151개 및 타입/프로덕션 빌드 통과. 실제 배포 화면의 확인 결과는 #69 후속 기록과 함께 본다. 자동검사만으로 실기기/현장 검수 완료를 주장하지 않는다.
- 이전 동결 배차·승인·실제/모의 경계는 유지한다. ORS 값을 기존 가상 위치에 임의 대응시키거나 실시간 교통/실차 ETA로 표시하지 않는다. 도로 보정과 실제 업무좌표 확인 후 계산 채택은 별도 판단한다.

초기 실행은 AIS 기록 파일명을 잘못 지정해 외부 수신 후 저장을 완료하지 못했다. 파일명을 바로잡고 로컬입력 사전검증을 외부요청 앞으로 옮겼으며 최종 수신은 정상 저장했다. 실패를 성공 이력으로 세지 않는다.

기존 통합 PR68에 연결 변경을 포함한다. 요청된 관련자 최초검토는 유지하고 같은 사람에게 반복 검토 요청하지 않는다. 서버 실행/배포 범위는 사용자가 승인한 임시 HTTPS 시연이며 상시호스팅이 아니다.

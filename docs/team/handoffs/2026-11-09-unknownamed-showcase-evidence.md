# 황대겸 · 평가 결과와 시연 근거 연결

기준 main: `6b8a776`. 담당 내부 평가 자료와 공통 진행 안내를 정리했다. 생산 엔진·API·DB·v0.1 계약은 바꾸지 않았다.

## 준비한 자료

- [전체 10사례 비교표](../../experiments/engine-evaluation-2026-11-08/showcase.md)와 같은 내용의 `showcase.json`을 만들었다. 보존한 80회 중 모든 입력의 솔버 시드0 B0~B3 결과40개를 표시하며, 전체80회·20쌍의 집계도 함께 제공한다.
- 원시 결과의 `not_run`·승인 불가 값은 보존하고 별도 독립 검사 기록을 연결했다. 원본 JSONL 행 번호·입력·프로토콜·결과 해시와 실제 실행 소스 커밋을 추적한다.
- `tools/build_showcase_evidence.py --check`는 과거 소스·전체 조합·원본 해시·독립 검산·파생 파일 일치를 검사한다. 솔버를 다시 실행하거나 원본 평가를 수정하지 않는다. CI에는 과거 커밋을 읽기 위한 전체 Git 기록을 포함했다.
- PR18~22의 완료 내용을 README·역할표·현재 상태·심사 근거에 반영했다. 이미 끝난 방법 선택·시각 이동 입력·대표 브라우저 승인 검수를 다음 AI가 중복 구현하지 않도록 했다. 과거 인계 원본은 보존했다.

## 보고서·발표에서 설명할 내용

10개 모의 입력에 계산 시드2개와 B0~B3를 적용해80회 실행했다. B1~B3 조정안60개는 별도 일정 검사를 통과했고, B0 원안20개는 보존을 확인했다. B2와 B3의 미처리 수가 같은20쌍 중 실제 처리한 작업 ID 집합도 같은 경우는14쌍이다. 이 중 작은 사례12쌍에서는 B3의 변경 작업이4~7건 적었지만 이동시간은12~82분 더 길었다. 50건의2쌍은 차이가 없었으며 전체 최적성을 증명하지 못했다. 따라서 확인한 것은 변경 부담과 이동 부담 사이의 절충이며, 실제 배차 업무시간·비용 절감이나 상용 서비스보다 나은 성능은 아니다.

예를 들어 마감 단축8건·생성 시드101·계산 시드0에서는 두 방법이 같은 작업을 모두 처리했다. B2는 변경8건·이동342분, B3는 변경4건·이동376분이었다. 반면 고정 위험 사례와20건 사례는 미처리 수가 같아도 실제 처리 작업이 달라 같은 업무의 개선율로 계산하지 않는다. 고정된 작업에 남은 위험도 그대로 표시한다.

## 검증과 다음 연결

- 로컬 전체 Python **275개 / 하위235개**, 계약·예제29개, DB32개 통과. 새 회귀16개는 원본 변경·누락·중복·시드/방법 불일치·승인 값 변조·다른 처리 작업·50건 한계·솔버 미호출을 다룬다.
- `--check` 통과, 기존 80회 원본과 입력·프로토콜은 변경하지 않았다.
- 외부 리뷰 불필요: 담당 내부 읽기 전용 자료·검수와 기존 완료 상태 정리다. 독립된 공개 화면은 프론트 연결 변경이므로 별도 PR에서 최길웅에게1회 검토를 요청한다. AI 내부 검수를 팀원 리뷰로 대신하지 않는다.
- 50건 탐색 개선은 동결 평가 자료와 분리한 개발 입력으로 진행할 후속 연구다. 이번 결과를 보고 설정을 맞춘 뒤 같은80회를 새 평가인 것처럼 재사용하지 않는다.
- 실제 데이터·현장 수요·운영 인증·공개 URL 배포는 이번 근거 생성으로 완료되지 않는다.

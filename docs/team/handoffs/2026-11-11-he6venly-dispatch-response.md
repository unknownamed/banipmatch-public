# 선효 #54 담당자 대응 API·DB 인계

## 작업 기준

2026-11-11 원격 main을 fetch하고 최신 내용을 작업 브랜치에 반영한 상태에서 시작했음. 제출 전 재확인에서도 추가 main 변경 없음. AGENTS.md/CLAUDE.md, #54/#55, 최신 완료 계획·대응 범위 R1~R8·공통 계약·역할 인계를 확인했음. 기존 PR42/43의 최신 head·댓글·CI도 확인했으며 미병합 자료 연결 코드를 임의로 합치지 않았음. 기존 실제 자료 작업은 각 PR에 보존됨.

길웅 #55에 요청·응답/오류·쿠키/CSRF·수신자 경계를 먼저 공유했음. 관련자 검토 답변은 아직 없으며 합의 완료로 표시하지 않음. 새 v0.2 계약은 검토 대상이고 배포 v0.1은 보존함. 서버/주소/실배포는 대겸 담당임.

## 구현

- 원본을 보존하는 조건 수정과 새 시나리오, 이유/확인 구분/입력 해시 저장, 기존 엔진의 조건 검증·재계산 비교 재사용. 추가 차량 정보 부족·고정 작업 수정 차단. 가정 준비/가용 조건은 승인/전달 차단. 모의 이동행렬의 기존 가정 표시는 유지함.
- 일반 입력 등록으로 고정·정책·수정 이력을 우회하지 못하게 제한. 승인 후 next-input은 승인 배정·미처리/현재 버전을 보존하는 새 원안이며 이후 수정은 revisions 사용.
- 현재 입력/계획·실행·저장 해시·승인·독립 일정 검사를 재확인한 차량별 변경 명세. 재배정 전/후 차량·미처리·고정 위험을 보존. 기존 엔진 helper의 새 scenario_id 허용 누락1곳을 함께 수정했음.
- 담당자별 SQLite/멱등 범위·수명/자원 제한, 담당자와 수신자의 별도 HttpOnly 쿠키·CSRF·Origin·객체 권한. 공개 모드에서는 공유 토큰 v0.1 경로를 제공하지 않음.
- 운영자가 동의한 팀원 시험 세션만 CLI로 발송 허용. 초대30분·1회 교환, 차량과 수신자 분리, 구독/차량 연결·해제·만료. 명세/구독 원문·다른 차량 일정을 타인에게 노출하지 않음.
- 자체 VAPID 서명·표준 Web Push 암호화. 허용 중계망·공인 DNS/IP 고정·TLS hostname 확인·redirect/proxy 차단·별도 제한시간 자식 프로세스. 구독 암호화와 전역 endpoint 중복 연결 차단.
- 승인과 전달을 별도 저장. 중복 전송 차단, 접수/열람/확인/가능/곤란·응답 이력 분리. 확실한 실패만 명시 재시도, Retry-After 보존. 타임아웃/5xx/전송 중 재시작은 불명이며 자동 재발송하지 않음. 교체 전 구독의 늦은410이 새 구독을 지우지 않음.
- 최신 계획/알림만 상세 조회·응답 허용. 곤란 응답은 후속 확인으로 남기며 자동 재배차하지 않음. 재시작 복구·생성 중 중단 세션 차단·만료 비밀 제거·유예 후 자기 세션 DB 삭제·보호키 유실 시 기동 차단.

## 미완료·판단 이유

필수 요구사항은 R1~R8 전체이며 소스/로컬 검사만으로 #54를 닫지 않음. 남은 순서는 길웅의 계약 검토·화면/SW/manifest 연결 → 대겸 HTTPS 설정/배포 → 동의한 팀원 기기 실수신·본문·응답·담당자 상태 왕복 및 실패 검수임. 실제 폰/브라우저의 알림 허용·홈화면 조건, 신뢰 프록시·실주소·백업 복구·배포 용량은 미확인임. 공개 주소 생성·실제 발송은 수행하지 않았음.

입력256KiB·20작업/10차량·계산 큐4·세션100/TTL24h 등은 서버 보호를 위한 보수적 설계 선택임. 성능 SLA·현장 적정 수치로 검증된 것이 아니며 배포 환경에서 다시 검사해야 함. 무료 서비스의 실제 전달 품질도 보장하지 않음. 실제/혼합 입력 저장·계산의 DEMO_DATA_ONLY 제한을 임의로 해제하지 않았음. #31/#36 실제 자료 검증·채택 작업과 별도임.

리뷰 필요 — 길웅1회: 요청/응답·오류·CSRF/쿠키와 수신자 화면/SW 연결 경계 확인. 검토 이후 수정은 기존 정책대로 근거/필요 검사로 처리하며 같은 승인 절차를 반복하지 않음.

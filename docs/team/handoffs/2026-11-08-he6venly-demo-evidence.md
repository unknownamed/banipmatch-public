# 안선효 · 대표 사례 재현 도구

- 심사 증거 기준의 입력→실계산→독립 검사→내부 승인·저장 흐름을 공통 모의 예제 01로 고정. 업무·출처 시각을 같은 간격으로 이동하고 원본·서버 시계는 보존.
- `python -m tools.demo_engine_api`에서 등록·조회·해시 대조, B0~B3 동일 입력 계산, B3 독립 검사, 위험 확인 누락 422, 승인 201, 같은 키 재시도, 다른 키의 이전 버전 409, 현재 계획 일치를 확인.
- `--review-only`는 승인 요청을 보내지 않고 화면 검토용 입력·실행 ID를 제공. 실제 프론트 전체 조작 검수는 후속.
- 증거는 제외된 `local/demo-evidence/`에 저장. 입력·결과·승인·HTTP 단계·시각 이동·소스 해시를 남기고 인증 토큰은 저장하지 않음. 소스 해시는 실행 도구 측 기준이므로 서버 체크아웃·환경을 별도로 맞춰야 함.
- 검사: 신규 테스트 11건 통과. 시간 간격·원본·null 보존, 외부 주소 거절, 실제 엔진 API 흐름, 승인 전 화면용 모드, 기존 증거 폴더 보호, 입력 해시 불일치 차단 포함.
- 실제 로컬 HTTP 서버와 별도 SQLite에서도 기본 모드 통과. 실행 1건·방법 결과 4건·승인 1건·계획 2버전, 외부 동작 false 확인. 생성한 서버는 종료했고 DB·응답 근거는 로컬 보존.
- 이 입력에서 B1~B3은 모두 미처리 1건·변경 2건·이동 100분으로 동일. 연결 확인 사례이며 변경 최소화의 우위나 현장 업무시간·비용 절감 근거로 사용하지 않음.
- 다음은 민준의 입력 근거 및 대겸의 비교 사례와 대조, 길웅 화면의 같은 ID 전체 시연, 입력 누락·미확인 등 추가 실패 상황의 시연 근거 연결. 공개 배포·운영 인증·외부 연락은 이번 작업 범위에 포함하지 않음.

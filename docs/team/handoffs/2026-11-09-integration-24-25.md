# PR24·25 병합 후 통합 점검

기준 main은 `535e5ec`다. 길웅이 PR24 보완본 `709fa9a`를 확인한 뒤 대겸 계정에서 병합했다. PR25는 검토 중 길웅 계정에서 먼저 `02524bf`로 병합했다. 대겸 계정의 [AI 보조 리뷰](https://github.com/unknownamed/banipmatch/pull/25#pullrequestreview-5824236822)에서 재현한 세 문제는 사용자가 맡긴 병합 후 오류 보완 범위로 수정했다.

## 수정한 동작

1. 지도·비교 탭에서 현재 `run`·`scenario`와 경로를 유지한다. 쿼리 순서에 관계없이 `view`만 추가·제거하며, 계산 요청 탭에서는 새 요청을 위해 이전 실행 정보를 지운다.
2. 원안 시각이 null이거나 형식이 잘못된 경우 해당 작업을 미확인 목록에 남기고, 다른 작업의 시간축은 유지한다. 미확인 복귀를 임의 시각으로 채우지 않는다. 표시 불가능한 막대 대신 알려진 시각과 작업 ID를 확인할 수 있다.
3. 원안 배정 없음·조정안 미처리·조정안 결과 누락을 구분한다. 계산 전이나 전체 원안 미배정 상태에서도 작업 ID를 숨기지 않는다.
4. PR24의 비차단 제안도 반영했다. 비교 가능한 쌍이 없으면 `동일 작업 비교 쌍 없음`으로 표시하고, UNKNOWN은 `시간 내 해 미발견`, INFEASIBLE은 `해 없음`으로 기존 앱과 맞춘다.

API·DB·엔진·v0.1 계약·동결 평가 자료·의존성은 변경하지 않았다. 작업 브랜치는 `codex/integration-24-25-nov09`다.

## 확인한 결과

- 프론트 전체 **94개** 검사와 기존 앱·공개 화면의 타입 검사/빌드 통과. 새 탐색 회귀6개, 누락 시각·미배정·결과 누락 회귀7개를 포함한다.
- 동결 평가 자료의 출처/해시 재검사, 정적 공개 산출물3파일 경계 검사 통과. 과거 평가80회를 다시 계산하지 않았다.
- 새 모의 사례를 현재 시각으로 옮겨 별도 로컬 DB와 HTTP API에서 B0~B3를 실계산했다. 새 화면에서 방법·표/차량별 보기 전환, 지도 왕복 후 동일 실행·시나리오 유지, 미처리 확인 전 승인 차단을 확인했다.
- 브라우저의 B3 내부 승인201, 저장 계획v2와 선택한 결과 일치, 다른 방법의 중복 승인 차단, 새로고침 후 이전 버전 승인 차단을 확인했다. 외부 예약·기사 통보는 수행하지 않았다.
- 390px 페이지 가로 넘침·브라우저 오류 없음. 별도 가로채기 응답으로 계산 대기 중 원안 복귀 null과 J2 미배정을 화면에 넣어, 다른 막대·미확인 시각·J2가 모두 남고 NaN이 없는지 확인했다. 이 경계 사례는 실제 서버가 해당 결과를 계산했다는 증거가 아니다.
- 첫 브라우저 검수는 페이지 이동 후 B3가 계속 선택돼 있을 것이라는 검수 코드의 가정 때문에 중단됐다. 기존 기본 방법은 B1이므로 돌아온 뒤 B3를 명시적으로 선택하도록 검수 절차만 고쳐 통과했다. 제품의 방법 선택 동작은 변경하지 않았다.
- 사용한 임시 HTTP 서버·브라우저·계산 작업은 종료했다. 공개 호스팅, 실제 현장 자료, 실서비스 운영 인증은 이번 검수 범위가 아니다.

팀원은 최신 main을 반영하고 작업을 이어가면 된다. 같은 지적에 대한 반복 재승인은 요구하지 않는다. PR24의 새 버전 확인은 병합 전에 실제로 완료됐으며, 이번 오류 보완을 새로운 역할 변경이나 무관한 기능 확장으로 해석하지 않는다.

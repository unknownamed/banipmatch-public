## 검증과 비교의 경계

새 입력은 결과를 보기 전에 규칙·시드·시간 예산·해시로 고정했다. 작은 8개는 두 난수 구조의 상관 변형이며 실제 데이터 표본8개가 아니다. 새 사례로 엔진 설정을 조정하지 않았다. 엔진 원시 결과는 미검증·승인 불가 표시를 유지하고 API 검사기 결과를 실험 기록에 별도로 남긴다. 독립 검사 통과를 외부 예약·기사 연락이나 실제 내부 승인으로 해석하지 않는다.

도구는 잘못된 출력·입력 변조·검증 실패를 숨기지 않고 결과 로그와 실패 종료값을 남긴다. B0는 별도 일정 승인 대상이 아니므로 정상적인 원안 위험을 검사 실패로 세지 않는다. 비교는 입력·예산·시드별로 짝을 맞추며 미처리 수준과 작업 집합을 나누어 표시한다.

## 실행한 검사

- 전체 Python **227개 / 하위221개 통과**. 기존 작은 완전열거 검사도 포함했다. 새 평가 도구의11개 회귀는 변조 지표·고정 변경·입력/소스 해시·다른 처리 집합·누락/잘못된 결과와 원시 실패 보존을 확인한다.
- 처음 추가한 실패 보존 회귀4종은 요약 중 오류를 재현했다. 도구가 원시 오류 결과를 집계하지 않도록 고친 뒤 통과했다. 생산 엔진이나 독립 검사 조건을 약화하지 않았다.
- 80회 실행은 수정 전 평가 도구 커밋0d2640b의 유효한 결과다. 후속 실패 처리 보완은 잘못된 출력 집계만 수정했으며 원래80회 기록·프로토콜·입력을 덮어쓰거나 재실행하지 않았다. 실행 당시 소스 해시는 메타데이터에 보존했다.
- 평가 엔진 소스·입력20개(변경 전/후)의 고정 해시 일치, 관련 문서 상대 링크171개 확인. PDF4쪽 렌더·본문 경계·링크 확인 후 변경3쪽도 재검수했다.
- 계약·DB·프론트 코드는 변경하지 않았다. PR/main CI 결과는 GitHub 실행 기록에서 확인한다.

이번 PR은 생산 코드·공통 규격을 바꾸지 않는 담당 내부 평가 도구·실험 증거·안내 정정이므로 필수 사람 리뷰를 새로 요청하지 않는다. AI의 자체 검수와 보조 검토를 팀원의 수동 리뷰로 기록하지 않는다.

## 팀원이 이어서 할 일

- **황대겸:** 같은 사례의 화면 지표를 원시 결과와 대조하고 보고서에 절충과 한계를 설명한다. 50건 탐색 개선은 이번 평가 입력과 분리한 개발 자료로 진행한다. 새 튜닝 이후에는 별도의 평가 묶음이 필요하다.
- **최길웅:** 대표 사례의 입력→계산→비교→내부 승인 전체 화면 검수 시, 변경 감소뿐 아니라 증가한 이동·다른 미처리 작업·고정 잔여 위험도 표시되는지 확인한다. 이번 작업으로 화면 필드를 추가하라는 뜻은 아니다.
- **심민준:** 모의 가정과 실제 확보 자료의 필드·출처를 구분한다. 추후 허가된 실제 자료가 들어오면 생성 규칙의 대표성을 다시 판단한다.
- **안선효:** 기존 독립 검사·승인 연결을 유지한다. 실험용 감사 결과와 서버의 승인 판정·입력/계획 버전 확인을 섞지 않는다.

# 황대겸 · 엔진 0.2.2 성능 보완과 보고서 근거

기존 [PR #6](https://github.com/unknownamed/banipmatch/pull/6)의 B2/B3 구현을 보완했습니다. 기존 시간·고정·차량 조건과 공통 v0.1 계약은 유지합니다. 병합 시점·최신 커밋은 PR을 확인합니다.

## 변경과 근거

- 50건 계산에서 모형 구성 약0.47초보다 솔버 probing 전처리의 비중이 컸습니다. 미처리 수 탐색에 도달하지 못한 원인을 로그로 확인했습니다.
- 같은 초기안의 보조변수까지 완전한 힌트를 만들고 probing만0으로 설정했습니다. 힌트는 제약이 아니며 presolve 자체는 유지합니다. 최적성 판정·유효안 선택·고정 보호는 그대로입니다.
- 힌트가 전 변수를 중복 없이 채우는지, 모든 값을 고정한 검사에서 실제 제약을 만족하는지, 원안/미처리·고정 예약·빈 경로·변경 플래그를 확인하는 회귀4개를 추가했습니다.
- 전체 Python171개·하위156개(데이터40/API45/엔진86), 계약29개·DB32개 통과. CI의 최종 결과는 PR Checks에서 확인합니다.
- 기존156회 실험을 보존하고 후속72회와 원인 진단4회를 따로 저장했습니다. [실험·재현 안내](../../experiments/engine-profile-2026-11-08/README.md), [표·그림·PDF](../../experiments/engine-report-2026-11-08/README.md)를 보고서 작성에 사용할 수 있습니다.

## 개선과 남은 한계

20건 B3는 3초 예산의 반복3회 모두 미처리8·변경2·이동720분의 최적성을 증명했습니다. 동일10초 조건의 중앙 시간은5.21→2.42초입니다. 50건 B2·10초도 반복3회 OPTIMAL입니다. 50건 B3·10초는 미처리26만 증명했고 변경24→23의 유효안을 얻었으나 변경 최소성과 최종 이동 목적을 증명하지 못했습니다. 50건3초도 FEASIBLE 한계가 남습니다.

고정 포함 혼합 입력은 고정2건과 잔여 위험1건을 보존합니다. 모든 조정 결과의 내부 진단 위반은0입니다. 합성 사례의 결과이며 실제 업무 효율·상용 제품 대비 우위·공개 서버 응답 보장은 아닙니다.

## 다음 연결 담당

- 선효: `solve(snapshot, method, config)` 연결, 결과에 대한 독립 일정 검사, 입력·계획 버전 대조와 승인 저장. 현재 결과는 `validation_status=not_run`, `approval_eligible=false`입니다. 공개 시연의 계산 요청 제한·실행 프로세스 시간 제한도 별도로 필요합니다.
- 길웅: B0 원안 위반·고정 잔여 위험·미처리·변경·이동을 함께 표시하고 FEASIBLE/UNKNOWN을 최적성 증명으로 표시하지 않습니다. 승인 화면은 서버의 독립 검증이 연결되기 전까지 차단 조건을 유지합니다.
- 민준: 같은 입력을 데이터 검증과 실제 실행 경로에 연결하고, API 표본·합성 표본·실자료의 출처를 구분합니다.
- 대겸: 통합 후 같은 입력의 엔진/화면 결과를 대조합니다. 추가 성능 개선은 실제 통합 병목이나 다른 입력에서 확인된 실패를 근거로 진행하며 같은 실험을 이유 없이 반복하지 않습니다.

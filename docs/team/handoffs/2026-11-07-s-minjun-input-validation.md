# 심민준 · CSV/JSON 입력 검증 첫 구현

## 목적·범위

기존 모의 CSV·JSON을 다른 파트가 사용할 수 있도록 읽고 검사한다.
계약 `v0.1 / schema_version=0.1.0`을 그대로 사용하며 원본 자료를 수정하지 않는다.

## 한 일

- `backend/data/inputs.py`: JSON 읽기, 중복 키 거절, 작업 CSV 타입 변환, 출처 명시, 작업 오류를 원본 행에 연결.
- `backend/data/validation.py`: 공통 스키마, 키·참조·시간창·고정·원안 분할·누락·방향별 경로 검사.
- 정상 입력만 독립 사본으로 반환하고 오류 시 `snapshot=None`과 코드·필드·출처·행을 반환.
- `backend/data/README.md`: 설치·함수 호출·오류·검사 경계·다른 파트 연결 방법 기록.
- `tests/data/test_inputs.py`: 신규 25개 테스트. 정상/준비 지연, 누락/미확인, CSV 타입·행 번호, 참조·고정·경로 오류 등.
- 기존 GitHub Actions에 데이터 모듈 테스트 단계 추가.

## 최초 구현 당시 확인 결과

Windows 로컬 Python 3.13.7의 별도 가상환경에서 실행:

```sh
python -m unittest discover -s tests/data -v
# Ran 25 tests / OK
python tools/check_development.py
# 계약·예제 passed 29 / DB passed 32
git diff --check
# 오류 없음
```

Python 3.12 Linux 환경의 결과는 PR CI에서 별도 확인한다. 위 결과는 앱·외부 API·엔진·승인·현장 성능 검증이 아니다.
검수 의존성은 기존 `requirements-validation.txt`를 사용했다. 이전 검토 환경의 `jsonschema` 미설치 문제는 이번 개인 가상환경 설치로 해결했다.

## 최초 구현 당시 범위·한계

- 엔진 PR #1 코드 변경·병합 없음. 공통 계약·배포 문서·예제 변경 없음.
- DB·HTTP API·해시/버전 저장·독립 결과 일정 검사·승인 구현 없음.
- 외부 가입·API 신청·수집·메시지 발송 없음. API 준비 진행표를 완료로 바꾸지 않음.
- 일부 작업만 계산하는 정책은 없음. 입력 오류 시 전체 보류.
- 후보 접근 경로를 보수적으로 요구하며, 시간대 미상/KST 입력 자동 변환·실제 TMS 대응은 미구현.
- 스키마·입력 관계 통과가 일정 실행 가능 또는 승인 가능을 뜻하지 않음. 날짜 지난 예제도 입력 검사/재생용으로만 통과할 수 있으며 승인 최신성은 서버 책임.
- 동일 출처 메타데이터를 CSV 전체에 명시하는 첫 인터페이스다. 행별 외부 출처가 다른 파일은 사전 분리하거나 후속 확장이 필요.

## 다음 담당자가 확인할 것

1. 안선효: PR #3의 누락/미확인 입력 저장 정책을 유지하면서 실행 전 점검에 연결할 위치를 검토. 반환 snapshot이 없는 경우 엔진 호출 차단. 입력 누락 422/미확인 근거 503의 HTTP 구분은 API 담당이 유지.
2. 황대겸: 공통 예제/준비시각/고정 조건·필요 경로를 검토하고 엔진 입력 경계와 연결. B0/B1 코드와의 실제 통합 테스트는 별도.
3. 최길웅: 오류의 source/row/path/message 표시. 문맥 오류를 CSV 행으로 오인하지 않기.
4. 심민준: 합의한 연결 방식 반영, 허용된 외부 표본·시간대 근거 확보 후 정규화 범위 확장.

리뷰·병합은 [최신 팀 기준](../review-policy.md)을 따른다. 기존 리뷰의 지적을 수정하고 관련 검사·CI가 통과하면 재검토·추가 승인을 반복하지 않는다.

## 2026-11-07 병합 과정의 보완

사용자 요청으로 황대겸의 병합 작업에서 최신 main을 합치고 기존 리뷰의 두 시간 관계 오류를 수정했다.

- 변경·모든 시간창의 `confirmed_at > as_of`를 해당 필드 경로로 거절한다.
- `input_valid_until < as_of`를 거절한다. 같으면 허용하며 과거 재생 자료를 서버 현재시각 때문에 거절하지 않는다.
- 공통 의미 규칙의 UTC 분 경계를 관측·수신·확인 시각에도 적용했다. 이전 README의 메타데이터 예외 설명을 바로잡고 엔진의 소수초 잘림도 막았다. 초·소수초를 임의로 반올림하지 않는다.
- 복귀 후 확정된 다른 시작위치로 이동할 시간이 확보된 차량을 잘못 거절하지 않도록 데이터와 최신 엔진의 경계를 맞췄다. 이동시간 누락·부족은 계속 차단한다.
- 기존 데이터·엔진·API 검사를 한 CI 작업에서 실행하도록 충돌을 해결했다. 공통 계약·기존 예제는 보존했다.

API 엔드포인트에 이 모듈을 연결한 것은 아니다. 전체 화면 연결·독립 일정 검사·실제 승인·외부 API는 여전히 후속 작업이다. 최초 구현의 25개 검사 기록과 병합 보완의 추가 검사는 구분한다.

병합 보완 검사: Python 3.12에서 데이터 40건을 포함한 전체 Python 136건과 하위 사례 95건, 계약·예제 29건, DB 32건 통과. 시간 경계·과거 재생·CSV 문맥 오류·정밀도·복귀 후 가용 회귀 15건을 추가했다. 엔진 입력 방어 수정은 `0.1.2-b0-b1`로 식별하며 과거 실험 결과를 재작성하지 않았다. GitHub CI 결과와 병합 SHA는 PR #5 기록에서 확인한다.

# 황대겸 · B2/B3 후속 검증과 규모별 한계

기준 엔진0.2.1, 계약v0.1 유지. [PR #6](https://github.com/unknownamed/banipmatch/pull/6)의 같은 핵심 기능에 대한 후속 보강입니다. 기존 관련자1회 리뷰 요청을 유지하며 추가 리뷰어나 재요청을 넣지 않습니다. 병합 상태는 PR에서 확인합니다.

## 반영한 것

- 기존 시간 조건을 합친 차량별 작업량 한계로 증명을 돕습니다. 목적·가능한 일정·외부 함수 계약은 유지합니다. 양수 여유시간·0시간 작업·비삼각 이동·고정 근무초과·빈 경로를 검사했습니다.
- 독립 전수열거에 여유시간과 차량 재사용 조건을 넣고, 입력 배열 순서가 바뀌어도 증명된 목적값이 같은지 확인했습니다.
- `tools/build_engine_benchmarks.py`: 준비시각·장비·중량·3항차가 섞인12건과 출발/고정 예약 포함12건 생성. 모의 출처를 표시하고 데이터 모듈로 입력 검증합니다.
- `tools/benchmark_engine.py`: 입력/소스 해시·전체 결과·실측 시간·집계를 보존하며 동일 입력/예산으로 방법을 비교합니다. 실행 중 매 결과를 저장하고 기존 출력은 덮어쓰지 않습니다.

## 검증 결과

전체 Python167개/하위156개(데이터40/API45/엔진82), 계약29+DB32 통과. [156회 실험과 재현 명령](../../experiments/engine-sensitivity-2026-11-08/README.md)에 성공·동률·미증명 사례를 모두 남겼습니다.

- 20건·10초: B1 변경12→B3 변경2, 미처리8/이동720 유지, 반복3회 모두 최적성 증명.
- 혼합12건: B1 변경8→B3 변경5, 미처리3/이동540 유지. 고정 포함 사례도 고정2건과 잔여 위험1건을 그대로 보존.
- 50건: 1/3/10초에서 유효한 B1 초기안 유지, 솔버 첫 단계 UNKNOWN. 계산 성능 해결로 표시하지 않습니다.

## 다음 연결 담당자가 확인할 것

선효는 실제 `solve` 연결·독립 일정 검사·입력/계획 버전 확인·승인 저장을 맡습니다. 모든 결과가 `validation_status=not_run`, `approval_eligible=false`이므로 현재 엔진 결과만으로 승인 처리를 켜면 안 됩니다. 큰 입력의 제한시간/강제 중단은 API 실행 프로세스에서 별도로 제한해야 합니다.

길웅은 미처리·고정 위험·변경·이동과 단계별 최적성 미증명을 구분해 보여줍니다. B0 전체 위반을 마감 위반이라고 표시하지 않고, 시간 제한의 유효안은 실패나 최적해와 구분합니다. 민준은 실제 입력/출처 연결을 이어가며, 이 모의 시나리오를 현장 표본으로 취급하지 않습니다.

대겸의 다음 우선순위는 PR의 첫 피드백 대응, 통합 후 동일 입력 결과 대조, 50건 전처리/경로 탐색 병목 분석입니다. 관련자 리뷰 전 새로운 공통 계약·팀원 구현을 대신 확장하지 않습니다. 외부 신청·메일 발송·서버 사용·배포는 이번 작업에 포함하지 않았습니다.

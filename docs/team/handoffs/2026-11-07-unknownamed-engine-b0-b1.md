# 황대겸 엔진 첫 구현 인계 · 2026-11-07

작업 브랜치: `codex/unknownamed-engine-v01`. 작성자 외 팀원 검토 후 병합합니다.

## 구현한 범위

- `backend.engine.solve(snapshot, method, config) -> MethodResult`: B0 원안 진단, B1 마감순 삽입.
- 고정 작업의 원안 보존, 준비·반입 시작/마감·장비·중량·이동·복귀·근무 종료 검사. 삽입할 때 해당 차량 경로 전체를 재계산합니다.
- 출발 작업끼리의 점유 충돌, 잘못된 접두부 순서, 복귀/가용 누락이 있으면 해당 차량에 신규 작업을 배정하지 않습니다.
- 미처리·변경 작업 집합·이동합계와 근거를 반환합니다. 입력을 변경하지 않고 DB·네트워크·예약·통보를 실행하지 않습니다.
- [실행 안내](../../../backend/engine/README.md), [S001 계산 결과·해석](../../experiments/engine-b0-b1/README.md).

## 다른 파트 연결

**안선효 / API·통합:** 기존 Snapshot을 넘기고 반환된 MethodResult를 API 실행 ID·입력 해시·계획 버전에 연결합니다. 엔진의 자체 진단을 독립 일정 검사의 대체물로 쓰지 않습니다. 결과는 항상 `validation_status=not_run`, `approval_eligible=false`이며 독립 검사 후 승인 조건을 따로 판단해야 합니다.

```python
from backend.engine import EngineInputError, solve

try:
    result = solve(snapshot, "B1", {"seed": 0, "time_limit_seconds": 10})
except EngineInputError as exc:
    # category: invalid / incomplete; issues: 공통 Issue 형식
    # API 계약의 검증/실행 실패 흐름으로 변환. 성공 결과로 저장하지 않기.
    handle_engine_input_error(exc.category, exc.issues)
```

위 `handle_engine_input_error`는 API 연결 지점을 나타내는 예시 이름이며 이 저장소의 구현 함수가 아닙니다. 실제 API 오류 매핑은 담당 검토가 필요합니다. B2/B3 호출은 현재 `NotImplementedError`입니다.

**심민준 / 데이터:** 명세의 null을 0으로 바꾸지 말고 출발 작업을 반영한 차량 가용시각·시작 위치와 방향별 이동시간을 전달합니다. 일관되지 않은 고정 기록은 그대로 드러나며 신규 배정이 막힙니다. 미확정 반입시간 변경은 계산 입력에서 거절합니다.

**최길웅 / 프론트:** `issues`의 근거 수준과 원문을 보여주고 미처리·고정 위험을 따로 표시합니다. `HEURISTIC`을 최적해로 표시하지 않습니다. 미처리 작업을 제외해 위반이 줄어든 결과를 전체 해결로 표현하지 않습니다. 공개 시연에서는 모의 표시와 승인 불가 상태를 유지합니다.

## 계약상 확인이 필요한 두 지점

1. v0.1 이동합계는 null을 허용하지 않습니다. B0의 배정 작업 이동시간이 없으면 수치를 임의로 만들 수 없어 `EngineInputError(category="incomplete")`로 반환을 보류합니다. 계약 원본은 바꾸지 않았으며 API가 이를 입력 부족으로 처리해야 합니다.
2. 고정 작업의 `sequence`까지 그대로 보존합니다. sequence=1인 미래 고정 작업 앞에는 정수 슬롯이 없어 삽입하지 못합니다. 이 경우 `SEARCH_LIMIT/not_proven`이며 물리적으로 불가능하다는 뜻이 아닙니다. 향후 계약 변경 시 데이터/API/엔진 담당이 함께 검토합니다.

## 검사와 남은 일

- 엔진 51개 테스트: 공통 예제, 고정 예약·출발 충돌, 누락/0/방향성, 장비·중량·근무 종료·반입 시작, 시간 한도, 지표, 입력 불변, 계약 형식, CLI 실패와 아래 리뷰 회귀 8건을 포함합니다.
- 기존 계약·예제 29개와 DB 32개 검사는 원본을 임시 복사해 실행합니다. 기존 배포 자료는 수정하지 않습니다.
- B2/B3 최적화, 큰 시나리오 성능 실험, API·DB 연결·독립 일정 검사·승인·화면은 남아 있습니다.
- 현재 시간 한도는 삽입 후보 사이에서 검사하는 협력적 중단입니다. 공개 서비스용 강제 실행 제한이 아닙니다. API 단계에서 입력 크기 제한·별도 실행 프로세스 시간 제한·사용자별 요청 격리가 필요합니다.
- Python 3.12, 의존성 `jsonschema==4.26.0`. 설치·검사 명령은 실행 안내에 있습니다. 연구실 서버나 외부 API 키 없이 로컬에서 실행합니다.

첫 배포 목표는 모의 데이터 공개 시연입니다. 실제 배포, 외부 API 신청, 연락 발송은 이번 작업에 포함하지 않았습니다.

## PR #1 리뷰 반영 · 2026-11-07

안선효의 [P1·P2 지적](https://github.com/unknownamed/banipmatch/pull/1#issuecomment-6706855242)을 재현하고 엔진 `0.1.1-b0-b1`에 반영했습니다. API·DB 계약과 기존 실험 원본은 변경하지 않았습니다.

- **P1:** 복귀지 D에서 시작지 O로 10분이 필요한데, 복귀와 같은 시각 또는 5분 뒤에 O에서 가용하다고 적힌 입력을 정상 배차로 사용했습니다. 마지막 출발 작업의 복귀지→차량 시작지 이동과 원래 `available_at`의 관계를 검사하도록 수정했습니다. 모순·경로 누락은 `INPUT_INCOMPLETE`이며 고정 배정은 보존하고 신규 배정을 막습니다. 충분한 이동시간을 반영한 시작 상태는 유지합니다.
- **P2:** 장비나 중량 조건을 충족하지 못하는 차량의 접근 경로 누락을 수집하면서, 배정 자체는 불가능한 후보 때문에 전체 상태가 입력 부족으로 바뀌었습니다. 조정할 작업의 정적 적합성을 먼저 검사하고, 적합한 후보에 필요한 경로만 누락 사유로 수집합니다. 고정 작업의 기존 장비·중량 위험은 계속 보고합니다.
- `tests/engine/test_review_regressions.py`: 복귀 경계·5분 후·정상 이동·모순 가용시각·방향 경로 누락·마감 판정·장비/중량 부적합 경로·실제 필수 경로를 검사합니다. 엔진 51건, 계약 29건, DB 32건 로컬 통과.
- 아직 승인 리뷰가 아니므로 수정한 커밋에 대한 팀원 재검토 후 병합합니다. AI 자체 검토는 팀원 승인을 대신하지 않습니다.

# 심민준 · 로컬 입력 준비와 출처 시각 검증

## 최신 기준과 선택한 작업

사용자 제공 `banipmatch-main (2).zip`은 시작 시점 main `a6bd91d`의 파일과 동일했다.
최신 작업수칙·리뷰 기준·상태·데이터 명세를 확인했다. API 실행 전 데이터 검증 연결은
안선효의 PR #12에서 이미 진행 중이므로 중복 구현하지 않았다.

이번 변경은 데이터 담당의 로컬 입력 준비 도구와 출처의 시간 관계 검사다.
공통 계약 `v0.1 / 0.1.0`, HTTP API·DB·기존 모의 예제는 보존한다.

## 한 일

- `python -m backend.data validate-json`: 전체 Snapshot JSON 검사.
- `python -m backend.data import-jobs`: 작업 CSV와 문맥·공통 출처 JSON 결합.
- 정상 입력만 `--output`에 저장하고 `--report`와 표준 출력에 검사 결과·오류·정규화 SHA-256 제공.
- 기존 입력/출력은 덮어쓰지 않고 같은 경로 사용을 거절. 오류 입력은 스냅샷을 새로 생성하지 않음.
- 종료코드 0(성공)/2(입력 문제)/1(출력 경로·저장 문제) 구분.
- 모든 사실 묶음의 미래 수신 시각과 관측/수신 역전을 필드별 오류로 검출.
  - `EVIDENCE_AFTER_SNAPSHOT`: `evidence.received_at > as_of`.
  - `EVIDENCE_TIME_ORDER`: null이 아닌 `observed_at > received_at`.
- 미래의 계획 시각(`ready_at` 등)과 실제 관측 시각을 구분. 관측 null, 기준시각과 같은 수신, 과거 재생을 허용.
- CSV·문맥·공통 출처 파일의 오류 출처를 분리. 기존 `load_jobs_csv` 호출은 그대로 지원하며
  선택 인자 `context_source`, `evidence_source`만 추가.
- 기존 JSON 파서를 문맥/출처 읽기에서도 재사용하여 중복 키·잘못된 UTF-8 등을 동일하게 처리.
- 신규 검사 20개(출처 9개, CLI 11개)와 README 호출 예제·제약 설명 추가.

## 실제 검사

Windows Python 3.13.7의 개인 가상환경에서 실행했다.

```sh
python -m pytest tests/data -q
# 60 passed, 107 subtests passed
python -m pytest -q
# 194 passed, 221 subtests passed
python tools/check_development.py
# 계약·예제 29개 + DB 32개 통과
git diff --check
# 오류 없음
```

PR #12 head `ebb0f4a`의 `backend/api/input_preflight.py` 원문을 임시 검사에서 호출해
정상/기존 07·08/신규 출처 시각 2종의 총 5개 변환 사례를 확인했다.
기존 `INPUT_INCOMPLETE` 422, `WINDOW_UNCONFIRMED` 503을 유지하며 신규 출처 시각 오류는
`INPUT_INVALID` 422의 details에 원래 데이터 오류 코드와 경로가 전달된다.
이것은 어댑터 함수 호환 검사이며 PR #12 전체 병합·HTTP/DB 통합 검사 결과가 아니다.
비교한 다른 파트 코드를 이 PR에 복사하거나 병합하지 않았다.

## 한계·하지 않은 일

- 외부 가입·API 신청·수집·실자료 업로드·기사 발송 없음. API 준비 완료 여부 변경 없음.
- 새 HTTP 엔드포인트·CSV 업로드 UI·배차 계산·독립 일정 검사·승인 로직 변경 없음.
- SHA-256은 로컬 직렬화 대조용. 서버의 불변 저장·계획 버전·등록 검증을 대신하지 않음.
- 시각의 실제 진실성·원본의 이용권한은 검증하지 않음. 미래 원문을 과거로 옮기거나 정밀도를 버리지 않음.
- 서로 다른 행별 출처를 하나의 CSV에서 받는 기능·KST 자동 변환·실제 TMS 필드 대응은 후속.
- 두 출력 파일 저장은 트랜잭션이 아님. 출력 실패 시 종료코드 1과 보고서를 보고 기존/부분 출력 파일을 정상 결과로 채택하지 않아야 함.
- 프론트 변경 없음. 전체 Python·데이터 CLI 검사 성공을 브라우저 전체 검수·현장 효과로 표현하지 않음.

확보한 뒤 시각·필드 대응을 추가하며 현재 승인 대기 때문에 모의 입력 개발을 중단하지 않는다.

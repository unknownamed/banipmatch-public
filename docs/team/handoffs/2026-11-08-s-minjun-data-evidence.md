# 심민준 · 심사 대응 데이터 근거

## 기준·작업 범위

시작 시 최신 main `e2d9151`, 심사 증거 기준·역할·작업수칙을 확인했다.
새 기능 확대보다 출처/이용조건·모의 생성 근거·대표 사례 설명을 준비하라는 요청에 따라
기존 입력과 결과를 보존하면서 데이터 근거 문서와 재산출 도구를 추가했다.

## 한 일

- `docs/data/README.md`: 보관한 실제 공개 조회 요약과 모의 입력을 분리. 자료별 확보 범위·이용조건 공백·필드/단위·누락 대응·완료/미완료를 정리.
- `docs/data/fixture-design.md`: 기존9종의 목적·가정·단순화, 혼합 생성 공식, 개발/평가 미분리와 일반화 한계 기록.
- `docs/data/representative-case.md`: 공통4작업의 KST 설명표·원안·마감/준비 하한 검산, 오류 재현 명령, 입력→계산→검사→승인 연결에서 맞출 값, AI/도구/팀 설계 구분.
- `tools/audit_data_evidence.py`: 기존 검증기로 입력을 읽어 해시·규모·선언된 자료 유형·출처·관측시각 null·범위를 집계. 외부 권한/현실 대표성은 not_assessed로 표시.
- `docs/data/input-audit.json`: 보관 입력7종+혼합2종의 재현 가능한 감사 결과. 전부 data_mode=simulated, 정상 입력9종.
- `tests/data/test_evidence_audit.py`: 보고서/입력/검사 소스 일치, 순서/경로 중복, 해시, invalid 제외, 혼합 생성 재현, 출력 덮어쓰기 방지 등9개 검사.
- 문서 목록에서 새 근거 자료로 연결.

## 검사 결과

Windows Python3.13.7 개인 가상환경에서 실행:

```sh
python tools/audit_data_evidence.py --output docs/data/input-audit.json
# snapshot_count=9 / valid_snapshot_count=9
python -m pytest tests/data/test_evidence_audit.py -q
# 9 passed / 2 subtests passed
python -m pytest -q
# 225 passed / 223 subtests passed
python tools/check_development.py
# 계약·예제29개 / DB32개 통과
git diff --check
# 오류 없음
```

CI는 기존 전체 Python/계약·DB/프론트 검사 정의를 그대로 사용한다.
입력·검사/집계 소스가 바뀌면 보관한 감사 결과가 낡지 않았는지 검사하도록 했다.

## 확인된 한계·하지 않은 일

- 실제 운송사 배차·허용된 API 전체 응답·수집/저장/발표 권한을 새로 확보하지 않음. HJNC 요약의 전체51행 원본은 없으며 이번에 외부 재조회하지 않음.
- 기존 작은/규모7종의 최초 생성 기록 전체를 복구했다고 주장하지 않음. 현재 입력 파일과 기존 결과가 기준. 혼합2종만 기존 생성기와 객체 동일성을 추가 검사.
- 실제 자료의 누락률·변경 빈도·현장 비용 계수를 산출하지 않음. 모의 관측 null·반복 사실 묶음을 현장 표본으로 세지 않음.
- 엔진을 재실행하거나 과거156회/72회 결과를 소급 검증하지 않음. 새로운 독립 평가 세트를 만든 것은 아님.
- API·DB·공통 계약·입력 검증 판정·배포 PDF·기존 실험 원본 변경 없음.
- 브라우저 전체 시연·운영 인증·공개 배포·외부 연락·가입/키 발급 없음.

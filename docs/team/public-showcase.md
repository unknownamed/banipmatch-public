# 공개 모의 시연 준비

전체 작업은 [완성본 계획 F08/F11](completion-plan.md)·[릴리스 #47](https://github.com/unknownamed/banipmatch/issues/47)에서 추적한다. 선효가 패키지/게시 준비, 길웅이 공개 화면, 대겸이 수치·최종 대조, 민준이 자료 권한을 맡는다. 공개 URL과 코드·데이터 이메일 제출은 별개이며 공개 준비 때문에11/13 제출을 늦추지 않는다. 실제 게시는 구체적인 대상·계정·승인 후 수행한다.

첫 공개 자료는 보존된 모의 계산 결과를 탐색하는 정적 화면이다. 방문자가 새로운 계산을 요청하거나 승인·파일 업로드·외부 통보를 수행하는 서비스와 구분한다. 기존 로컬 앱의 입력→실계산→내부 승인 기능은 유지한다.

## 두 가지 시연

| 목적 | 실행 경로 | 확인할 것 |
|---|---|---|
| 실제 코드 연결 설명 | 기존 로컬 API와 `python -m tools.demo_engine_api --review-only` | 같은 ID의 입력·실계산·독립 검사·내부 승인, 별도 로컬 DB. 모의 토큰은 외부에 공개하지 않음 |
| 평가 수치·절충 공개 | `frontend/dist-showcase/` | 전체10사례의 보존 결과와 전체80회·20쌍 맥락. 서버·계정·공유 DB 없이 읽기 전용 |

공개 화면은 새 계산을 실행한 것처럼 진행 표시를 만들지 않는다. 원시 `not_run`·승인 불가와 별도 감사 기록을 구분한다. 다른 화물을 처리한 비교, 이동 증가, 고정 잔여 위험,50건의 이점 미확인도 표시한다. 실제 배차·GPS·현장 효과는 확보하지 못했다.

## 로컬에서 만들고 확인하기

저장소 루트에서 기존 Python 개발 의존성을 설치한 환경을 사용한다. 원본 검사에는 과거 실행 커밋이 필요하므로 얕은 복제본이면 Git 기록을 먼저 가져온다.

```sh
python tools/build_showcase_evidence.py --check
cd frontend
npm ci --ignore-scripts
npm test
npm run build:showcase
cd ..
python tools/check_showcase_dist.py
cd frontend
npm run preview:showcase -- --host 127.0.0.1 --port 4174
```

브라우저에서 `http://127.0.0.1:4174/`를 연다. 미리보기는 로컬 검수용이며 공개 운영 서버로 사용하지 않는다. 확인 후 해당 프로세스를 종료한다. 정적 모듈은 `file://`로 여는 대신 HTTP 정적 서버에서 확인한다.

## 게시 가능한 범위

- **`frontend/dist-showcase/` 내용만** 게시한다. 저장소·원본 개인 자료·`.env`·`local/`·DB·기존 앱의 `dist/`는 게시 대상이 아니다.
- 새 진입점은 API 클라이언트·지도·승인 코드를 불러오지 않는다. URL의 `view`, `run`, `scenario` 값을 바꿔도 기존 앱으로 전환되지 않는다.
- 소스맵·공용 파일 폴더·환경파일·개발 프록시를 공개 빌드에 포함하지 않는다. 빌드 검사는 가짜 환경 토큰이 산출물에 들어가지 않는지와 API 경로·불필요한 파일을 검사한다.
- HTML CSP의 `connect-src 'none'`은 스크립트의 API·WebSocket 등의 연결을 차단한다. 정적 HTML·JS·CSS는 같은 호스트에서 내려받는다. 개인정보 저장소나 계산 서버가 없으므로 이 화면에는 방문자별 DB 충돌·계산 요청 한도가 발생하지 않는다.
- 일반 웹 트래픽·전송량·접속 로그·HTTPS·보안 헤더는 선택한 호스팅 서비스의 조건을 따른다. 정적 화면이라고 운영 환경 확인까지 끝난 것은 아니다.
- 상대 경로로 빌드하므로 `/demo/` 같은 하위 경로에도 게시할 수 있다. 게시 후 실제 URL에서 새로고침·사례 선택·휴대폰 폭·CSP 오류를 다시 확인한다.
- GitHub `Frontend checks`에는7일 보관하는 검토용 산출물을 남긴다. **파일 보관은 공개 URL 배포가 아니며**, 워크플로에는 게시 권한·배포 단계가 없다. 저장소도 자동 공개 전환하지 않는다.

## 공개 후 실시간 계산까지 확장할 때

읽기 전용 화면을 공개하는 것과 기존 로컬 API를 인터넷에 여는 것은 다른 작업이다. 실시간 기능을 추가할 때는 사용자·시나리오·계획의 권한 분리, 입력 크기·방법·계산시간·동시 실행 제한, 큐·요청 속도 제한, 저장 수명·삭제, 승인 권한과 중복 처리, 비밀값 보관·HTTPS를 API 담당과 함께 구현·검수한다. 현재 공통 모의 토큰이나 loopback 서버를 외부로 노출하지 않는다. 이러한 운영 기능을 정적 화면이 구현했다고 표시하지 않는다.

## 담당과 남은 결정

- 대겸: 원시 결과·표시 지표·보고서 설명 대조, 파생 자료 원본 검사.
- 길웅: 새 독립 화면1회 검토, 표·선택·모바일·접근성 및 기존 앱 영향 확인.
- 선효: 기존 로컬 실계산·승인 시연 유지. 향후 실시간 공개 API 조건 검토.
- 민준: 모의 입력과 실제 자료의 출처·이용조건 구분 유지.
- 실제 URL을 만들려면 게시할 호스팅 계정·주소와 허용 비용을 확정해야 한다. 현재는 파일과 검수 근거를 준비한 상태이며 새 가입·결제·공개 게시를 실행하지 않는다.

## 참고한 공식 문서

2026-11-09 확인. 프로젝트 구성에 적용한 설계 판단과 제공사 문서를 구분한다.

- [Vite 정적 배포](https://vite.dev/guide/static-deploy.html): 빌드 산출물 게시와 로컬 미리보기 구분, 경로 설정.
- [MDN CSP connect-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src): 스크립트 연결 제한의 범위.
- [GitHub upload-artifact](https://github.com/actions/upload-artifact): CI 산출물 보관. 워크플로는 확인한v4 커밋으로 고정했다.

# 실제 자료와 모의 시연 연결 — 현재 작업 분담

**전체 일정과 종료 기준은 [완성본 전체 계획](completion-plan.md)·[#50](https://github.com/unknownamed/banipmatch/issues/50)을 따른다.** 이 문서는 F01~F07의 개발 상세이며 보고서·발표·패키지·공개까지의 전체 작업을 대신하지 않는다. 기존 공백9사례는 준비 완료, 실제 API→웹 연결과 후속 통합 검수는 남아 있다.

2026-11-10 사용자 최신 요청에 따른 실행 기준이다. **가장 최근 설계문서 v6(2026-11-07), 심사 보완서(11월8일), 개발 규격 v0.1과 이후 합의**를 기준으로 한다. 새 기능을 모두 넣는 계획이 아니다. 기존 4개 파트는 유지하며 다음 작업과 인계물을 구체화했다. 아래의 완료 조건은 아직 완료 사실이 아니다.

## 이번 목표

운송사 담당자가 확인된 반입시간 변경의 영향·원안·조정안·미해결 이유를 비교하는 웹앱을 완성한다. 실제 API 응답을 서버에서 받아 화면에 표시하는 데까지 연결한다. 개인이 사업자·기관 자격 없이 신청 가능한 자료를 우선한다. 가입·본인 인증·키 약관·무료 한도는 별도로 지킨다.

실제 배차·GPS 등을 확보하지 못한 부분은 **의미가 일관된 모의 자료**로 충분히 시연한다. 500개 같은 수량을 목표로 고정하지 않는다. 이미 있는 평가10사례·80회, 새 데이터 공백9사례와 AIS 형식 기반 시연을 먼저 연결한다. 부족한 상황만 추가하고 실제 표본 수로 합산하지 않는다.

발표에서 각 자료마다 다음을 설명할 수 있어야 한다: **누가 제공하는가 → 실제로 받은 형식/필드 → 사용한 범위 → 없는 자료와 확인된 이유 → 모의 보완 → 더 확보하면 가능한 개선.** 자료가 없는 이유를 확인하지 못했다면 원인도 미확인이라고 쓴다.

## 담당별 바로 시작할 작업

### 심민준 — 실제 응답·정규화·형식 기반 모의 자료 (#30, #35)

1. 이미 발급/시험한 도로·기상 작업을 다시 신청하지 않는다. HJNC·KMA의 실응답 매핑과 `정상/빈 응답/누락/오류/오래됨` 표본을 정리한다. 키·개인정보·재배포 미확인 원본 대신 허용된 집계와 **별도 생성한 합성 wire 예제**를 Git에 넣는다.
2. 실제 필드명·자료형·null·인코딩·시간대·단위와 내부 표시 의미를 문서화한다. 실응답에서 확인한 필드와 공식 명세만 확인한 필드를 구별한다. 받은 응답이 구조 변경을 보이면 추정 파싱보다 안전한 실패를 우선한다.
3. 각 표본의 `출처/실제·모의/수신시각/관측시각/허용 범위/미확인 이유/추가 필요자료`를 선효·길웅에게 인계한다. 모의값에는 실제 수신시각을 붙이지 않는다. 기존 `audit_kma_response.py`, HJNC/도로 감사 도구를 재사용한다.
4. 담당 키는 본인 허용 환경에서 설정한다. 대겸은 기상청 본인 키가 없으므로 팀원 키를 대신 전달하지 않는다. 시연 실행자/환경을 먼저 정하고 그 환경에서 연결을 검증한다.

완료 증거: 필드 대응표·공급자 형식의 합성 정상/오류 예제·실제 검증 집계·파서 검사·데이터 공백 설명. 선효가 같은 예제로 읽을 수 있어야 한다.

### 안선효 — 실제 서버 연결·공통 읽기 응답·AIS (#31, #36)

1. PR42/43의 **최신 head·리뷰·미완료 상태부터 확인**한다. 준비된 parser/읽기 상태/제한 수신을 재작성하지 않는다. PR42는 초안, PR43은 관련자 검토가 남아 있어 main 포함이라고 가정하지 않는다.
2. HJNC 소량 수동 조회 → KMA → ORS → AIS 참고 조회 순으로 실용성을 검증한다. 허용된 계정·공식 주소만 서버에서 호출하고 URL/키를 프론트·로그로 보내지 않는다. 제한시간·동시 요청 묶기·호출 속도/사용량·429 중단/재시도 시각을 다룬다. 새로고침·마커 재생이 외부 재수집을 만들지 않게 한다.
3. 읽기 결과의 성공/부분/빈 응답/실패/미설정, 마지막 시도와 성공, 출처와 시각을 화면에 전달한다. 캐시 보관은 제공사별 허용 범위 내에서만 한다. 실패 후 모의 성공으로 자동 대체하지 않는다.
4. AIS는 제한된 서버 연결 후 종료, 무수신/잘못된 위치/단절을 노출한다. 합성 재생은 실제 연결과 별도 선택이다. 선박 좌표를 화물차/컨테이너 위치로 자동 연결하지 않는다.
5. 읽기용 응답 개정안과 예제를 민준·길웅에게 먼저 인계한다. 읽기 참고 패널은 계산/승인과 분리한다. `DEMO_DATA_ONLY`를 제거하거나 실자료를 simulated로 위장하지 않는다. 혼합 저장·계산은 별도 공통 경계 검토 후 연결한다.

완료 증거: 로컬 실제 API→정규화→HTTP 응답, 키 없음/인증 실패/timeout/429/빈·부분/오래됨 검사, 같은 화면 재조회 중복 호출 방지, 원문/비밀값 노출 없음. 키가 없어 합성 검사만 했으면 실연결 미완료로 기록한다.

### 최길웅 — 실제·모의 전환과 근거가 보이는 화면 (#32, #37)

1. 기존 비교·승인·카카오 지도 화면을 활용한다. ORS는 개인 무료 Standard 발급/한도 확인을 먼저 남기고 본인 허용 환경에서 서버 시험한다. [개인 신청 링크](personal-api-signup.md) 참고.
2. 항차 반입시간·기상·선박 참고 정보를 핵심 작업 비교와 연결하되, **실제 현재 조회 / 저장 자료 재생 / 모의 시연**을 사용자가 구별하게 한다. 자료마다 출처·관측/수신시각·미확인 항목을 확인할 수 있어야 한다.
3. 일반/위성+지명 배경 전환에서 중심·줌·선택 대상을 유지한다. 선박·차량을 구별하고, 실제 수신 위치만 실제 마커로 표시한다. 시연 움직임은 모의/보간임을 표시하며, 수신 끊긴 실제 점을 계속 움직이지 않는다.
4. '데이터 없음' 대신 확인된 상황을 표시한다: 키 미설정, 응답0건, 부분 누락, 관측 오래됨, 실제 GPS 미확보 등. 원인 미확인은 그대로 둔다. 빈차/공컨·적컨/미확인을 같은 아이콘 상태로 합치지 않는다.
5. 대겸의 [9개 사례](../experiments/data-demo-2026-11-10/README.md)에서 정상/입력 차단/고정 위험의 화면을 확인한다. 실제 API 실패 후에도 **사용자가 선택한** 독립 모의 배차 비교는 동작해야 한다. 가정 입력을 사용했으면 표시한다.

완료 증거: 정상·누락·조회 실패·AIS0건·모의 선택·오래된 점·지도 전환의 브라우저 검수. 실제 외부 API→화면 표시 1건 이상을 출처/시각과 함께 기록하고 다른 API의 미검증 상태를 숨기지 않는다.

### 황대겸 — 계산·비교·자료 채택과 발표 근거 (#33)

1. 현재 바로 가능한 **데이터 공백9사례**를 고정해 B0~B3와 입력 차단을 검사한다. 고정 보존·미처리·변경·이동·해 상태를 기록하고, 입력 누락은 계산하기 전에 막는 API 경계와 엔진의 개별 진단을 구분한다.
2. 준비시각을 확인한 모의 사례를 별도로 비교한다. 무엇이 더 있어야 해결 가능한지 설명하되 그 차이를 현장 수집 효과로 주장하지 않는다. 기존 동결80회는 변경하지 않는다.
3. 실제 자료의 시간대·단위·신선도·권한·필수 필드가 확인되면 새로운 혼합 사례로 연결한다. 실항차의 가정 마감 변경과 관측된 변경을 구별한다. 미확인값을 추정해 실측값으로 쓰지 않는다.
4. 선효의 실제 연결과 길웅의 화면이 준비되면 같은 입력·실행/계획 버전으로 끝까지 검수한다. 보조 자료의 실패가 독립 모의 계산을 막지 않는지, 반대로 핵심 입력 부족이 승인으로 넘어가지 않는지 확인한다.
5. 네 담당의 근거를 모아 보고서20쪽·발표15쪽에 맞는 주장 범위를 정리한다. 각 담당은 자기 파트의 자료/한계/시연 설명도 작성한다.

완료 증거: [고정 입력·원시 결과·요약](../experiments/data-demo-2026-11-10/README.md), 같은 조건 B2/B3 비교, 미완료 자료와 채택 조건. 새 모의 검사가 실제 API 연결 완료를 대신하지 않는다.

## 연결 순서와 병합

1. 전원 최신 main과 관련 PR head/리뷰를 확인한다. 기존 작업은 보존한다.
2. 민준의 필드·합성 예제와 선효의 읽기 응답안을 맞춘다. 길웅은 합성 예제로 UI를 병행한다. 대겸은 아래 고정 사례 검증을 병행한다.
3. 소유자가 허용 환경에 키를 설정한 뒤 선효·길웅이 실응답 1건의 끝까지 연결을 확인한다. 이슈에는 키 없이 증거·미확인만 남긴다.
4. 중요한 연결은 관련자1회 검토 후 수정·검사·CI를 통과하면 병합한다. 전체를 합친 main에서 한 번 통합 검수한다. 이번 분담은 PR42/43의 검토를 대신하지 않는다.

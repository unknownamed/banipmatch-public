## 2026-11-10 최종 대응 범위와 현재 구현

[최신 설계 결정](dispatcher-response-scope.md): 조건 확인/새 입력 재계산→확정→차량별 변경 전달→수신자 응답까지 완성 범위로 확정했다. 전화·채팅·기업 외부 업무 대행은 제외. #54~#57 담당 배정 완료. 대겸의 `tools/dispatch_response.py` 로직/검토 도구와 회귀19개를 준비했으나, 화면·API·실제 푸시/응답·휴대폰 검수는 미완료다. 해당 도구가 전송 권한을 부여하거나 외부 연락을 수행하지 않는다. 기존 F01~F12와 공개 보호·실배포/보고서 목표도 유지한다.

## 2026-11-10 최신 사용자 확정 — 최종 통합·배포는 대겸

이전 같은 날 계획의 발표 작업·선효 릴리스 담당·정적 시연만의 목표를 변경했다. **직접 계산 가능한 웹앱 + 최종 보고서·코드/데이터**가 현재 목표다. 팀원은 자기 파트 구현/시험·근거 인계와 통합/배포본 테스트를 맡는다. **대겸이 최종 통합·수정/보완·최종본·보고서 편집과 실제 서버/주소/배포**를 맡는다. 서버 실행/게시를 AI나 팀원이 임의 수행하지 않는다. 공개 계산용 세션 분리·자원 제한·실주소 검수는 아직 미구현/미확인이다.

[전체 계획](completion-plan.md)과 #50을 갱신하고 #47을 대겸 최종 통합/배포로 재배정했다. #49는 완료가 아닌 현재 범위 밖 후속 보류다. [보고서 본문 초안](../report/report-draft.md)과 [주장/근거표](../report/evidence-index.md)를 기존 검증 자료로 작성했고, 신규 실제 연결/배포 절은 미완료로 남겼다. 팀원은 이슈 템플릿 ‘통합·배포본 테스트 결과’로 재현 근거를 보내고 대겸 수정 후 재확인한다. 아래 이전 기록은 완료 사실·당시 계획의 이력이며 최신 역할은 이 절이 우선한다.

## 2026-11-10 완성본 전체 작업 확정

[전체 완료 계획](completion-plan.md)에 개발·자료 채택·최종 통합·코드/데이터 패키지·보고서·발표·공개·제출까지 F01~F12의 담당/의존성/완료 증거를 정의했다. [#50](https://github.com/unknownamed/banipmatch/issues/50)이 전체 추적표이고, 기존 #30~#37의 열린7개 작업과 새 #47(선효·릴리스), #48(대겸·보고서), #49(길웅·발표)를 연결한다. 역할별 파트 본문/근거는 각자가 작성한다.

이는 **계획/검수 양식 완료**다. 실제 API→웹 연결·새 통합 검사·최종 보고서/발표/패키지·공개 배포가 이번 문서 작업으로 완료된 것은 아니다. 대겸은 기존 검증 도구 외에도 수치/주장 정리·본문·후속 통합/제출 검수가 남는다. 공식 보존 안내문에서 보고서/코드·데이터11/13 14시, 발표PDF11/20 14시, 문제해결 발표11/27(질의5분 포함총15분)을 재확인했다. 새 공지/회신은 제출 전 확인한다.

## 최신 우선 작업 — 실제 자료 검증·연결 (2026-11-09)

[공통 실행 계획](real-data-integration.md)과 [신청 상태](api-access-status.md)를 따릅니다. 모의 시연 완료를 이유로 유용한 API 검증을 미루지 않고 HJNC·도로공사를 우선 확인합니다. 기존 지도는 재사용합니다.

- 민준 본인 명의 도로공사 키 발급·인증과 소량 양방향 응답을 확인했습니다. [단위·집계/품질 검증](../data/road-api-verification.md)의 공백 때문에 계산 입력 변환은 보류합니다. 본인 키는 공유하지 않습니다.
- HJNC 공개 조회1회에서 실제10행을 받았고 단일/쌍 관측 비교용 로컬 도구를 준비했습니다. 원본은 로컬만 보관합니다. 시간대·전체 범위·변경 이력·반복 수집/공개 시연 조건은 미확인입니다.
- 선효는 읽기 전용 연결/캐시/실패 상태, 길웅은 실제·참고·모의와 출처 표시, 대겸은 검증된 혼합 입력의 비교 기준을 맡습니다. 도구 준비를 앱의 외부 API 연동 완료로 표현하지 않습니다.
- 실제 API가 실패하면 모의 자료로 자동 바꾸지 않습니다. 마지막 성공 자료·실패·명시적으로 선택한 모의 모드를 구분합니다. 자료 계약 변경은 관련자1회 검토를 유지합니다.
- 현재 API 저장은 `simulated`만 허용하며 혼합 입력은 `422 DEMO_DATA_ONLY`입니다. [선효 #31](https://github.com/unknownamed/banipmatch/issues/31)에서 저장·검사·승인·공개 범위를 검토한 뒤 연결합니다. 이번 준비에서는 그 제한을 바꾸지 않았습니다.

## 바로 할 일

로컬 API 실행과 담당별 연결 방법은 [백엔드 안내](../../backend/README.md)를 따릅니다. main에 반영된 독립 일정 검사·모의 승인과 미구현인 운영 인증을 구분합니다.

1. 대표 사례의 브라우저 검수와 평가→화면 대조는 PR18~26에서 완료했습니다. 최종 보고서/발표 통합과 위 실제 자료 담당 작업을 이어갑니다.
2. 설명용 결과로 연결한 화면에는 모의 표시를 유지하고 승인을 막습니다.
3. 반복 시연은 `python -m tools.demo_engine_api --review-only`로 준비합니다. 기본 예산은 방법별10초이며 원본 시간을 같은 폭으로 이동한 모의 입력을 생성합니다. 짧은3초 예산은 환경에 따라 실패할 수 있고, 실패를 숨기거나 자동 재계산하지 않습니다.
4. 엔진 담당은 [기존0.2.1·156회 실험](../experiments/engine-sensitivity-2026-11-08/README.md)을 보존하고 [0.2.2·72회 후속 실험](../experiments/engine-profile-2026-11-08/README.md)을 추가했습니다. 20건 B3는3초에서도 변경2건의 최적성을 증명했고10초 호출 중앙값은5.21→2.42초입니다. 50건10초 B2는 전체 최적성을 증명했으나 B3는26/23/1,440(미처리/변경/이동분)의 FEASIBLE로 전체 미증명이며3초는 두 방법 모두 첫 목적 FEASIBLE입니다. 다음은 리뷰 피드백·통합 대조·50건 B3의 남은 증명 병목 검증입니다. [기존156회 PDF4쪽](../experiments/engine-report-2026-11-08/engine-experiment-summary.pdf)과 [후속72회 PDF2쪽](../experiments/engine-report-2026-11-08/engine-performance-followup.pdf)을 분리 제공합니다. 모의 결과를 현장 효과로 확대하지 않습니다.
5. 데이터·API 담당은 [최신 데이터 준비 인계](handoffs/2026-11-08-s-minjun-data-preparation.md)를 읽고 연결된 실행 전 점검과 출처 시각 오류 전달을 유지합니다. 누락·미확인 입력도 등록·보관하는 API 정책은 유지하며, `InputReport.valid`를 일정 독립 검증·승인 성공으로 사용하지 않습니다.

첫 통합에서 J0 고정, J1/J2 조정, J3 미처리 이유가 일치해야 합니다. 과거 자료의 단순 시간슬롯 데모를 현재 엔진 완성본으로 취급하지 않습니다.

- 공개 전환·라이선스·최종 보고서·발표자료는 별도 작업입니다.

## 2026-11-07 서비스 비교 인계

TIGER FACE·PortQM·PortWise, Containus TMS·체인포털 VBS·PSA Singapore OptETruck·ECT/Portbase의 공개 자료를 비교했습니다. 배차·추적·예약 변경은 이미 존재하는 기능입니다. 우리 검증 초점은 확인된 반입시간 변경이 남은 작업에 미치는 영향과 처리 수준을 지킨 변경 부담의 비교입니다. 경쟁사의 미지원·시장 공백·성능 우위는 확인되지 않았습니다.

역할표·README·AI 시작 지침·PR 검토 항목에 연결했습니다. 출발 작업은 현재 계약대로 고정하며, 해외/구판 예약 규칙을 HJNC 규칙으로 옮기지 않습니다. 기존 PDF·계약·실행 코드는 이번 비교 반영으로 바꾸지 않았습니다. API 준비·서비스 비교 공통 문서는 처음 [PR #2](https://github.com/unknownamed/banipmatch/pull/2)로 공유했으며, 사용자가 최신 main에서 바로 읽도록 직접 반영을 명시했습니다. 엔진 PR #1은 별도입니다.

팀원의 TMS 보조 도구 제안도 공통 비교 문서에 검토 결과를 남겼습니다. 모의 CSV·JSON 입력 기반으로 먼저 구현하며 실제 TMS 내보내기·연동·정산 지원·현장 사용·설치 불필요 주장은 확인 전 가정으로 구분합니다. 입력 읽기와 변경안의 외부 자동 반영은 별개입니다.

## 2026-11-08 심사 항목별 증거 준비

사용자 제공 심사표를 [주장·근거·부족 증거·현재 담당·완료 기준](evaluation-evidence.md)에 연결했습니다. 공식 최신 공고 확인이나 기능 구현 완료가 아니라, 기존 범위의 보고서·발표 근거를 준비하는 기준입니다. 서면70점 미만 부적격 기준과 보고서20쪽/발표15쪽 구성안을 표시하고, 최종 공고·분량·일정은 제출 전 재확인합니다.

기존156회와 후속72회는 228회 모의 실행이며 현장228건이나 운송비 절감 실증이 아닙니다. 동일 처리 수준에서 변경·이동 부담·위반·고정 잔여 위험·시간·해 상태를 함께 제시합니다. 실제 배차·합법적 실응답·사용 수요·현장 효과의 미확보를 유지하며, 현장 자료가 없으면 공개 근거와 모의 가정을 구분한 사례를 준비합니다. 이후 PR12·14가 병합돼 실계산·독립 검사·내부 승인 연결을 검수했습니다. 이후 PR18·22에서 대표 사례 브라우저 검수도 완료했습니다. 현장 검증은 남아 있으며, v0.1 계약·담당·당시 API 신청/외부 연락/실자료 권한 보류 기록이며 현재 개인 신청 범위는 문서 맨 위 최신 배정이 우선합니다.

확인일: 2026-11-08. 대상은 HJNC 일반 수출 Dry 컨테이너이며, 본문은 공개 공지 확인 결과다. 실제 운송사 자료·항차 변경 이력·협조처를 확보했다는 뜻이 아니다.

## 보고서에 설명할 문제

HJNC 공지는 수출 Dry 컨테이너의 반입마감 준수 필요성을 설명한다. 별도의 과거 공지에서는 반입 제한 일수가 운영 상황에 따라 조정된 사례를 확인할 수 있다. 따라서 반입 시작과 마감은 적용 시점·대상·출처를 함께 확인해야 할 입력이다. 반입맞춤은 **담당자가 확인한 변경값**을 받아 기존 운송사 작업표에서 영향을 받는 작업과 조정 대안을 비교한다.

위 공지들은 변경 대응이라는 문제의 업무적 근거다. 실제 배차 담당자가 얼마나 자주 재조정하며 기존 TMS로 처리하기 어려운 부분이 무엇인지까지 입증하지는 않는다. 이 필요성·사용 의향·업무 부담은 현장 검증 과제로 남긴다.

## 설계에 적용하는 구분

- **공식 안내와 입력값:** 공지의 일반 규칙을 그대로 모든 항차에 자동 계산하지 않는다. 최신 스케줄·예외·담당 확인을 거친 `windows`와 `change`를 사용한다.
- **ETA와 반입마감:** 접안과 마감의 관련성이 있더라도 선박 ETA 변동을 확인된 마감 변경으로 자동 승격하지 않는다.
- **운영 기준과 모의 조건:** 실험의 150분 마감, 180분 시작, 이동 8~30분, 여유 10분 등은 설명용 합성 조건이다. HJNC 공지에서 추출한 실제 항차·도로·대기시간 값이 아니다.
- **고정 작업:** 출발 작업과 변경 불가 예약 보호는 현재 시제품의 조정 범위다. 현장에서 모든 출발 작업이 영구 변경 불가능하다는 주장으로 확대하지 않는다.
- **요금과 효과:** 공지에 청구 제도가 있다는 사실만으로 미처리 감소를 매출·운송비 절감으로 환산하지 않는다. 실제 요율·예외·부과 대상·대응 비용 확인이 필요하다.

## 심사 질문에 답하는 기준

**왜 필요한 문제인가?** 공식 공지의 마감 준수 이유와 제한 변경 사례를 제시한다. 담당자의 재작업 빈도와 실제 손실은 아직 확인하지 못했다고 구분한다.

**기존 서비스보다 무엇이 좋은가?** [기존 서비스 비교](service-comparison.md)를 바탕으로 현재는 ‘기존 작업을 지키면서 남은 작업의 변경 부담과 이동 부담을 비교하는 보조 흐름’을 검증한다고 설명한다. 상용 TMS보다 우수하거나 해당 기능이 없다는 주장은 하지 않는다.

**모의 데이터가 현실적인가?** [평가 입력과 생성 규칙](../experiments/engine-evaluation-2026-11-08/README.md)을 공개하고, 가능한 일정·위반·고정 위험을 재현하는 검증용 사례라고 설명한다. 현실의 발생 분포·운송 시간·업무비용을 추정한 데이터는 아니다.

**우리 팀이 설계한 것은 무엇인가?** 목적의 우선순위, 고정 보호, 시간·차량·준비 제약, 변경 지표, 결과의 독립 검사, 비교 실험과 화면 흐름이다. 탐색은 OR-Tools를 사용하며 AI의 코드 작성 보조와 담당자의 설계·검증을 구분한다.

**실제 도입에는 무엇이 남았나?** 허가된 배차 표본과 확인된 반입시간, 필드 대응, 도입 절차·운영 인증·사용자 격리·현장 검증이 필요하다. 로컬 내부 승인과 터미널 예약 변경·기사 연락은 별개다.

## 아직 확보하지 않은 근거

특정 항차의 실제 이전/새 반입시간 쌍, 변경 발생 빈도, 운송사 배차표와 GPS, 실제 작업 변경 소요, 현장 사용 의향과 비용 절감 계수는 확보하지 않았다. 이번 작업은 기존 연락의 재발송·신규 API 신청·자동 수집을 수행하지 않았다.

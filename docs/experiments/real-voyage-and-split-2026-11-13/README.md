# 실제 HJNC 항차 사례와 50건 분할 계산 (2026-11-13)

보고서 1.1·5.2·6장에 쓴 두 실험의 원자료다. 실행: `python docs/experiments/real-voyage-and-split-2026-11-13/run.py` (약 3분). HJNC 수집본 두 개는 같은 폴더의 `hjnc-snapshots.json`에 있다.

## 1. 실제 HJNC 항차
- HJNC 공개 선석 배정 수집본 두 개(2026-11-11 09:53:51Z, 2026-11-12 15:26:41Z)를 비교했다. 공통 항차 25개 중 19개의 반입 마감이 달랐다(앞당김 8, 늦춰짐 11). 바뀐 마감은 모두 새 접안 예정(ETB)의 10시간 전이다. 비교한 행은 `result.json`의 `common_rows`에 있다. 두 시점 비교이므로 실제 공지 횟수·시점은 알 수 없다.
- 앞당겨진 항차 중 시연 사례(2시간 30분)와 크기가 가장 가까운 항차를 미리 정한 규칙으로 골랐다: OOET-2026-0003, 11/16 23:00 → 21:00(KST).
- 그 항차의 실제 반입 시작·이전 마감·새 마감을 넣고, 배차표(작업 20건·차량 8대)는 `frontend/src/fixtures/demo-02-evening.synthetic.json`을 시각만 옮겨 썼다(모의). 변경을 안 시점은 알 수 없어 시연처럼 이전 마감 4시간 전으로 가정했다.
- 결과(10초): 원래 배차 2건 마감 초과 → 최소 변경안 4건 변경(기사 4명)으로 0건, 최적 증명. 전체 재배치 0건·14건 변경. 별도 검사기(`tools/check_engine_robustness.py`의 `check`) 위반 0건.

## 2. 50건 분할 계산
- 입력: `docs/experiments/engine-evaluation-2026-11-08/inputs/eval_cutoff_50_404.json`(항차 V1·V2 각 25건, 차량 8대, V1 마감 7시간 30분 앞당김).
- 전체 10초·60초: 미처리 9건, 변경 41건, 첫 목적(미처리) 단계 FEASIBLE(하한 0), 최적 미증명.
- 분할(V2 25건을 원래 배차로 고정, V1만 계산, 10초): 미처리 15건(하한 13), 변경 10건(기사 4명), 최적 미증명.
- 해석: 다른 항차를 통째로 고정하면 그 차량을 빌려 쓸 수 없어 미처리가 늘어난다. 이동 시간은 고정 작업을 빼고 세므로 두 방식을 비교하지 않는다.

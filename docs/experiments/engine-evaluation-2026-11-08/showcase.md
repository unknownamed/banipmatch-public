# 공개 시연용 고정 모의 평가 근거

기존 80회 결과를 다시 계산하지 않고 읽기 전용으로 묶었다. 모든 10개 입력의 솔버 시드0 B0~B3 40개 원시 결과와 전체80회·20쌍 맥락을 제공한다. 유리한 사례를 선택하지 않았다.

원시 `validation_status=not_run`, `approval_eligible=false`를 보존했다. `audit`은 별도 일정 검사 기록이며 API 실행·내부 승인·외부 예약 변경이 아니다. B0는 원안 위험 진단이며 일정 승인 대상이 아니다.

변경 감소의 현장 시간·비용·탄소 효과는 미확인이다. 같은 미처리 수라도 처리 작업 ID가 다르면 동일 업무 효율 개선으로 합치지 않는다. 고정 위험과 솔버의 단계별 증명 상태는 원시 결과에 함께 있다.

## 재현·추적

`python tools/build_showcase_evidence.py --check`는 원시 파일·입력·출처 커밋 소스 해시, 80개 방법/시드 조합, 독립 일정 검사를 확인하고 산출물을 대조한다. 솔버를 호출하지 않는다. 새 시각 정보를 생성하지 않는다.

파일 해시와 산출물 대조는 Git의 운영체제별 줄바꿈 변환을 허용하기 위해 UTF-8 바이트의 CRLF만 LF로 정규화한다. 공백·내용·BOM·단독 CR은 변경하지 않으며, 공백 한 글자 변경도 실패한다. `provenance.hash_convention`이 이 규칙을 명시한다. `results_sha256`은 저장소 LF 기준이고, 원래 Windows 실행의 CRLF 원본 바이트 해시는 `original_results_byte_sha256`에 별도로 보존했다. 입력·프로토콜·메타데이터에 남은 기존 실행 해시는 바꾸지 않았다.

[JSON](showcase.json)의 `provenance`에 SHA-256과 출처 커밋을, 각 방법의 `source_jsonl_line`에 [results.jsonl](results/results.jsonl)의 1부터 시작하는 행 번호를 기록했다. 각 `methods` 항목은 행 번호 외 원시 기록을 그대로 보존한다. 실행 가능한 해와 최적성 증명은 서로 다르며 `solution_status`, `objective_proven`, `objective_stages`를 확인한다.

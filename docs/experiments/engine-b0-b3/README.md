# B0~B3 모의 비교 · 2026-11-07

엔진 `0.2.0-b0-b3`, OR-Tools `9.15.6755`, Python 3.12, 로컬 단일 worker. 모든 입력은 의도적으로 구성한 모의 자료이며 실제 운송 효율이나 상용 서비스 대비 성능의 증거가 아닙니다.

- [입력 7종](inputs): 공통 예제의 복사본과 변경/이동·시각 보존·차량 경쟁·고정 예약·20건·50건 사례
- [최종 실계산 JSON](2026-11-07_final_results.json): 입력 해시, 모든 배정, 단계별 목적값·하한·상태, 실제 실행 설정 포함
- [비교 CSV](2026-11-07_final_results.csv)
- [모형과 해석](../../../backend/engine/OPTIMIZATION.md)

## 재현

저장소 루트에서:

```sh
python -m pip install -r backend/engine/requirements.txt
python tools/compare_engine.py --inputs docs/experiments/engine-b0-b3/inputs --output local/comparison-new.json --time-limit-seconds 3 --seed 0
```

기존 출력이 있으면 새 파일명을 사용합니다. B0~B3는 같은 입력·seed·방법별 3초 예산으로 실행합니다. B2/B3의 B1 초기안 구성은 최대 1초이며 이 3초에 포함됩니다. 라이브러리 로딩은 비교 전에 완료하며 외부 해를 추가로 주지 않습니다. 시간 제한 실행은 환경에 따라 결과가 달라질 수 있습니다.

## 작은 사례에서 확인한 차이

각 칸은 **미처리 / 변경 작업 / 이동분**입니다. 모두 조정 작업 위반 0인 결과끼리 비교합니다.

| 사례 | B1 | B2 | B3 | 해석 |
|---|---:|---:|---:|---|
| 공통 4작업 | 1 / 2 / 100 | 1 / 2 / 100 | 1 / 2 / 100 | 이 사례에서 B3가 더 낫지는 않음 |
| 변경과 이동 절충 | 0 / 1 / 40 | 0 / 1 / 40 | 0 / 0 / 60 | B3는 처리 수준을 유지하면서 변경을 줄이는 대신 이동이 20분 늘어남 |
| 원안 출발시각 보존 | 0 / 1 / 60 | 0 / 1 / 60 | 0 / 0 / 60 | 더 일찍 출발할 수 있어도 가능한 원안 시각을 유지 |
| 호환 차량 경쟁 | 1 / 0 / 40 | 0 / 2 / 80 | 0 / 2 / 80 | 변경을 줄이려고 처리 가능한 작업을 버리지 않음 |
| 미래 고정 예약 | 0 / 0 / 60 | 0 / 1 / 60 | 0 / 0 / 60 | 고정 배정·정수 순서를 유지하고 남은 작업만 조정 |

작은 5개 입력에서 B2/B3의 모든 목적 단계가 `OPTIMAL`이었습니다. B2는 변경 수를 최적화하지 않으므로 같은 이동합계에서 다른 시각을 반환할 수 있습니다. 공통 예제의 B0는 미처리 0이지만 조정 작업 위반 2건이므로, B0의 이동 150→100을 운송 효율 개선율로 해석하지 않습니다.

## 큰 사례와 시간 제한

| 입력 | B0 조정 작업 위반 | B1 미처리/변경/이동 | B2·B3 미처리/변경/이동 | B2·B3 판정 |
|---|---:|---:|---:|---|
| 20작업·4차량 | 10 | 8 / 12 / 720 | 8 / 12 / 720 | FEASIBLE, 첫 목적 미증명·후속 목적 미실행 |
| 50작업·8차량 | 30 | 26 / 24 / 1440 | 26 / 24 / 1440 | 유효한 초기안 보존. 솔버 첫 단계 UNKNOWN, 후속 목적 미실행 |

이 두 사례에서는 3초 내 개선·최적성을 확인하지 못했습니다. 최종 결과를 유지하되 `objective_proven=false`로 표시합니다. 20작업 실행은 최종 처리까지 약 3.0초, 50작업은 약 2.3초였으며, 전체 프로세스의 엄격한 시간 보장이 아닙니다. 실제 수치는 JSON/CSV의 `elapsed_ms`를 확인합니다.

## 재현과 사용 범위

저장소 루트에서:

```sh
python -m pip install -r backend/engine/requirements.txt
python -m backend.engine --snapshot "docs/development/v0.1/예제 데이터/01_snapshot.json" --output local/engine-results.json
python -m unittest discover -s tests/engine -v
```

다시 실행할 때 `elapsed_ms`는 환경에 따라 달라집니다. 작은 예제의 0ms 표시는 밀리초 미만을 정수로 내린 값이며 무비용 계산을 뜻하지 않습니다. 입력 배열 순서와 무관하게 같은 배치를 재현하는 테스트가 있습니다.

결과의 `result_origin=computed`는 코드가 계산했다는 뜻입니다. 독립 일정 검증·API 저장·버전 충돌·사용자 승인은 아직 없으므로 `validation_status=not_run`, `approval_eligible=false`를 유지합니다. `run_id`는 로컬 비교용 식별자이며 API의 실행 ID로 재사용하지 않습니다.

다음 실험은 B2/B3 구현 후 같은 입력·조건에서 미처리 최소화, 변경 최소화, 이동 부담을 순서대로 비교하는 것입니다. 미래 고정 작업 사이의 정수 순서 삽입 한계와 입력 누락 처리도 함께 기록해야 합니다.

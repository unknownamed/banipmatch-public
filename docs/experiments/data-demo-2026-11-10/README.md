# 데이터 공백을 설명하는 시연·계산 검수

황대겸 담당, 2026-11-10. 최신 설계의 **정상 처리뿐 아니라 자료가 부족할 때의 행동과 추가 필요자료**를 확인하는 작은 모의 검수 묶음이다. 실제 HJNC/기상/AIS 응답을 엔진에 넣은 결과가 아니며 기존 동결80회와 별개다. 네 작업·두 차량으로 상태를 명확히 설명하는 목적이다. 수량 확대나 현장 성능평가로 사용하지 않는다.

## 결과

9사례의 예상 판정이 모두 일치했다. 4개 완전 입력에서 B0~B3 **16회**를 계산했다. 조정안12개는 독립 일정검사를 통과했고, 모든 실행에서 고정 작업을 원안 그대로 보존했다. 나머지5개는 입력검사에서 차단해 솔버를 호출하지 않았다. B2/B3는 같은 작업 집합·미처리 수로 비교했으며 계산 예산3초, 시드42다.

| 사례 | 입력검사 / 화면에서 설명할 결과 | 다음에 필요한 것 |
|---|---|---|
| cutoff | B0 가변 작업 위반2건, B3 위반0·미처리1. J3 준비가 늦음 | 준비·반입 가능시각 등 실제 업무 조건. 순서만 바꿔 해결된다고 하지 않음 |
| opening | 시작 지연. 출발 고정 위험1건 유지. B2/B3 미처리0, 변경2→0 | 출발 작업 현장 확인. 자동으로 대기/예약 변경했다는 설명 금지 |
| fixed_risk | 출발 위험1건을 보존. B2/B3 미처리2, 변경1→0 | 담당자 판단/외부 조치. 고정 위험을 삭제해 성공으로 만들지 않음 |
| ready_missing | `INPUT_INCOMPLETE`, 계산0회 | 운송사 화물 준비시각 |
| ready_recovered | 별도 가정으로 준비시각을 확인하면 계산 가능. B3 미처리1은 남음 | 확인된 데이터가 생겨도 모든 화물이 해결되지는 않음. 최적 전체 처리수와 개별 미처리 작업의 불가능 증명은 구분 |
| route_missing | `INPUT_INCOMPLETE`, 계산0회. 반대 방향 행은 남아 있음 | 해당 방향 이동시간·단위·차량 적합성. 역방향 복사/0분 채우기 금지 |
| return_unknown | `INPUT_INCOMPLETE`, 계산0회 | 고정 차량의 복귀/가용 확인 |
| window_unconfirmed | `WINDOW_UNCONFIRMED`, 계산0회 | 공식 반입시간 변경 확인. ETA/기상은 이를 대신하지 않음 |
| future_evidence | `INPUT_INVALID`, 계산0회 | 기준시각과 당시 사용 가능했던 근거를 맞춘 새 입력 |

B2/B3 이동 합계 차이는 이 작은 네 사례에서0분이다. 변경 감소 자체를 상용 서비스 대비 우위나 현장 시간·비용 절감으로 해석하지 않는다. B0 미처리0은 위반 없이 모든 작업이 처리됐다는 뜻이 아니다. 입력 회복도 모의 가정이며 실제 운송사 자료를 얻었다는 뜻이 아니다.

## 파일과 재현

- [protocol.json](protocol.json): 계산 전에 고정한9사례·예상 입력검사·시드·시간 예산·입력/소스 해시.
- [inputs](inputs): 개발 규격 v0.1의 독립 시연 입력9개. `data_mode=simulated`, 외부 동작 비활성.
- [results/results.jsonl](results/results.jsonl): 16회 엔진 원시 반환·독립 검사·고정 보존·소요시간. 원시 결과의 `approval_eligible=false`를 그대로 보존한다.
- [results/summary.json](results/summary.json): 9사례 판정과 B2/B3 짝 비교. 내부 승인·DB 저장·브라우저 검수 완료를 뜻하지 않는다.

저장소 루트에서 의존성을 설치한 Python으로 실행한다. 새 출력 디렉터리를 사용하며 기존 산출물은 덮어쓰지 않는다.

```powershell
python -m tools.data_demo_acceptance build --output local/data-demo-new --as-of 2026-11-10T00:00:00Z
python -m tools.data_demo_acceptance run --protocol local/data-demo-new/protocol.json --output local/data-demo-new/results
python -m pytest tests/engine/test_data_demo_acceptance.py -q
```

실제 시연 시각에 맞춘 새 입력이 필요하면 `--as-of`에 **UTC 분 경계 시각**을 넣어 전체 시각을 같은 폭으로 이동한다. 이 경우에도 모의 자료다. 현재 앱의 유효기간/승인 검사를 통과하려고 과거 원본의 시각을 몰래 바꾸지 않는다. 이 도구는 별도 고정 입력을 만들며 API를 자동 실행하지 않는다.

원본 프로토콜을 `run`하면 입력·소스 해시를 검사한다. 코드가 변경되면 이전 결과를 덮어쓰지 말고 새 묶음을 만든다. 시간 측정값과 동률 해는 환경에 따라 달라질 수 있다. 검사 도구 오류로 끝난 실행도 보존하며 실패를 삭제하거나 유리한 사례만 선택하지 않는다.

## 다른 파트에서 사용하는 법

민준은 실제 자료 누락 사유를 위 입력 판정과 연결하되 공급자 wire 예제는 별도로 만든다. 선효는 같은 공통 입력을 등록·실행할 때 예상 오류를 대조하고, 길웅은 오류를 읽을 수 있는 문구와 추가 필요자료로 표시한다. 기상/AIS 같은 참고 패널의 실패는 별도이며 이 엔진 스냅샷에 억지로 필드를 추가하지 않는다.

실제 API→참고 화면→모의 계산을 나란히 시연할 수 있으나, 엔진에 사용하지 않은 외부 자료를 계산에 활용했다고 발표하지 않는다. 혼합 계산은 [담당 실행 계획](../../team/data-demo-sprint-2026-11-10.md)의 시간대·단위·권한·계약 검토 후 별도 새 사례로 진행한다.

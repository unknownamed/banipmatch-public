# B2/B3 모형과 판정 범위

기준: 엔진 `0.2.0-b0-b3`, 공통 계약 `v0.1.0`, OR-Tools `9.15.6755`. 함수는 기존 `solve(snapshot, method, config)`를 유지합니다. DB·웹·외부 수집·내부 승인 상태를 변경하지 않습니다.

## 무엇을 결정하는가

작업별 배정 여부·차량·정수 순서·분 단위 출발시각을 결정합니다. 차량별 선택 경로는 CP-SAT Circuit으로 표현합니다. 배정하지 않은 후보는 자기 자신으로 연결하고, 선택한 작업은 시작 노드와 하나의 경로를 이룹니다. 경로를 따라 순서가 증가하도록 해 이동시간이 0인 구간에서도 순서를 보존합니다.

시간 제약은 시작 가용시각 또는 앞 작업 복귀에 접근시간을 더한 이후 출발, 준비 이후 출발, 반입 시작 이후 도착, 도착+여유가 마감 이내, 처리·복귀까지 근무 종료 이내입니다. 방향별 이동시간을 사용하고 장비·중량에 맞는 차량만 후보로 둡니다.

이미 출발한 고정 작업은 최적화 경로 밖의 과거 기록으로 보존합니다. 차량의 확정 가용시각·위치에서 남은 경로를 시작합니다. 미래 고정 예약은 차량·순서 정수·출발·도착·복귀를 그대로 둔 필수 노드입니다. 고정 작업의 새 마감 위반은 잔여 위험으로 보고하며, 해당 작업을 제거하거나 선택 작업의 하드 제약처럼 전체 불능을 만들지 않습니다. 고정 기록 자체의 모순이나 고정 예약 사이 접근 불확실성은 해당 차량의 신규 배정을 막고 입력 부족으로 알립니다.

## 두 목적의 차이

| 방법 | 우선순위 |
|---|---|
| B2 | 전체 미처리 수 → 조정 가능 작업 이동합계 |
| B3 | 전체 미처리 수 → 변경 작업 합집합 크기 → 조정 가능 작업 이동합계 |

변경 작업은 원안 대비 차량 변경, 허용폭을 초과한 출발시각 변경, 같은 차량에 남은 쌍의 상대순서 역전 참여, 원안 미처리에서 신규 배정된 작업의 합집합입니다. 차량과 시각이 함께 바뀌어도 한 작업으로 셉니다. 역전의 상대가 고정 작업이면 그 고정 작업도 현행 지표 정의에 따라 역전 참여 집합에 들어갑니다. 작업 삭제로 순번만 당겨지는 경우는 변경이 아닙니다.

이동합계는 조정 작업으로 들어가는 접근+적재+지정 복귀입니다. 미래 고정 작업으로 들어가는 접근은 시간 제약에는 쓰지만 이동 목적에는 포함하지 않습니다. 결과의 실제 지표와 모형 목적값을 비교해 다르면 결과를 반환하지 않습니다.

## 시간 예산과 결과 상태

두 방법 모두 동일 입력으로 B1 초기안을 최대 1초 동안 구성합니다. 이 시간은 요청의 전체 예산에 포함되며, 남은 예산이 더 짧으면 그 시점에 중단합니다. 이후 모형 구성과 모든 최적화 단계도 남은 시간을 공유합니다. 이전 단계의 최적값이 증명된 때만 그 값을 고정하고 다음 목적을 실행합니다. 매 단계 총 예산을 새로 부여하지 않습니다.

초기안과 최적화 중 얻은 안은 해당 방법의 목적 순서로 비교해 더 좋은 유효 후보를 보존합니다. 솔버가 첫 해를 못 찾아도 유효한 초기안이 있으면 `FEASIBLE`입니다. 단, `objective_stages`는 실제 솔버의 `UNKNOWN/NOT_RUN`을 그대로 남겨 초기안을 최적해로 오인하지 않게 합니다. 유효 후보가 없으면 `UNKNOWN`, 입력이 부족하면 `INPUT_INCOMPLETE`입니다. 실제 입력 관계 오류는 `EngineInputError`로 반환합니다.

모든 단계가 최적이라고 증명되고 입력 부족이 없어야 `objective_proven=true`입니다. 미처리 목적의 최적값이 증명돼도 특정 미처리 작업 하나가 물리적으로 불가능하다는 뜻은 아닙니다. 작업별 원인은 직접 확인한 준비·장비·중량 하한 외에는 확정하지 않습니다.

`solver_version`, 요청/적용 시드, worker=1, 초기안 출처, 각 단계 목적값·하한·상태를 기록합니다. 최초 라이브러리 로딩은 예산에서 제외합니다. 입력 검증·최종 진단·운영체제 지연을 포함한 강제 프로세스 종료 보장은 없으므로 API 담당은 입력 크기·동시 계산·프로세스 시간 제한을 별도로 둬야 합니다.

## 남아 있는 제한

- 현행 계약은 고정 작업의 순서 정수도 보존합니다. 고정 순서 1 앞이나 빈 정수가 없는 고정 예약 사이에는 삽입할 수 없습니다. 따라서 최적성은 이 계약 모형 안의 결과이며 현장 전체 배차 공간의 최적성을 뜻하지 않습니다.
- 후보 접근 경로 누락은 보수적으로 입력 부족으로 표시합니다. 누락 구간을 0으로 가정하지 않으며 희소 행렬의 허용 범위는 후속 검토입니다.
- 20·50건, 3초 모의 실험은 유효한 초기안을 유지했지만 전체 최적성을 증명하지 못했습니다. 더 큰 입력에서 개선이나 응답 시간을 보장하지 않습니다.
- 반환 결과는 계속 `validation_status=not_run`, `approval_eligible=false`입니다. 엔진 내부의 모형 검사·지표 대조·테스트가 선효 담당의 독립 일정 검사기를 대신하지 않습니다.

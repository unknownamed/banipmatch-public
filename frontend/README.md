# 프론트 (최길웅)

배차 담당자용 단일 작업 화면. 현재는 **공통 예제(v0.1) 설명용 결과를 표시하는 단계**이며 백엔드·실제 계산과는 아직 연결하지 않았다.

## 도구 (PR #4로 병합된 첫 구현)

React 18 + TypeScript + Vite 5, 테스트는 Vitest. 상태 관리·UI 라이브러리는 쓰지 않았다.

## 실행

Node 20 이상.

```sh
cd frontend
npm install
npm run dev        # http://localhost:5173
npm test           # 공통 예제 판정 테스트
npm run build      # 타입 검사 + 빌드
```

- 기본은 fixture 모드: `docs/development/v0.1/예제 데이터`의 01·03·04 JSON을 **복사하지 않고 직접** 읽는다.
- [백엔드 안내](../backend/README.md)에 따라 로컬 API를 실행한 뒤 `frontend/.env.local`에 `VITE_API_MODE=http`와 서버 모의 토큰과 같은 `VITE_API_TOKEN`을 설정하고 개발 서버를 시작한다. `.env.example`을 참고하며 실제 설정값은 Git에 올리지 않는다. `/v1` 요청은 `127.0.0.1:8000`으로 전달한다(포트는 백엔드에 맞춰 `vite.config.ts` 수정).
- HTTP 모드에서 `?run=`이 없으면 **예제로 계산 요청** 화면이 뜬다. 버튼을 누르면 예제 01을 새 ID로 `POST /v1/scenarios`, 02로 `POST /v1/runs`를 보내고 받은 `run_id` 결과 화면으로 이동한다. 실패 후 다시 시도는 같은 본문·같은 Idempotency-Key를 쓴다. 2026-11-08 main의 로컬 API로 등록 201 → 실행 202 → 결과 200과 J0 고정·J3 미처리·승인 차단 표시, 백엔드 중단 시 오류 안내를 확인했다. 입력 예제는 01·07(입력 누락)·08(미확인 변경) 중 고른다. 07/08처럼 입력은 등록됐지만 계산이 422·503으로 거절되면 저장된 입력·변경 근거·원안 표와 거절 사유를 보여주고 재시도 버튼은 숨긴다. 승인은 approvalGate를 통과하고 미처리·고정 위험 작업 확인 체크 후에만 `POST /v1/plans/{plan_id}/approvals`를 보낸다(같은 run·방법은 같은 멱등키). 성공 시 승인 버전과 `GET /v1/plans` 현재 버전을 표시하고, 409·422·503은 Error.code별 할 일을 안내한다. 현재 서버는 설명용 결과만 주므로 실제 승인 성공은 아직 확인하지 못했다.
- 다른 ID 조회: `?scenario=S001&run=R001`.

## 구조

| 파일 | 역할 |
|---|---|
| `src/api/types.ts` | `contracts.schema.json` 중 화면에서 쓰는 타입(필드명·enum 그대로) |
| `src/api/client.ts` | `/v1` HTTP 조회 클라이언트(202 계산 중 처리) |
| `src/api/fixtureClient.ts` | 공통 예제를 돌려주는 조회 클라이언트 |
| `src/api/useDispatchView.ts` | 입력·실행·결과를 따로 조회, 202면 간격을 늘려 재조회, ID가 다른/늦은 응답 무시 |
| `src/lib/compare.ts` | 같은 작업 ID로 원안/조정안 맞추기, 고정 작업 이탈 감지 |
| `src/lib/approval.ts` | 승인 버튼 차단 조건(설명용·미검증·입력 불일치 등) |
| `src/lib/time.ts` | UTC Z → 한국 시각 표시, null은 `미확인` |

## 지키는 규칙

- 변경 여부·원인은 응답의 `metrics`, `issues`만 쓴다. 화면에서 원인을 만들어내지 않는다.
- `illustrative_fixture` 결과는 배너로 표시하고 승인 버튼을 막는다.
- 계산 중에도 입력·변경 근거는 먼저 보인다. 등록·계산·승인 POST는 사용자 동작 없이 자동 반복하지 않는다.

## 승인 요청 검수 범위 (PR #9)

- 입력·실행·결과의 ID와 기준 계획 버전, 전체 해 상태를 검사하고 미처리·고정 위험 작업을 확인한 뒤 보낸다. 서버는 현재 입력·계획 버전과 권한을 승인 트랜잭션에서 다시 검사해야 한다.
- 통신 실패로 결과를 모르거나 저장소 장애가 나면 같은 본문과 멱등키로 재시도한다. 화면 안에서 방법을 바꿨다가 돌아와도 요청 키를 유지한다. 전체 페이지를 새로고침하면 이 메모리 캐시는 초기화되므로 현재 계획부터 확인한다.
- 버전 충돌·입력 거절·미확인 근거·승인 기능 미구현 응답 뒤에는 오래된 요청을 반복하지 않는다. 다른 계획·실행·방법·버전 또는 외부 반영을 보고한 성공 응답도 승인 완료로 표시하지 않는다.
- 유효한 승인 응답 뒤 현재 계획 조회 실패 또는 버전·입력·승인 ID 차이를 별도 경고한다. 조회 실패를 승인 POST 실패로 취급해 다시 보내지 않는다.
- `npm test`에는 jsdom의 실제 React DOM 클릭·상태 전이 회귀가 포함된다. 승인 성공·응답 유실·버전 충돌은 모의 HTTP 클라이언트로 검증한 것으로, 서버의 승인 저장·인증·동시성 구현이 완료됐다는 의미는 아니다.
